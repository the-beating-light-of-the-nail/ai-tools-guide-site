# 案例：用 TraeWork 做一套能上台的 PPT

> 改编自 TRAE 核心用户 K 叔的实测长文[《用 TRAE Work 做 PPT，最重要的不是「生成」》](https://zhuanlan.zhihu.com/p/2056077700767428956)（2026-07）。他的任务：把 OpenAI 两篇工程文章的读后感，整理成 11 页社区分享 PPT。

## 为什么"帮我做个 PPT"必翻车

一句话"帮我根据这篇文章做一份分享 PPT"，产出往往是**像网页截图、像后台页面、像设计 demo，就是不像一套能站在台上讲的 PPT**。原因不是模型不行，而是你没说清"怎么才算做好"。

两个最常见的坑：

- **视觉指令反向带偏**："高级一点 / 科技感"会把 AI 带向蓝紫渐变、玻璃卡片、等距组件、仪表盘布局。有效做法是**反向定义**——"不要等距卡片、不要按钮感标签、不要 dashboard 式页面"，目标定为"纸张笔记、批注、现场讲解"风。
- **标题不像人话**：❌"认知递进 / 模式变化" → ✅"AI 新词不是凭空冒出来的 / 痛点在往后移"。检验法：标题单独读一遍，现场不会说的话就别放页首。

## 五步链路：先定义"好"，再让 AI 推进

K 叔的完整流程分五步，每步产出一份"锚点文档"，**每一步都可以停下来改**——停在越早的环节，改动成本越低。

### 第一步：深度拆解材料，产出 memo

```
请先不要生成 PPT。
先分别分析这两篇文章，每篇提取核心议题、核心主张、论证骨架、
认知增量和边界条件。再基于分析整理一份读后感 memo。
不要逐段摘要，重点提取两篇之间的递进关系。
输出后停住，等我确认。
```

关键：**停在 memo 阶段改方向**。PPT 生成后问题会混在一起（主线/标题/视觉/文本框），那时再改最贵。

### 第二步：slide plan——每页一个主张

基于确认的 memo 整理 10 页左右的 slide plan，格式：

```text
Slide 03 / Claim：AI 编程的痛点在往后移
Proof object：Harness → sessions → supervision overload → Symphony
Layout：process sequence
```

11 页按"读后认知顺序"排而非文章目录：封面 → Hook → 递进 → 方法一 → 现场 → 新瓶颈 → 方法二 → 模式变化 → 边界 → 给小团队 → 收束。

### 第三步：design brief——反向定义风格

```
基于已确认的 slide plan 写 design brief，重点写清楚：
- 这套 PPT 不要像什么
- 视觉方向和参考对象
- 背景安全区（常规内容放中间，底部不贴太低，页码不压纹理边缘）
- 哪些文字必须可编辑
- 哪些元素可以用 image-gen 生成
- 哪些说法只是读后理解，不能写成官方定义
```

### 第四步：生成可编辑 PPTX

```
基于已确认的 memo、slide plan 和 design brief 生成可编辑 PPTX。
不要重新猜文章逻辑，不要把个人理解写成官方定义。
文字保留为 PPT 文本层。图片只做背景、材质和装饰。
每页导出 PNG 预览，生成 contact sheet（总览图），记录验证结果。
```

**image-gen 分工原则：图片负责气质，文字负责事实。** 标题、页码、引用来源、关键术语、中文说明绝不画进图片——中文可能生成错字，文案后面会改，别人打开还要挪位置。

### 第五步：标注问题逐项修改

```
根据我标注的问题逐项修改。每次修改后重新导出 PPTX、预览图和 contact sheet。
检查旧文案残留、文字换行、安全区和 PPTX 可打开性。
```

修改指令要具体："再美化一下"AI 不知道你在说什么；要拆成"文字框宽度 / mask 尺寸 / padding 是否均衡"这样的可执行项。

## 四类验收检查

| 检查 | 看什么 |
| --- | --- |
| 逐页预览 PNG | 遮挡、错位、旧文案残留 |
| contact sheet 总览 | 某页太密、风格跑偏、封面结尾撑不住 |
| PPTX 包校验 | 文件是否损坏、页数、能否重新导入、媒体正常 |
| 文本布局 | placeholder 遗漏、意外换行、安全区占用 |

## 伦理红线

- 不使用官方 logo 冒充官方内容；
- 不伪造产品截图——**视觉可以有质感，但事实层要干净**。

## 小结

- 正式对外分享才跑满全流程；内部草稿保留 memo 和 slide plan 即可；
- 快速场景也可以先试[模板库](/traework/03-first-task)和 PPT 类插件/技能；
- K 叔的原话值得抄在本子上：**"人的工作没有消失，只是换了位置——从站在每个细节里，变成站在流程上面。"**

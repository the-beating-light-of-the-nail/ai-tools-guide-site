# 进阶：Plan、Spec、Goal 三种工作流与自定义命令

TraeWork 内置三种任务工作流（Plan / Spec / Goal）和一套自定义命令机制。用对工作流，长任务的可靠性会显著提升。

> 官方文档：[work_spec-and-plan](https://docs.trae.cn/work_spec-and-plan) ｜ [work_commands](https://docs.trae.cn/work_commands)

## 三种工作流怎么选

| 工作流 | 适合 | 产物 | 可用模式 |
| --- | --- | --- | --- |
| **Plan** | 边界清晰、执行前需要确认步骤的任务（中小功能、模块级重构、缺陷修复） | `.trae/documents/` 下的 plan.md | Work / Code / Design |
| **Spec** | 范围较大、需要先对齐方案和验收标准的复杂任务（系统级任务、大规模重构、多人协作） | `.trae/specs/` 下的大纲 + tasks.md + 验收清单 | 仅 Code |
| **Goal** | 目标明确、需要智能体持续推进的长任务（连续修复测试、批量迁移、持续排查） | 目标导向的多轮续跑 | Work / Code |

入口统一：对话框输入 `/` 从列表选，或直接输 `/Plan`、`/Spec`、`/goal` 回车。

## Plan：先出计划再动手

AI 分析需求并规划 → 在 `.trae/documents/` 生成计划文档 → **你确认后**才逐项执行。计划不符预期，可以手动编辑文档或自然语言让 AI 调整。

适合办公场景的例子：整理一批报表、迁移一套文档结构——先看 AI 打算分几步、动哪些文件，确认了再放行。

## Spec：把验收标准写进文档

AI 生成三阶段文档组（大纲、任务列表、验收清单），存于 `.trae/specs/` 按任务分组。**首次创建时 AI 会暂停等你确认**；确认后，任务列表和验收清单的状态随进度自动更新。等待阶段可直接编辑文档或让 AI 改；文档可纳入版本控制，作为项目知识资产。

这套"先对齐验收标准再执行"的思路，与 QoderWork 板块的[Spec 驱动开发](/qoderwork/03-first-task)理念一致——工具不同，方法论相通。

## Goal：目标导向的多轮续跑

用自然语言定义**完成条件**，智能体每轮结束自动评估目标是否达成：未达标继续推进，达标自动停止。配合专用「操作岛台」可随时查看、编辑、暂停、删除目标。

适合"把这 50 个文件全部转换成统一格式并抽查通过"这类有明确终点的批量任务。

## 自定义命令：把常用指令封装成 `/xxx`

命令是把常用 Prompt 封装成快捷方式的机制，适合：复用高频指令（总结变更、整理会议记录）、规范输出格式（commit message、PR 描述模板）、固化常见流程（代码审查、安全检查）。

**创建步骤**（桌面版）：

1. 左下角头像 > 设置 > 左侧「命令」（或对话框左下方命令图标 → 菜单底部「管理技能与命令」）；
2. 「命令」面板点「创建」；
3. 配置字段：
   - **命令名称**：唯一标识，如 `summarize-pr-info`，仅支持小写字母、数字和短横线；
   - **描述**：什么时候用；
   - **说明 / Instructions**：AI 触发后执行什么——写清执行步骤、上下文来源、输出内容；
4. 点「确认」。可选运行环境：本地（仅桌面版）或云端。

**内置命令**：`/plan`、`/spec`、`/browser_use`（操作内置浏览器取上下文，辅助功能验证）。

使用：对话框输入 `/` 或点命令图标选择，再补充本次的具体要求。

## 命令、技能、规则怎么分工

| | 封装什么 | 触发 | 适合 |
| --- | --- | --- | --- |
| 命令 | 一段固定指令模板 | 手动 `/` 调用 | 高频短指令 |
| [技能](/traework/04-skills) | 一套方法（含脚本/资源） | 手动或 AI 自动 | 完整工作方法 |
| 规则 | 强制规范 | 全量常驻 | 编码风格、语言约定 |

# Plan、Spec、Goal 怎么选？把长任务管住不跑偏

你接一个长任务，最怕它半路跑偏：干到一半你发现方向错了，返工比重做还累。TraeWork 内置三种工作流（Plan / Spec / Goal）加一套自定义命令，帮你把长任务摁在轨道上跑。官方说明在 [work_spec-and-plan](https://docs.trae.cn/work_spec-and-plan) 和[work_commands](https://docs.trae.cn/work_commands)。

## 三种工作流怎么选

| 工作流 | 适合 | 产物 | 可用模式 |
| --- | --- | --- | --- |
| Plan | 边界清晰、执行前需要确认步骤的任务（中小功能、模块级重构、缺陷修复） | `.trae/documents/` 下的 plan.md | Work / Code / Design |
| Spec | 范围较大、需要先对齐方案和验收标准的复杂任务（系统级任务、大规模重构、多人协作） | `.trae/specs/` 下的大纲 + tasks.md + 验收清单 | 仅 Code |
| Goal | 目标明确、需要智能体持续推进的长任务（连续修复测试、批量迁移、持续排查） | 目标导向的多轮续跑 | Work / Code |

入口统一：你在对话框输入「/」从列表选，或直接输 `/Plan`、`/Spec`、`/goal` 回车。

## Plan：先出计划再动手

AI 分析需求并规划，在 `.trae/documents/` 生成计划文档，你确认后才逐项执行。计划不符预期，你手动编辑文档，或自然语言让 AI 调整。

你办公场景可以这么用：整理一批报表、迁移一套文档结构——先看 AI 打算分几步、动哪些文件，你确认了再放行。

## Spec：把验收标准写进文档

AI 生成三阶段文档组（大纲、任务列表、验收清单），存于 `.trae/specs/` 按任务分组。首次创建时 AI 会暂停等你确认；确认后，任务列表和验收清单的状态随进度自动更新。你等待阶段能直接编辑文档或让 AI 改；文档你还能纳入版本控制，当项目知识资产留着。

这套「先对齐验收标准再执行」的思路，和 QoderWork 板块的[Spec 驱动开发](/qoderwork/03-first-task)理念一致——工具不同，方法论相通。

## Goal：目标导向的多轮续跑

你用自然语言定义完成条件，智能体每轮结束自动评估目标是否达成：没达标继续推进，达标自动停止。你配合专用「操作岛台」随时查看、编辑、暂停、删除目标。

你适合拿它干「把这 50 个文件全部转换成统一格式并抽查通过」这类有明确终点的批量任务。

## 自定义命令：把常用指令封装成 /xxx

命令是把常用 Prompt 封装成快捷方式的机制。你复用高频指令（总结变更、整理会议记录）、规范输出格式（commit message、PR 描述模板）、固化常见流程（代码审查、安全检查）时，特别好用。

创建步骤（桌面版）：

1. 你点左下角头像 > 设置 > 左侧「命令」（或对话框左下方命令图标 → 菜单底部「管理技能与命令」）；
2. 你点「命令」面板「创建」；
3. 配置字段：
   - 命令名称：唯一标识，如 summarize-pr-info，仅支持小写字母、数字和短横线；
   - 描述：什么时候用；
   - 说明 / Instructions：AI 触发后执行什么——写清执行步骤、上下文来源、输出内容；
4. 你点「确认」。可选运行环境：本地（仅桌面版）或云端。

内置命令：`/plan`、`/spec`、`/browser_use`（操作内置浏览器取上下文，辅助功能验证）。

使用：你在对话框输入「/」或点命令图标选择，再补充本次的具体要求。

## 命令、技能、规则怎么分工

| | 封装什么 | 触发 | 适合 |
| --- | --- | --- | --- |
| 命令 | 一段固定指令模板 | 手动 `/` 调用 | 高频短指令 |
| [技能](/traework/04-skills) | 一套方法（含脚本/资源） | 手动或 AI 自动 | 完整工作方法 |
| 规则 | 强制规范 | 全量常驻 | 编码风格、语言约定 |

## 新手常见问题

Plan 和 Spec 该用哪个？
你任务边界清晰、想先确认步骤，用 Plan；你范围大、要先把验收标准对齐（系统级、多人协作），用 Spec。Spec 只在 Code 模式有。

Goal 适合什么活？
你目标明确、要让 AI 自己跑到底的批量活，比如「50 个文件转格式并抽查」。它每轮自测达标就停，你不用守着。

自定义命令和技能差在哪？
命令是固定指令模板，你手动「/」调用，适合高频短指令；技能是一套方法（含脚本/资源），能 AI 自动触发。你高频重复的活，命令先上。

命令名称有什么限制？
只能小写字母、数字和短横线，比如 summarize-pr-info。你起名时别带空格和大写，否则建不出来。

Spec 的文档能当资产留着吗？
能。你等待阶段就能编辑，确认后状态自动更新，文档还能纳入版本控制，当项目知识资产留着。

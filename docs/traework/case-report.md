# 案例：动态汇报——数据看板、周报与述职

静态截图周报的时代可以结束了。这一章用三个真实场景讲 TraeWork 的"动态产物"打法：数据看板、周报、述职报告。

> 场景素材改编自运营研究社[《TRAE Work 这波更新，让你的汇报直接"动"起来》](https://zhuanlan.zhihu.com/p/2064037124559606413)（2026-07）与 K 姐研究社的办公助手实测（[2026-08](https://zhuanlan.zhihu.com/p/2071317142574724109)）。

## 场景一：数据看板

**痛点**：季度汇报的时间都花在"内容呈现"而不是"内容本身"——导出 PDF、压缩截图、反复传文件，数据一更新全部重来。

**做法**：

1. 把 CSV 数据文件打包上传；
2. 用大白话描述结构：

```text
做一个季度数据看板：最上面是品牌的综合排名，
下面是不同指标的趋势图、漏斗图和对比图。
```

产出是**可交互的动态网页**：鼠标点击图表能查具体数值；数据更新后重新生成，分享链接不变、内容自动更新。TraeWork 还会自动提炼结论，例如：

> 某品牌搜索量排名第 5 但成交人数排名第 4，搜索→成交转化效率较高，IP 粉丝粘性优势显著。

细节修改三种方式：圈选页面局部用评论框下意见（如"封面加一点可爱元素"）、手动拖拽调整布局文字、直接在预览页点选元素改属性——见[第一个任务](/traework/03-first-task)。

**同款玩法**：年终聚会「议程手册」（打包分工/流程/运营文件 → 一句话生成图文网页）；社群互动游戏——

```text
做一个「冷知识闯关小游戏」：一共 20 道题，每关随机抽一道选择题，
答对进入下一关，答错显示正确答案后再进入下一关，
最后显示得分排名以及超过多少人。
```

生成带完整交互逻辑的 HTML，一键分享到群聊，打开即玩。

## 场景二：一分钟周报（配合办公助理）

绑定[办公助理](/traework/05-bot-assistant)后，在飞书里直接发：

```text
帮我优化工作总结，按照本周结论、关键进展、下周计划写周报：
- 结论用一句话说清本周最值得汇报的成果
- 关键进展列 3-5 条，说清楚做了什么、带来了什么结果
- 下周计划写 2-3 条，写清楚要推进的事情和需要的支持
```

生成后顺手接一句：

```text
把这周周报写入飞书文档，并发送到汇报群。
```

实测一分钟内完成。诀窍在于**先让 AI 归纳你的原始记录**（"帮我看看这个文档主要写了什么"），确认归类合理后再套周报结构。

## 场景三：述职报告（结构化模板全文）

```text
根据我的工作记录整理一份逻辑清晰、重点突出的述职报告。要求：
1. 对工作内容归类、合并、去重，避免写成流水账
2. 提炼 3-5 项核心业绩，按"工作背景—关键行动—实际结果—业务价值—个人贡献"展开
3. 优先使用数据和前后对比，区分团队成果与个人贡献
4. 不得虚构信息
5. 输出包括：述职总结、核心业绩、能力沉淀、问题复盘、下一阶段计划
6. 语言专业、简洁、自信，先讲结论再讲过程，少用空泛表述

岗位：【自媒体内容运营实习生】
述职周期：【2026 年第二季度】
工作记录文档：@《本周实习工作汇总》
```

「不得虚构信息」是这类高风险文档的关键约束。还可授权访问日程、会议记录、聊天记录，让汇报素材更全。

## 方法论小结

三个场景共用一条链路：**原始记录 → AI 归纳 → 结构化模板 → 写回协作工具**。

| 场景 | 输入 | 模板核心 | 输出 |
| --- | --- | --- | --- |
| 数据看板 | CSV 数据 | 结构描述 + 图表类型 | 可交互网页（链接长期有效） |
| 周报 | 工作总结文档 | 结论/进展/计划三段式 | 飞书文档 + 群消息 |
| 述职 | 工作记录 + 授权数据 | 六要求结构化模板 | 五段式述职报告 |

# 公众号→飞书知识库流水线怎么搭？全自动归档

你每天刷到好文章，顺手点收藏，然后就再也没打开过——你这也是大多数人的知识管理现状。这篇讲一位产品经理怎么用 TraeWork 把「公众号文章 → 飞书知识库」跑成全自动流水线。素材改编自 TRAE 官方论坛用户 HancksLiu 的实战帖[《我用 TraeWork 打造「公众号文章→飞书知识库」全自动流水线》](https://forum.trae.cn/t/topic/172002)（2026-07），配套技能已开源：[yucai0302/wechat-to-feishu-kb](https://github.com/yucai0302/wechat-to-feishu-kb)。

## 三个痛点

1. 微信生态封闭：通用爬虫抓公众号返回空壳页或提示「需在微信客户端打开」，你用 AI 搜索引擎也穿不透微信 CDN 防护，「一键收藏」类工具对公众号基本无效；
2. 阅读与沉淀割裂：你文章收藏了就再也没打开过，没法纳入个人或团队知识库检索复用；
3. 手动整理太贵：一篇 5000 字文章你手动归档 15-20 分钟，每周 10-15 篇，光归档就要 3-4 小时。

## 方案架构：两个 Skill + 双模式

```text
Skill 1  wechat-article-saver     抓取公众号文章 → 存本地 Markdown
Skill 2  wechat-to-feishu-kb      本地 Markdown → 飞书知识库
─────────────────────────────────────────────
即时模式：聊天中直接发文章链接 → Skill 自动触发抓取 + 写入
批量模式：链接逐行贴进 pending.txt → 每晚 22:00 定时任务自动处理
```

### 抓取：四层降级策略

微信公众号的反爬是核心难点，Skill 给你内置了四层降级，任一层成功即继续：

1. Playwright + Chromium 无头浏览器渲染；
2. HTTP fetch 带反爬 Header（User-Agent、Accept-Language 等）；
3. TraeWork 内置 WebFetch 工具；
4. 你手动粘贴原文兜底。

正文用 Mozilla Readability 提取、Turndown 转 Markdown，单篇约 30 秒。

### 沉淀：飞书对接

飞书侧你只用了 lark-cli 的两个能力：`wiki + node-create`（建知识库节点）和 `docs + update`（写文档内容）。你本地同时保留 Markdown 双备份，能被 Obsidian / Notion / Logseq 直接索引。

## 效果

| 指标 | 之前 | 之后 |
| --- | --- | --- |
| 单篇整理 | 15-20 分钟 | 5 秒（即时）/ 0 秒（定时） |
| 每周节省 | — | 3-4 小时 |
| 每月节省 | — | 约 15 小时 |
| 知识可检索 | 收藏夹里吃灰 | 100%（飞书 AI 问答 + 本地全文搜索） |
| 团队复用 | 无 | 知识库全员可访问 |

## 最重要的一课：定时任务的提示词

作者第一次配定时任务时只写了一句「抓取文章存知识库」，失败——缺 space_id、认证方式、文件路径等参数。你修正后的认知：

> 定时任务本质上是一个「无人值守的对话」，提示词越详细，越稳定。

你把完整执行步骤、参数、错误处理逻辑全写进任务说明后一次跑通。详见[自动化定时任务](/traework/07-automated-tasks)的写作清单。

## 迁移到你的场景

这条流水线的骨架是通用的：

```text
信息源（链接/邮件/报表）→ 抓取 Skill（多层降级）→ 标准化中间格式
→ 沉淀 Skill（飞书/Notion/本地知识库）→ 定时调度 + 即时对话双模式
```

你可替换的信息源：行业资讯页、竞品 changelog、应用商店评论、团队周报邮件。作者也坦承现状的局限——你本地 pending.txt 的收集方式「还不够智能」，理想的自动推荐受限于微信生态的封闭性。

## 安全提醒

- 你抓取流程涉及登录凭证时，勿在公共设备操作；
- 你尊重内容版权：归档自用与二次分发是两回事，团队知识库注意授权边界。

## 新手常见问题

为什么不能直接爬公众号？
微信生态封闭，通用爬虫返回空壳或要求客户端打开，你用 AI 搜索也穿不透 CDN 防护。作者用四层降级（含你手动粘贴兜底）才兜住。

手动归档到底多贵？
一篇 5000 字你手动归档 15-20 分钟，每周 10-15 篇就要 3-4 小时。流水线跑通后单篇 5 秒（即时）或 0 秒（定时）。

定时任务第一次为什么失败？
作者只写「抓取文章存知识库」，缺 space_id、认证、路径。你记住：定时任务是无人值守的对话，步骤、参数、异常处理写全才稳。

知识库能被团队复用吗？
能。飞书知识库全员可访问，你本地还留 Markdown 双备份，Obsidian / Notion / Logseq 直接索引。

抓来的文章能随便转发吗？
不能。你归档自用和二次分发是两回事，团队知识库要注意授权边界，别把别人的文章顺手外发。

# Skills 技能怎么装？给 AI 配一份“专业能力说明书”

你打开 TraeWork，会发现同样一句话派下去，有时它交的活特别专业，有时又很敷衍。差别往往不在模型，而在你有没有给它装上对应的技能。

技能（Skills）就是给 AI 打包好的一套专业做法——里面封着指令、脚本和相关资源，让它对着特定场景，能稳定给出内行水准的产出。你派同样一句话任务下去，装没装对技能，质量可能天差地别。官方说明在 [docs.trae.cn/work_skills](https://docs.trae.cn/work_skills)。

## 一个技能长什么样

你第一次见技能，先看它的样子：每个技能说白了就是一个带 `SKILL.md` 文件的文件夹：

```text
skill-name/
├── SKILL.md        # 必须：YAML 头部（name、description）+ 描述/使用场景/指令/示例
├── examples/       # 可选：示例
├── templates/      # 可选：模板
└── resources/      # 可选：资源
```

它最关键的设计是按需加载：AI 启动的时候只扫一眼各技能的简要描述，等任务真的高度相关了，才把完整说明调进来。你不用每次都把整本说明书塞进上下文，跑起来也轻。

三个容易混的概念，你一次认清：

| | 作用 | 加载方式 |
| --- | --- | --- |
| 技能 Skill | 描述“如何完成任务”的方法 | 按需加载 |
| 规则 Rule | 代码风格、语言框架等规范 | 全量加载、持续占用上下文 |
| MCP Server | 提供“可以调用的工具” | 按连接调用 |

## 装技能：两个来源

从市场安装最常用。你点左侧导航栏顶部的「插件市场」，进「技能」页签搜目标技能，点卡片右侧的「+」就装好了；你点卡片本身还能看详情。

网上看到好用的技能包（zip 或 .skill 文件），你也能传上来。你在「技能」页签右上角点「上传技能」加载。这里有个硬前提：压缩包根级必须包含 `SKILL.md`，而且这个文件里得有 YAML 格式的名称和描述，不然你传不进去。你第一次装，建议先从市场挑一个顺手的试。

## 用技能：三种方式

第一种是「/」快捷调用：你在对话框输入「/」，从列表里挑。

第二种是指令点名，比如你直接说「用 codemap 技能总结一下这个分支的改动」。

第三种最省心——AI 自动调用。当你的任务描述正好命中某个技能的「适用场景」，它会自己触发。所以 `SKILL.md` 里的描述你越写得准，自动触发就越靠谱。你装多了想管，技能卡片上有滑块能启用或禁用；详情弹窗左下角有「卸载」。

## 生效范围与运行环境

你建的技能分项目级和全局级，运行又分本地和云端：

| 维度 | 说明 |
| --- | --- |
| 项目技能 | 在项目内创建，仅当前项目可用，存于项目 `.trae/skills/` |
| 全局技能 | 在设置中心创建，所有项目可用（macOS/Linux `~/.trae-cn/skills`，Windows `%userprofile%\.trae-cn\skills`） |
| 本地运行 | 仅本地任务（仅桌面版） |
| 云端运行 | 云端任务及 GitHub 拉取的项目（网页版 + 桌面版） |

## 什么时候该自己做技能

按官方定位，技能主要解决三类问题：

- 输出一致性：设计规范、品牌一致性、格式约定——十次任务走同一条被验证过的路；
- 固定重复工作流：周报流程、数据清洗 SOP、内容检查清单；
- 沉淀与分享：把个人经验打包成文件，跨项目、跨团队复用。

你老是重复同一段说明，就该考虑做了。判断标准很简单：同一段任务说明你写过第三遍，就该做成技能了。你想把一本书或一套方法论蒸馏成技能，思路可以参考 WorkBuddy 板块的[打造 Skill：知识蒸馏](/workbuddy/adv-build-skill/)——`SKILL.md` 的规范两边是相通的。

## 去哪里找技能

你逛市场时，先看看官方「必装技能」清单。更多来源在这：

- TraeWork 插件市场（官方，含「必装技能」推荐清单）
- 社区技能合集：[awesome-agent-skills](https://github.com/libukai/awesome-agent-skills)、[awesome-skills-cn](https://github.com/lingxuling/awesome-skills-cn)（7000+ Skills 中文版）
- TraeWork 官方论坛 [forum.trae.cn](https://forum.trae.cn) 的用户分享帖

## 新手常见问题

技能、规则、MCP Server 到底怎么分？
技能讲「怎么完成任务」，按需加载；规则是编码规范，一直占着上下文；MCP Server 是「能调用的工具」，按连接调用。三者不是一回事，你别记混。

上传本地技能包为什么失败？
多半是压缩包根级没放 `SKILL.md`，或者文件里缺 YAML 格式的名称和描述。你这两个条件缺一个都传不进去。

AI 为什么不自动用我的技能？
自动触发靠的是任务描述命中技能的「适用场景」。你 `SKILL.md` 里的描述写得越准，它越容易对上。你描述太笼统，它就懒得触发。

项目技能和全局技能选哪个？
只在一个项目里用的，做成项目技能，存项目 `.trae/skills/`；你想跨项目复用的，去设置中心做成全局技能（macOS/Linux 在 `~/.trae-cn/skills`，Windows 在 `%userprofile%\.trae-cn\skills`）。

自己做的技能要写到第三遍才值得吗？
那是个省事的判断线。同一段任务说明你第三次手敲，基本就说明它该固化成技能了，省下的时间远超你写一次的成本。

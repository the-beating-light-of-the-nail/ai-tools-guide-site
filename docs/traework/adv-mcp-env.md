# MCP 和云端环境怎么接？把私有系统和重活交给云

你碰到插件接不进的外部系统，得靠 MCP；你本地电脑跑不动的重任务，得丢到云端运行环境。这篇讲两样怎么接。官方说明在 [work_mcp-overview](https://docs.trae.cn/work_mcp-overview) 和[work_set-up-the-remote-environment](https://docs.trae.cn/work_set-up-the-remote-environment)。

## MCP：AI 世界的 USB 接口

MCP（Model Context Protocol，模型上下文协议）是一种让大模型访问自定义工具和服务的协议。在 TraeWork 里，智能体当 MCP 客户端，向 MCP Server 发请求用它的工具。

你用 MCP 的流程分三步：① 你自行添加 MCP Server → ② 你把它加进自定义智能体 → ③ 智能体调用它的工具。

三种传输类型你按场景选：

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| stdio | 本地 | 本地命令行启动 |
| HTTP（SSE） | 本地 / 远程 | 传统远程方式 |
| Streamable HTTP | 本地 / 远程 | SSE 的升级版，推荐 |

运行环境你二选一：本地（仅本地任务，仅桌面版）或云端（云端任务及 GitHub 拉取的项目）。

你接入前先看清责任边界：MCP Server 是第三方构建维护的，TraeWork 不审查也不认可，对它行为、调用失败、返回数据不担责。你接之前看清楚它要什么权限——和[WorkBuddy 板块讲的 MCP 原理](/workbuddy/11-ai-work-system/)一致：MCP 解决「怎么连」，连了之后安不安全是你的责任。

你办公用户听一句建议：优先用官方插件市场里封装好的连接（飞书、腾讯文档等），确有私有系统需求再上自建 MCP。

## 云端运行环境

云端运行环境给云端智能体提供基于云的代码分析、执行、调试环境，统一运行时和依赖管理，避免「在我电脑上能跑」的问题。你适合拿它跑：需要在隔离环境运行、管理项目依赖、与 AI 协作复杂调试的任务。

创建步骤：

1. 你点左下角头像 > 设置 → 左侧「云端运行环境」；
2. 你点右上角「创建」，配置参数后确认。

关键配置：

| 配置 | 说明 |
| --- | --- |
| 预装依赖 | 基础镜像 + 语言版本（Python 3.10–3.14、Node.js 18–24、Go、Rust、Java 11–25、Ruby、PHP、Swift） |
| 环境变量 | 普通（明文，最多 100 个）/ 敏感变量（KMS 加密存储，最多 50 个） |
| 运行脚本 | install（≤10KB，阻塞）、start（≤10KB，非阻塞）、terminals（最多 10 个） |
| 网络白名单 | npm、pypi、maven、github、docker 等常见源 |

使用入口：网页版任务全在云端；你桌面版在输入框左下角先切「云端」再选环境。

你注意限制：自定义云端运行环境只能在 Code 模式用；暂不支持自定义容器镜像和网络策略。你办公用户多数场景用默认云端环境就行，不用自建。

## 本地任务 vs 云端任务：一张决策表

| 情况 | 选择 | 原因 |
| --- | --- | --- |
| 要操作本地文件 | 本地 | 云端摸不到你的硬盘 |
| 涉及敏感数据 | 本地（+隐私模式） | 数据不出机器 |
| 长时间跑、不想占电脑 | 云端 | 云端沙箱隔离执行 |
| 需要特定依赖环境 | 云端（自建环境） | 统一运行时 |
| 网页版发起 | 只能云端 | 网页版无本地环境 |
| 定时任务 | 云端更稳 | 不依赖你电脑开机 |

## 新手常见问题

MCP 和插件什么关系？
插件接不进的外部系统，你用 MCP 接。MCP Server 是第三方建的，TraeWork 不审查，你接之前看清它要什么权限。

云端环境只能在 Code 模式吗？
对。自定义云端运行环境只能在 Code 模式用，还不支持自定义容器镜像和网络策略。你普通办公大多用默认云端环境，不用自建。

本地和云端怎么选？
你操作本地文件、涉及敏感数据，选本地（加隐私模式）；你长时间跑、要特定依赖、网页版发起、定时任务，选云端更稳。

我接 MCP 要注意什么责任？
MCP 只解决「怎么连」，连了之后安不安全的责任在你。你接私有系统前，务必看清它申请的权限范围。

网页版能跑本地任务吗？
不能。网页版无本地环境，发起的任务只能云端跑。你要在自己电脑上动文件，得用桌面版。

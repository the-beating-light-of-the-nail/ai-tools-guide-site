# 进阶：MCP 与云端运行环境

插件覆盖不到的外部系统，用 MCP 接；本地环境跑不动的任务，放云端运行环境跑。

> 官方文档：[work_mcp-overview](https://docs.trae.cn/work_mcp-overview) ｜ [work_set-up-the-remote-environment](https://docs.trae.cn/work_set-up-the-remote-environment)

## MCP：AI 世界的 USB 接口

MCP（Model Context Protocol，模型上下文协议）是一种允许大模型访问自定义工具和服务的协议。在 TraeWork 里，智能体作为 **MCP 客户端**，向 MCP Server 发起请求使用其工具。

使用流程：①自行添加 MCP Server → ②将 MCP Server 添加到自定义智能体 → ③智能体调用其工具。

**三种传输类型**：

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| stdio | 本地 | 本地命令行启动 |
| HTTP（SSE） | 本地 / 远程 | 传统远程方式 |
| Streamable HTTP | 本地 / 远程 | SSE 的升级版，推荐 |

运行环境二选一：本地（仅本地任务，仅桌面版）或云端（云端任务及 GitHub 拉取的项目）。

**必须知道的责任边界**：MCP Server 由第三方构建和维护，TraeWork 不审查也不认可，对其行为、调用失败及返回数据不承担责任。接入前看清楚它要什么权限——和[WorkBuddy 板块讲的 MCP 原理](/workbuddy/11-ai-work-system/)一致：**MCP 解决"怎么连"，"连了之后安不安全"是你的责任**。

> 办公用户的建议：优先用官方插件市场里封装好的连接（飞书、腾讯文档等），确有私有系统需求再上自建 MCP。

## 云端运行环境

为云端智能体提供基于云的代码分析、执行和调试环境，统一运行时与依赖管理，避免"在我电脑上能跑"的问题。适合：需要在隔离环境运行、管理项目依赖、与 AI 协作复杂调试的任务。

**创建步骤**：

1. 左下角头像 > 设置 → 左侧「云端运行环境」；
2. 右上角「创建」，配置参数后确认。

**关键配置**：

| 配置 | 说明 |
| --- | --- |
| 预装依赖 | 基础镜像 + 语言版本（Python 3.10–3.14、Node.js 18–24、Go、Rust、Java 11–25、Ruby、PHP、Swift） |
| 环境变量 | 普通（明文，最多 100 个）/ 敏感变量（KMS 加密存储，最多 50 个） |
| 运行脚本 | install（≤10KB，阻塞）、start（≤10KB，非阻塞）、terminals（最多 10 个） |
| 网络白名单 | npm、pypi、maven、github、docker 等常见源 |

使用入口：网页版任务全在云端；桌面版在输入框左下角先切「云端」再选环境。

**限制**：自定义云端运行环境**只能在 Code 模式**中使用；暂不支持自定义容器镜像和网络策略。办公用户多数场景用默认云端环境即可，无需自建。

## 本地任务 vs 云端任务：一张决策表

| 情况 | 选择 | 原因 |
| --- | --- | --- |
| 要操作本地文件 | 本地 | 云端摸不到你的硬盘 |
| 涉及敏感数据 | 本地（+隐私模式） | 数据不出机器 |
| 长时间跑、不想占电脑 | 云端 | 云端沙箱隔离执行 |
| 需要特定依赖环境 | 云端（自建环境） | 统一运行时 |
| 网页版发起 | 只能云端 | 网页版无本地环境 |
| 定时任务 | 云端更稳 | 不依赖你电脑开机 |

# 進階：三大工作臺——設計、幻燈片、寫作

通用工作臺之外，QoderWork 為三類高頻產出建了垂直工作臺：設計畫布、16:9 幻燈片、長文寫作。切換入口在輸入框左下角的工作臺選擇器。

> 官方檔案：docs.qoder.com/zh/qoderwork 下的 design / slides / writing 三頁。

## 設計工作臺：AI 原生的"設計即程式碼"畫布

自然語言描述，在無限畫布上獲得**可執行、可編輯、可交付**的設計產物；產物被視為程式碼資產，可一鍵「交付給 Qoder」（IDE）繼續開發。

**八步流程**：切換工作臺 → 描述需求（截圖和連結可直接貼上）→ 可選設定（風格參考 / 工作目錄 / 保真度 / 元件庫）→ 選執行模式（「直接執行」跳過澄清；「進入設計計劃模式」先對齊）→ 回答澄清問題（每題有備選項，可"AI 自行決定"）→ 確認設計計劃（稽核"契約"面板：產物/平臺/輸出/元件庫/保真度/風格）→ 觀察生成（左側"深度思考"實時推理）→ 預覽（可點 CTA、看 hover、走查導航流）。

**關鍵設定**：

| 設定 | 可選值 |
| --- | --- |
| 風格參考 | 自動選擇（161 個參考裡挑）或指定 Airbnb / Apple / Carbon / Ant Design 等 |
| 保真度 | 線框圖 / 高保真（預設） |
| 元件庫 | 不指定（HTML-first）/ shadcn/ui / Spark Design / Ant Design |

**迭代三板斧**：追加指令；**Nudge 微調**（配色、間距、圓角引數，無需重新描述）；直接編輯畫布背後的設計檔案原始碼。三大機制（Questions 追問、Design Plan、Nudge）解決的是"AI 猜錯方向"的老問題——資訊不足時先追問，而不是猜。

## 幻燈片工作臺：先大綱後成片

右側畫布是 16:9、1280×720 的 HTML 幻燈片工作區。**硬性前置：必須先確認大綱**——「大綱」標籤裡每節帶一句簡介和版式標籤（封面頁/文字大綱/左圖右文/雙欄/引文等），"接受大綱"才開始生成，不合適可附反饋駁回。

流程：切換工作臺 → 描述需求 → 挑模版（可"不使用模版"，內建 35 個）→ 回答澄清（受眾、頁數、語言）→ **確認大綱** → 看生成過程（縮圖逐張就緒）→ 後處理選項（可全跳過）→ 檢視成果。

產出匯出：**PPTX、PDF、HTML** 三格式；常用模版可"儲存為模版"複用。

官方建議："好的需求往往同時點出**受眾**和**想讓對方記住什麼**，而不僅僅是主題。"

## 寫作工作臺：長文的版本化管理

面向文章、報告、推文、技術指南、內部檔案。Document 工作區 = Markdown 檔案樹 + 編輯器；產物落到本地 `outputs/` 目錄；**每一輪迭代都保留為可回溯的版本**（編輯器右上角可切"最新版本/早期版本"，可匯出 PDF）。

語氣五選：不指定（AI 自行判斷）/ 正式 / 輕鬆 / 技術 / 創意。

五個官方典型場景：

| 場景 | 輸入 → 輸出 |
| --- | --- |
| 零散筆記 → 技術指南 | 散記資料夾 → 結構化指南 |
| 無責內部故障覆盤 | 對話/日誌 → 覆盤檔案 |
| PR 列表 → 釋出說明 | git 記錄 → 按 Features/Improvements/Fixes 分組 |
| 技術部落格 | 主題+字數結構 → 成稿 |
| API 規範 → 整合指南 | 介面檔案 → 鑑權、cURL 示例、錯誤碼錶、FAQ |

注意：手動編輯後，AI 後續輪次會**基於你的修改**繼續——人改稿不會被 AI 覆蓋。

## 怎麼選

| 需求 | 工作臺 |
| --- | --- |
| 檔案、資料、調研、自動化 | 通用 |
| 海報、落地頁、UI 原型 | 設計 |
| 彙報、課件、路演 | 幻燈片 |
| 文章、報告、指南 | 寫作 |

> 對比視角：TraeWork 的做法是用 Design 模式 + HTML 產物覆蓋設計場景（見[做一套能上臺的 PPT](/zh-tw/traework/case-ppt)），QoderWork 的垂類工作臺更"開箱即用"——兩種路線按手感選。

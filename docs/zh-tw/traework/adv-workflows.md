# Plan、Spec、Goal 怎麼選？把長任務管住不跑偏

你接一個長任務，最怕它半路跑偏：幹到一半你發現方向錯了，返工比重做還累。TraeWork 內建三種工作流（Plan / Spec / Goal）加一套自定義命令，幫你把長任務摁在軌道上跑。官方說明在 [work_spec-and-plan](https://docs.trae.cn/work_spec-and-plan) 和[work_commands](https://docs.trae.cn/work_commands)。

## 三種工作流怎麼選

| 工作流 | 適合 | 產物 | 可用模式 |
| --- | --- | --- | --- |
| Plan | 邊界清晰、執行前需要確認步驟的任務（中小功能、模組級重構、缺陷修復） | `.trae/documents/` 下的 plan.md | Work / Code / Design |
| Spec | 範圍較大、需要先對齊方案和驗收標準的複雜任務（系統級任務、大規模重構、多人協作） | `.trae/specs/` 下的大綱 + tasks.md + 驗收清單 | 僅 Code |
| Goal | 目標明確、需要智慧體持續推進的長任務（連續修復測試、批次遷移、持續排查） | 目標導向的多輪續跑 | Work / Code |

入口統一：你在對話方塊輸入「/」從列表選，或直接輸 `/Plan`、`/Spec`、`/goal` 回車。

## Plan：先出計劃再動手

AI 分析需求並規劃，在 `.trae/documents/` 生成計劃檔案，你確認後才逐項執行。計劃不符預期，你手動編輯檔案，或自然語言讓 AI 調整。

你辦公場景可以這麼用：整理一批報表、遷移一套檔案結構——先看 AI 打算分幾步、動哪些檔案，你確認了再放行。

## Spec：把驗收標準寫進檔案

AI 生成三階段檔案組（大綱、任務列表、驗收清單），存於 `.trae/specs/` 按任務分組。首次建立時 AI 會暫停等你確認；確認後，任務列表和驗收清單的狀態隨進度自動更新。你等待階段能直接編輯檔案或讓 AI 改；檔案你還能納入版本控制，當專案知識資產留著。

這套「先對齊驗收標準再執行」的思路，和 QoderWork 板塊的[Spec 驅動開發](/zh-tw/qoderwork/03-first-task)理念一致——工具不同，方法論相通。

## Goal：目標導向的多輪續跑

你用自然語言定義完成條件，智慧體每輪結束自動評估目標是否達成：沒達標繼續推進，達標自動停止。你配合專用「操作島臺」隨時檢視、編輯、暫停、刪除目標。

你適合拿它幹「把這 50 個檔案全部轉換成統一格式並抽查通過」這類有明確終點的批次任務。

## 自定義命令：把常用指令封裝成 /xxx

命令是把常用 Prompt 封裝成快捷方式的機制。你複用高頻指令（總結變更、整理會議記錄）、規範輸出格式（commit message、PR 描述模板）、固化常見流程（程式碼審查、安全檢查）時，特別好用。

建立步驟（桌面版）：

1. 你點左下角頭像 > 設定 > 左側「命令」（或對話方塊左下方命令圖示 → 選單底部「管理技能與命令」）；
2. 你點「命令」面板「建立」；
3. 配置欄位：
   - 命令名稱：唯一標識，如 summarize-pr-info，僅支援小寫字母、數字和短橫線；
   - 描述：什麼時候用；
   - 說明 / Instructions：AI 觸發後執行什麼——寫清執行步驟、上下文來源、輸出內容；
4. 你點「確認」。可選執行環境：本地（僅桌面版）或雲端。

內建命令：`/plan`、`/spec`、`/browser_use`（操作內建瀏覽器取上下文，輔助功能驗證）。

使用：你在對話方塊輸入「/」或點命令圖示選擇，再補充本次的具體要求。

## 命令、技能、規則怎麼分工

| | 封裝什麼 | 觸發 | 適合 |
| --- | --- | --- | --- |
| 命令 | 一段固定指令模板 | 手動 `/` 呼叫 | 高頻短指令 |
| [技能](/zh-tw/traework/04-skills) | 一套方法（含指令碼/資源） | 手動或 AI 自動 | 完整工作方法 |
| 規則 | 強制規範 | 全量常駐 | 編碼風格、語言約定 |

## 新手常見問題

Plan 和 Spec 該用哪個？
你任務邊界清晰、想先確認步驟，用 Plan；你範圍大、要先把驗收標準對齊（系統級、多人協作），用 Spec。Spec 只在 Code 模式有。

Goal 適合什麼活？
你目標明確、要讓 AI 自己跑到底的批次活，比如「50 個檔案轉格式並抽查」。它每輪自測達標就停，你不用守著。

自定義命令和技能差在哪？
命令是固定指令模板，你手動「/」呼叫，適合高頻短指令；技能是一套方法（含指令碼/資源），能 AI 自動觸發。你高頻重複的活，命令先上。

命令名稱有什麼限制？
只能小寫字母、數字和短橫線，比如 summarize-pr-info。你起名時別帶空格和大寫，否則建不出來。

Spec 的檔案能當資產留著嗎？
能。你等待階段就能編輯，確認後狀態自動更新，檔案還能納入版本控制，當專案知識資產留著。

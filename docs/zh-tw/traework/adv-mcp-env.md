# 進階：MCP 與雲端執行環境

外掛覆蓋不到的外部系統，用 MCP 接；本地環境跑不動的任務，放雲端執行環境跑。

> 官方文件：[work_mcp-overview](https://docs.trae.cn/work_mcp-overview) ｜ [work_set-up-the-remote-environment](https://docs.trae.cn/work_set-up-the-remote-environment)

## MCP：AI 世界的 USB 介面

MCP（Model Context Protocol，模型上下文協議）是一種允許大模型訪問自定義工具和服務的協議。在 TraeWork 裡，智慧體作為 **MCP 客戶端**，向 MCP Server 發起請求使用其工具。

使用流程：①自行新增 MCP Server → ②將 MCP Server 新增到自定義智慧體 → ③智慧體呼叫其工具。

**三種傳輸型別**：

| 型別 | 位置 | 說明 |
| --- | --- | --- |
| stdio | 本地 | 本地命令列啟動 |
| HTTP（SSE） | 本地 / 遠端 | 傳統遠端方式 |
| Streamable HTTP | 本地 / 遠端 | SSE 的升級版，推薦 |

執行環境二選一：本地（僅本地任務，僅桌面版）或雲端（雲端任務及 GitHub 拉取的專案）。

**必須知道的責任邊界**：MCP Server 由第三方構建和維護，TraeWork 不審查也不認可，對其行為、呼叫失敗及返回資料不承擔責任。接入前看清楚它要什麼許可權——和[WorkBuddy 板塊講的 MCP 原理](/zh-tw/workbuddy/11-ai-work-system/)一致：**MCP 解決"怎麼連"，"連了之後安不安全"是你的責任**。

> 辦公使用者的建議：優先用官方外掛市場裡封裝好的連線（飛書、騰訊文件等），確有私有系統需求再上自建 MCP。

## 雲端執行環境

為雲端智慧體提供基於雲的程式碼分析、執行和除錯環境，統一執行時與依賴管理，避免"在我電腦上能跑"的問題。適合：需要在隔離環境執行、管理專案依賴、與 AI 協作複雜除錯的任務。

**建立步驟**：

1. 左下角頭像 > 設定 → 左側「雲端執行環境」；
2. 右上角「建立」，配置引數後確認。

**關鍵配置**：

| 配置 | 說明 |
| --- | --- |
| 預裝依賴 | 基礎映象 + 語言版本（Python 3.10–3.14、Node.js 18–24、Go、Rust、Java 11–25、Ruby、PHP、Swift） |
| 環境變數 | 普通（明文，最多 100 個）/ 敏感變數（KMS 加密儲存，最多 50 個） |
| 執行指令碼 | install（≤10KB，阻塞）、start（≤10KB，非阻塞）、terminals（最多 10 個） |
| 網路白名單 | npm、pypi、maven、github、docker 等常見源 |

使用入口：網頁版任務全在雲端；桌面版在輸入框左下角先切「雲端」再選環境。

**限制**：自定義雲端執行環境**只能在 Code 模式**中使用；暫不支援自定義容器映象和網路策略。辦公使用者多數場景用預設雲端環境即可，無需自建。

## 本地任務 vs 雲端任務：一張決策表

| 情況 | 選擇 | 原因 |
| --- | --- | --- |
| 要操作本地檔案 | 本地 | 雲端摸不到你的硬碟 |
| 涉及敏感資料 | 本地（+隱私模式） | 資料不出機器 |
| 長時間跑、不想佔電腦 | 雲端 | 雲端沙箱隔離執行 |
| 需要特定依賴環境 | 雲端（自建環境） | 統一執行時 |
| 網頁版發起 | 只能雲端 | 網頁版無本地環境 |
| 定時任務 | 雲端更穩 | 不依賴你電腦開機 |

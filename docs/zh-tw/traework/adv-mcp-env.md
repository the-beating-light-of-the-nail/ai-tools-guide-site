# MCP 和雲端環境怎麼接？把私有系統和重活交給雲

你碰到外掛接不進的外部系統，得靠 MCP；你本地電腦跑不動的重任務，得丟到雲端執行環境。這篇講兩樣怎麼接。官方說明在 [work_mcp-overview](https://docs.trae.cn/work_mcp-overview) 和[work_set-up-the-remote-environment](https://docs.trae.cn/work_set-up-the-remote-environment)。

## MCP：AI 世界的 USB 介面

MCP（Model Context Protocol，模型上下文協議）是一種讓大模型訪問自定義工具和服務的協議。在 TraeWork 裡，智慧體當 MCP 客戶端，向 MCP Server 發請求用它的工具。

你用 MCP 的流程分三步：① 你自行新增 MCP Server → ② 你把它加進自定義智慧體 → ③ 智慧體呼叫它的工具。

三種傳輸型別你按場景選：

| 型別 | 位置 | 說明 |
| --- | --- | --- |
| stdio | 本地 | 本地命令列啟動 |
| HTTP（SSE） | 本地 / 遠端 | 傳統遠端方式 |
| Streamable HTTP | 本地 / 遠端 | SSE 的升級版，推薦 |

執行環境你二選一：本地（僅本地任務，僅桌面版）或雲端（雲端任務及 GitHub 拉取的專案）。

你接入前先看清責任邊界：MCP Server 是第三方構建維護的，TraeWork 不審查也不認可，對它行為、呼叫失敗、返回資料不擔責。你接之前看清楚它要什麼權限——和[WorkBuddy 板塊講的 MCP 原理](/zh-tw/workbuddy/11-ai-work-system/)一致：MCP 解決「怎麼連」，連了之後安不安全是你的責任。

你辦公使用者聽一句建議：優先用官方外掛市場裡封裝好的連線（飛書、騰訊檔案等），確有私有系統需求再上自建 MCP。

## 雲端執行環境

雲端執行環境給雲端智慧體提供基於雲的程式碼分析、執行、除錯環境，統一執行時和依賴管理，避免「在我電腦上能跑」的問題。你適合拿它跑：需要在隔離環境執行、管理專案依賴、與 AI 協作複雜除錯的任務。

建立步驟：

1. 你點左下角頭像 > 設定 → 左側「雲端執行環境」；
2. 你點右上角「建立」，配置引數後確認。

關鍵配置：

| 配置 | 說明 |
| --- | --- |
| 預裝依賴 | 基礎映象 + 語言版本（Python 3.10–3.14、Node.js 18–24、Go、Rust、Java 11–25、Ruby、PHP、Swift） |
| 環境變數 | 普通（明文，最多 100 個）/ 敏感變數（KMS 加密儲存，最多 50 個） |
| 執行指令碼 | install（≤10KB，阻塞）、start（≤10KB，非阻塞）、terminals（最多 10 個） |
| 網路白名單 | npm、pypi、maven、github、docker 等常見源 |

使用入口：網頁版任務全在雲端；你桌面版在輸入框左下角先切「雲端」再選環境。

你注意限制：自定義雲端執行環境只能在 Code 模式用；暫不支援自定義容器映象和網路策略。你辦公使用者多數場景用預設雲端環境就行，不用自建。

## 本地任務 vs 雲端任務：一張決策表

| 情況 | 選擇 | 原因 |
| --- | --- | --- |
| 要操作本地檔案 | 本地 | 雲端摸不到你的硬碟 |
| 涉及敏感資料 | 本地（+隱私模式） | 資料不出機器 |
| 長時間跑、不想佔電腦 | 雲端 | 雲端沙箱隔離執行 |
| 需要特定依賴環境 | 雲端（自建環境） | 統一執行時 |
| 網頁版發起 | 只能雲端 | 網頁版無本地環境 |
| 定時任務 | 雲端更穩 | 不依賴你電腦開機 |

## 新手常見問題

MCP 和外掛什麼關係？
外掛接不進的外部系統，你用 MCP 接。MCP Server 是第三方建的，TraeWork 不審查，你接之前看清它要什麼權限。

雲端環境只能在 Code 模式嗎？
對。自定義雲端執行環境只能在 Code 模式用，還不支援自定義容器映象和網路策略。你普通辦公大多用預設雲端環境，不用自建。

本地和雲端怎麼選？
你操作本地檔案、涉及敏感資料，選本地（加隱私模式）；你長時間跑、要特定依賴、網頁版發起、定時任務，選雲端更穩。

我接 MCP 要注意什麼責任？
MCP 只解決「怎麼連」，連了之後安不安全的責任在你。你接私有系統前，務必看清它申請的權限範圍。

網頁版能跑本地任務嗎？
不能。網頁版無本地環境，發起的任務只能雲端跑。你要在自己電腦上動檔案，得用桌面版。

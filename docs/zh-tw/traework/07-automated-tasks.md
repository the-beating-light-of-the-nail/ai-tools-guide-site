# 自動化定時任務

到點自動執行預設任務、生成結果，全程無需人工干預——這是 TraeWork 從"你問它才動"變成"到點自己幹"的關鍵功能。

> 官方文件：[docs.trae.cn/work_automated-tasks](https://docs.trae.cn/work_automated-tasks)

## 入口與建立方式

入口：左欄頂部「自動化」按鈕 → 定時任務管理面板（三個頁籤：任務模板、已配置、執行歷史；建立按鈕在右上角）。

三種建立方式，按順手程度選：

**方式一：在對話中建立**（推薦，支援自然語言觸發時間）

1. 點右上角「在對話中建立」；
2. 輸入任務內容和執行時間（如"工作日早上 9 點"）；
3. 輸入框左下角選執行環境及輸出儲存位置；
4. 傳送 → AI 解讀，必要時確認細節；
5. 檢查 AI 輸出的任務資訊並調整。

**方式二：手動新建**——右上角「手動新建」→ 在彈窗裡逐項配置 → 「建立」。

**方式三：從模板建立**——「任務模板」頁籤選模板（配置已預設好）→ 按需修改 → 「建立」。

## 關鍵配置項

| 配置 | 可選值 |
| --- | --- |
| 執行模式 | Work / Code（注意：建立後不可改） |
| 執行環境 | 雲端 / 本地（建立後不可改） |
| 觸發方式 | 固定時間（每天/每週/每月）、間隔觸發（分鐘/小時/天）、自定義（自然語言，僅對話建立支援） |
| 任務內容 | 完整任務指令 |
| 輸出儲存位置 | 產物落盤目錄（建立後不可改） |

## 官方推薦的四類場景

| 場景 | 任務示例 |
| --- | --- |
| 程式碼倉庫定期維護 | 安全掃描、Bug 排查、補測試用例、變更日報（Code 模式） |
| 資訊檢索與彙總 | 行業資訊、競品動態、應用商店評論摘要、政策更新提醒 |
| 品牌輿情 | 輿情週報、社群討論跟蹤、使用者反饋歸集 |
| 週期性彙報 | 行業速遞、運營日報、關鍵指標監控 |

一個可直接抄的輿情週報任務：

```text
每天早上 9:00，收集過去 24 小時內與【我的公司/產品名】相關的公開報道和社媒討論，
按"媒體報道 / 使用者反饋 / 競品動態"分類，標註來源和連結；
有效資訊少於 3 條時輸出說明而不是硬湊內容；
輸出一份 Markdown 週報草稿存到 output/ 目錄。
```

## 必須記住的限制

1. 對話中建立時，執行模式預設為當前模式且**不支援修改**；
2. **任務一旦建立，無法修改執行模式、執行環境和輸出儲存位置**——要改只能刪了重建；
3. 檢視執行歷史時，TraeWork 當前執行模式需與任務的執行模式一致；
4. 雲端任務依賴帳號積分，長任務留意[積分消耗](/zh-tw/traework/adv-models-credits)。

## 定時任務的提示詞要寫得更細

定時任務本質上是**無人值守的對話**：執行時沒有你在旁邊補話。社群實測的典型教訓——第一次只寫"抓取文章存知識庫"，因缺少具體引數（存到哪、怎麼認證、失敗怎麼辦）而失敗；把完整執行步驟、引數和錯誤處理寫進任務說明後，一次跑通。

寫作清單：

- [ ] 資料來源寫明確（哪個網站/哪個檔案/哪個表格）
- [ ] 輸出格式和儲存路徑寫明確
- [ ] 異常處理寫明確（資料為空時怎麼辦、來源失敗時怎麼辦）
- [ ] 跑通一次手動對話再固化為定時任務

一個完整的定時 + 推送組合：定時任務生成日報 + [辦公助理](/zh-tw/traework/05-bot-assistant)綁定飛書群，就是一條"早 9 點自動日報進群"的流水線。實戰案例見[公眾號→飛書知識庫流水線](/zh-tw/traework/case-feishu-pipeline)。

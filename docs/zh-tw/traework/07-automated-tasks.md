# 自動化定時任務怎麼設？讓 AI 到點自己幹

你以前用 TraeWork，是「你問它才動」。自動化定時任務把這個關係反過來：你定好時間，它到你定的點自己跑、自己出結果，全程不用守著，連睡覺它也在跑。官方說明在 [docs.trae.cn/work_automated-tasks](https://docs.trae.cn/work_automated-tasks)。

## 入口和三種建法

你點左欄頂部的「自動化」按鈕，進定時任務管理面板。進面板先認三頁籤：任務模板、已配置、執行歷史；建立按鈕在右上角。

建法有三種，挑順手的：

方式一：在對話中建立（推薦，能用大白話定時間）。你點右上角「在對話中建立」，把任務內容和執行時間寫進去（比如「工作日早上 9 點」），在輸入框左下角選執行環境和輸出儲存位置，傳送後 AI 幫你解讀，必要時確認細節，再檢查它給出的任務資訊調一調。

方式二：手動新建。你點右上角「手動新建」，在彈窗裡逐項配置，點「建立」。

方式三：從模板建立。你切到「任務模板」頁籤選一個（配置已預設好），按需改一改，點「建立」。

## 關鍵配置項

| 配置 | 可選值 |
| --- | --- |
| 執行模式 | Work / Code（注意：建立後不可改） |
| 執行環境 | 雲端 / 本地（建立後不可改） |
| 觸發方式 | 固定時間（每天/每週/每月）、間隔觸發（分鐘/小時/天）、自定義（自然語言，僅對話建立支援） |
| 任務內容 | 完整任務指令 |
| 輸出儲存位置 | 產物落盤目錄（建立後不可改） |

注意最後一列：執行模式、執行環境、輸出儲存位置這三個，一旦建立就改不了，要改你只能刪了重建。

## 官方推薦的四類場景

| 場景 | 任務示例 |
| --- | --- |
| 程式碼倉庫定期維護 | 安全掃描、Bug 排查、補測試用例、變更日報（Code 模式） |
| 資訊檢索與彙總 | 行業資訊、競品動態、應用商店評論摘要、政策更新提醒 |
| 品牌輿情 | 輿情週報、社群討論跟蹤、使用者反饋歸集 |
| 週期性彙報 | 行業速遞、運營日報、關鍵指標監控 |

一個能直接抄的輿情週報任務：

```text
每天早上 9:00，收集過去 24 小時內與【我的公司/產品名】相關的公開報道和社媒討論，
按"媒體報道 / 使用者反饋 / 競品動態"分類，標註來源和連結；
有效資訊少於 3 條時輸出說明而不是硬湊內容；
輸出一份 Markdown 週報草稿存到 output/ 目錄。
```

## 必須記住的限制

1. 對話中建立時，執行模式預設為當前模式且不支援修改，你發現不對也改不了；
2. 任務一旦建立，無法修改執行模式、執行環境和輸出儲存位置——要改只能刪了重建；
3. 你檢視執行歷史時，TraeWork 當前執行模式需與任務的執行模式一致；
4. 雲端任務依賴賬號積分，長任務留意[積分消耗](/zh-tw/traework/adv-models-credits)。

## 定時任務的提示詞要寫得更細

定時任務本質上是無人值守的對話：執行時沒你在旁邊補話。社群實測你也會踩坑——第一次只寫「抓取文章存知識庫」，因缺具體引數（存到哪、怎麼認證、失敗怎麼辦）而失敗；你把完整執行步驟、引數和錯誤處理寫進任務說明後，一次跑通。

寫作清單：

- [ ] 資料來源寫明確（哪個網站/哪個檔案/哪個表格）
- [ ] 輸出格式和儲存路徑寫明確
- [ ] 異常處理寫明確（資料為空時怎麼辦、來源失敗時怎麼辦）
- [ ] 你先跑通一次手動對話，再固化為定時任務

一個完整的組合：你把它和[辦公助理](/zh-tw/traework/05-bot-assistant)繫結飛書群串起來，就是一條「早 9 點自動日報進群」的流水線。實戰案例見[公眾號→飛書知識庫流水線](/zh-tw/traework/case-feishu-pipeline)。

## 新手常見問題

定時任務能隨時改時間嗎？
時間、觸發方式這些能改。但執行模式、執行環境、輸出儲存位置這三項建立後就鎖死，只能刪了重建。

對話裡建立和手動建立差在哪？
對話建立能用大白話定時間（比如「工作日早 9 點」），AI 幫你解讀成配置；手動建立得自己逐項填。圖省事就用對話建立。

為什麼我第一次只寫一句就失敗了？
定時任務是無人值守的對話，沒人在旁邊補話。漏了存哪、怎麼認證、失敗怎麼辦，它就卡住。把步驟和異常處理寫全，一次就能跑通。

查執行歷史要注意什麼？
當前執行模式得和任務執行模式一致，否則歷史看不了。你切錯模式，歷史就空了。

長任務會不會燒積分？
會。雲端任務按賬號積分計費，長任務留意[積分消耗](/zh-tw/traework/adv-models-credits)。先手動跑通再掛定時，別讓它在沒人時反覆失敗燒錢。

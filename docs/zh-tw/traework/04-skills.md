# Skills 技能怎麼裝？給 AI 配一份“專業能力說明書”

你開啟 TraeWork，會發現同樣一句話派下去，有時它交的活特別專業，有時又很敷衍。差別往往不在模型，而在你有沒有給它裝上對應的技能。

技能（Skills）就是給 AI 打包好的一套專業做法——裡面封著指令、指令碼和相關資源，讓它對著特定場景，能穩定給出內行水準的產出。你派同樣一句話任務下去，裝沒裝對技能，質量可能天差地別。官方說明在 [docs.trae.cn/work_skills](https://docs.trae.cn/work_skills)。

## 一個技能長什麼樣

你第一次見技能，先看它的樣子：每個技能說白了就是一個帶 `SKILL.md` 檔案的資料夾：

```text
skill-name/
├── SKILL.md        # 必須：YAML 頭部（name、description）+ 描述/使用場景/指令/示例
├── examples/       # 可選：示例
├── templates/      # 可選：模板
└── resources/      # 可選：資源
```

它最關鍵的設計是按需載入：AI 啟動的時候只掃一眼各技能的簡要描述，等任務真的高度相關了，才把完整說明調進來。你不用每次都把整本說明書塞進上下文，跑起來也輕。

三個容易混的概念，你一次認清：

| | 作用 | 載入方式 |
| --- | --- | --- |
| 技能 Skill | 描述“如何完成任務”的方法 | 按需載入 |
| 規則 Rule | 程式碼風格、語言框架等規範 | 全量載入、持續佔用上下文 |
| MCP Server | 提供“可以呼叫的工具” | 按連線呼叫 |

## 裝技能：兩個來源

從市場安裝最常用。你點左側導航欄頂部的「外掛市場」，進「技能」頁籤搜目標技能，點卡片右側的「+」就裝好了；你點卡片本身還能看詳情。

網上看到好用的技能包（zip 或 .skill 檔案），你也能傳上來。你在「技能」頁籤右上角點「上傳技能」載入。這裡有個硬前提：壓縮包根級必須包含 `SKILL.md`，而且這個檔案裡得有 YAML 格式的名稱和描述，不然你傳不進去。你第一次裝，建議先從市場挑一個順手的試。

## 用技能：三種方式

第一種是「/」快捷呼叫：你在對話方塊輸入「/」，從列表裡挑。

第二種是指令點名，比如你直接說「用 codemap 技能總結一下這個分支的改動」。

第三種最省心——AI 自動呼叫。當你的任務描述正好命中某個技能的「適用場景」，它會自己觸發。所以 `SKILL.md` 裡的描述你越寫得準，自動觸發就越靠譜。你裝多了想管，技能卡片上有滑塊能啟用或停用；詳情彈窗左下角有「解除安裝」。

## 生效範圍與執行環境

你建的技能分專案級和全域性級，執行又分本地和雲端：

| 維度 | 說明 |
| --- | --- |
| 專案技能 | 在專案內建立，僅當前專案可用，存於專案 `.trae/skills/` |
| 全域性技能 | 在設定中心建立，所有專案可用（macOS/Linux `~/.trae-cn/skills`，Windows `%userprofile%\.trae-cn\skills`） |
| 本地執行 | 僅本地任務（僅桌面版） |
| 雲端執行 | 雲端任務及 GitHub 拉取的專案（網頁版 + 桌面版） |

## 什麼時候該自己做技能

按官方定位，技能主要解決三類問題：

- 輸出一致性：設計規範、品牌一致性、格式約定——十次任務走同一條被驗證過的路；
- 固定重複工作流：週報流程、資料清洗 SOP、內容檢查清單；
- 沉澱與分享：把個人經驗打包成檔案，跨專案、跨團隊複用。

你老是重複同一段說明，就該考慮做了。判斷標準很簡單：同一段任務說明你寫過第三遍，就該做成技能了。你想把一本書或一套方法論蒸餾成技能，思路可以參考 WorkBuddy 板塊的[打造 Skill：知識蒸餾](/zh-tw/workbuddy/adv-build-skill/)——`SKILL.md` 的規範兩邊是相通的。

## 去哪裡找技能

你逛市場時，先看看官方「必裝技能」清單。更多來源在這：

- TraeWork 外掛市場（官方，含「必裝技能」推薦清單）
- 社群技能合集：[awesome-agent-skills](https://github.com/libukai/awesome-agent-skills)、[awesome-skills-cn](https://github.com/lingxuling/awesome-skills-cn)（7000+ Skills 中文版）
- TraeWork 官方論壇 [forum.trae.cn](https://forum.trae.cn) 的使用者分享帖

## 新手常見問題

技能、規則、MCP Server 到底怎麼分？
技能講「怎麼完成任務」，按需載入；規則是編碼規範，一直佔著上下文；MCP Server 是「能呼叫的工具」，按連線呼叫。三者不是一回事，你別記混。

上傳本地技能包為什麼失敗？
多半是壓縮包根級沒放 `SKILL.md`，或者檔案裡缺 YAML 格式的名稱和描述。你這兩個條件缺一個都傳不進去。

AI 為什麼不自動用我的技能？
自動觸發靠的是任務描述命中技能的「適用場景」。你 `SKILL.md` 裡的描述寫得越準，它越容易對上。你描述太籠統，它就懶得觸發。

專案技能和全域性技能選哪個？
只在一個專案裡用的，做成專案技能，存專案 `.trae/skills/`；你想跨專案複用的，去設定中心做成全域性技能（macOS/Linux 在 `~/.trae-cn/skills`，Windows 在 `%userprofile%\.trae-cn\skills`）。

自己做的技能要寫到第三遍才值得嗎？
那是個省事的判斷線。同一段任務說明你第三次手敲，基本就說明它該固化成技能了，省下的時間遠超你寫一次的成本。

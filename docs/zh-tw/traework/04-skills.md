# Skills：給 AI 裝上"專業能力說明書"

技能（Skills）是 TraeWork 生態裡最重要的概念之一：每個技能封裝了指令、指令碼及相關資源，為智慧體提供**可複用、面向特定場景的專業能力**。同樣一句話任務，裝沒裝對技能，產出品質可能天差地別。

> 官方文件：[docs.trae.cn/work_skills](https://docs.trae.cn/work_skills)

## Skill 是什麼

每個技能就是一個帶 `SKILL.md` 檔案的資料夾：

```text
skill-name/
├── SKILL.md        # 必須：YAML 頭部（name、description）+ 描述/使用場景/指令/示例
├── examples/       # 可選：示例
├── templates/      # 可選：模板
└── resources/      # 可選：資源
```

它的關鍵設計是**按需載入**：智慧體啟動時只掃描各技能的簡要描述，任務高度相關才載入完整說明——有效減少上下文中的 Token 消耗。

三個相鄰概念別混淆：

| | 作用 | 載入方式 |
| --- | --- | --- |
| 技能 Skill | 描述"如何完成任務"的方法 | 按需載入 |
| 規則 Rule | 程式碼風格、語言框架等規範 | 全量載入、持續佔用上下文 |
| MCP Server | 提供"可以呼叫的工具" | 按連線呼叫 |

## 裝技能：兩個來源

**從市場安裝**（最常用）：

1. 左側導航欄頂部點「外掛市場」；
2. 進入「技能」頁籤，搜尋目標技能；
3. 點卡片右側 **+** 安裝；點卡片可看詳情。

**上傳本地技能包**：在網上看到好用的技能包（zip 或 .skill 檔案），在「技能」頁籤右上角點「上傳技能」載入。前置條件：壓縮包**根級必須包含 SKILL.md**，且 SKILL.md 含 YAML 格式的名稱和描述。

## 用技能：三種方式

1. **`/` 快捷呼叫**：對話方塊輸入 `/` 從列表選；
2. **指令點名**：如"用 codemap 技能總結一下這個分支的改動"；
3. **AI 自動呼叫**：任務描述命中技能的"適用場景"時自動觸發——所以 SKILL.md 裡的描述寫得越準，自動觸發越可靠。

管理：技能卡片滑塊啟用/禁用；詳情彈窗左下角「解除安裝」。

## 技能的生效範圍與執行環境

| 維度 | 說明 |
| --- | --- |
| 專案技能 | 在專案內建立，僅當前專案可用，存於專案 `.trae/skills/` |
| 全域性技能 | 在設定中心建立，所有專案可用（macOS/Linux `~/.trae-cn/skills`，Windows `%userprofile%\.trae-cn\skills`） |
| 本地執行 | 僅本地任務（僅桌面版） |
| 雲端執行 | 雲端任務及 GitHub 拉取的專案（網頁版 + 桌面版） |

## 什麼時候值得做自己的技能

按官方定位，技能解決三類問題：

- **輸出一致性**：設計規範、品牌一致性、格式約定——十次任務走同一條被驗證過的路；
- **固定重複工作流**：週報流程、資料清洗 SOP、內容檢查清單；
- **沉澱與分享**：把個人經驗打包成檔案，跨專案、跨團隊複用。

判斷標準很簡單：**同一段任務說明你寫過第三遍，就該做成技能了。** 想把一本書或一套方法論蒸餾成技能，思路可以參考 WorkBuddy 板塊的[打造 Skill：知識蒸餾](/zh-tw/workbuddy/adv-build-skill/)——SKILL.md 的規範兩邊是相通的。

# 案例：用 TraeWork 做一套能上臺的 PPT

> 改編自 TRAE 核心使用者 K 叔的實測長文[《用 TRAE Work 做 PPT，最重要的不是「生成」》](https://zhuanlan.zhihu.com/p/2056077700767428956)（2026-07）。他的任務：把 OpenAI 兩篇工程文章的讀後感，整理成 11 頁社群分享 PPT。

## 為什麼"幫我做個 PPT"必翻車

一句話"幫我根據這篇文章做一份分享 PPT"，產出往往是**像網頁截圖、像後台頁面、像設計 demo，就是不像一套能站在臺上講的 PPT**。原因不是模型不行，而是你沒說清"怎麼才算做好"。

兩個最常見的坑：

- **視覺指令反向帶偏**："高階一點 / 科技感"會把 AI 帶向藍紫漸變、玻璃卡片、等距元件、儀表板佈局。有效做法是**反向定義**——"不要等距卡片、不要按鈕感標籤、不要 dashboard 式頁面"，目標定為"紙張筆記、批註、現場講解"風。
- **標題不像人話**：❌"認知遞進 / 模式變化" → ✅"AI 新詞不是憑空冒出來的 / 痛點在往後移"。檢驗法：標題單獨讀一遍，現場不會說的話就別放頁首。

## 五步鏈路：先定義"好"，再讓 AI 推進

K 叔的完整流程分五步，每步產出一份"錨點檔案"，**每一步都可以停下來改**——停在越早的環節，改動成本越低。

### 第一步：深度拆解材料，產出 memo

```
請先不要生成 PPT。
先分別分析這兩篇文章，每篇提取核心議題、核心主張、論證骨架、
認知增量和邊界條件。再基於分析整理一份讀後感 memo。
不要逐段摘要，重點提取兩篇之間的遞進關係。
輸出後停住，等我確認。
```

關鍵：**停在 memo 階段改方向**。PPT 生成後問題會混在一起（主線/標題/視覺/文字框），那時再改最貴。

### 第二步：slide plan——每頁一個主張

基於確認的 memo 整理 10 頁左右的 slide plan，格式：

```text
Slide 03 / Claim：AI 程式設計的痛點在往後移
Proof object：Harness → sessions → supervision overload → Symphony
Layout：process sequence
```

11 頁按"讀後認知順序"排而非文章目錄：封面 → Hook → 遞進 → 方法一 → 現場 → 新瓶頸 → 方法二 → 模式變化 → 邊界 → 給小團隊 → 收束。

### 第三步：design brief——反向定義風格

```
基於已確認的 slide plan 寫 design brief，重點寫清楚：
- 這套 PPT 不要像什麼
- 視覺方向和參考物件
- 背景安全區（常規內容放中間，底部不貼太低，頁碼不壓紋理邊緣）
- 哪些文字必須可編輯
- 哪些元素可以用 image-gen 生成
- 哪些說法只是讀後理解，不能寫成官方定義
```

### 第四步：生成可編輯 PPTX

```
基於已確認的 memo、slide plan 和 design brief 生成可編輯 PPTX。
不要重新猜文章邏輯，不要把個人理解寫成官方定義。
文字保留為 PPT 文字層。圖片只做背景、材質和裝飾。
每頁匯出 PNG 預覽，生成 contact sheet（總覽圖），記錄驗證結果。
```

**image-gen 分工原則：圖片負責氣質，文字負責事實。** 標題、頁碼、引用來源、關鍵術語、中文說明絕不畫進圖片——中文可能生成錯字，文案後面會改，別人開啟還要挪位置。

### 第五步：標註問題逐項修改

```
根據我標註的問題逐項修改。每次修改後重新匯出 PPTX、預覽圖和 contact sheet。
檢查舊文案殘留、文字換行、安全區和 PPTX 可開啟性。
```

修改指令要具體："再美化一下"AI 不知道你在說什麼；要拆成"文字框寬度 / mask 尺寸 / padding 是否均衡"這樣的可執行項。

## 四類驗收檢查

| 檢查 | 看什麼 |
| --- | --- |
| 逐頁預覽 PNG | 遮擋、錯位、舊文案殘留 |
| contact sheet 總覽 | 某頁太密、風格跑偏、封面結尾撐不住 |
| PPTX 包校驗 | 檔案是否損壞、頁數、能否重新匯入、媒體正常 |
| 文字佈局 | placeholder 遺漏、意外換行、安全區佔用 |

## 倫理紅線

- 不使用官方 logo 冒充官方內容；
- 不偽造產品截圖——**視覺可以有質感，但事實層要乾淨**。

## 小結

- 正式對外分享才跑滿全流程；內部草稿保留 memo 和 slide plan 即可；
- 快速場景也可以先試[模板庫](/zh-tw/traework/03-first-task)和 PPT 類外掛/技能；
- K 叔的原話值得抄在本子上：**"人的工作沒有消失，只是換了位置——從站在每個細節裡，變成站在流程上面。"**

# 安全治理：動作、資料、後果與人機責任

## 什麼時候需要看

如果你只是讀取自己有權檢視的資料、整理一份不觸達他人的草稿，可以先跳過本章。只要任務涉及團隊共享、個人或客戶資料、自動寫入臺賬或待辦、跨系統連線、對外傳送、付款、刪除、審批，或輸出可能影響法律、財務、人事決定，就回到這裡確認誰能做、誰要確認，以及失敗時如何停。你不必先記住 G0–G3：先看實際動作、資料敏感度和可能後果，再按本章登記。

## 30 秒結論

<span id="claim-g0-g3-controls-01" data-claim-id="claim-g0-g3-controls-01"></span>G0–G3 只表示動作風險等級；資料敏感度和專業後果必須獨立判斷，並採用三者中更嚴格的控制。

<span id="claim-g2-continuous-authorization-01" data-claim-id="claim-g2-continuous-authorization-01"></span>G2 只有在工作流正式釋出、邊界明確且取得共同核准的持續授權後，才可從逐批事前確認轉為核准範圍內執行和抽檢；G3 每次仍須事前確認。

<span id="claim-human-responsibility-01" data-claim-id="claim-human-responsibility-01"></span>業務負責人始終對最終業務結果負責，不能把責任轉移給 AI 或流程維護者；G3 執行者與動作核准人不得為同一人。

## 為什麼重要

只按「讀」或「寫」判斷風險會遺漏兩類問題：讀取候選人資訊雖然不改變系統狀態，卻涉及個人資訊；生成法律、財務或人事判斷即使只儲存草稿，也可能影響高後果決定。反過來，普通內部資料上的可逆新檔案與覆蓋原件、外發或刪除，也不能使用同一確認規則。

把動作、資料和專業後果拆開後，業務負責人能看清誰承擔結果，流程維護者能實現正確的確認與回退，資料/安全責任人能按授權範圍設定控制下限。等級不是自動化成熟度，也不是「允許執行」的標籤；它只是決定最低控制強度的一個維度。

## 方法或模型

### 先獨立判斷 G0–G3 動作等級

| 等級 | 固定定義 | 預設控制 |
|---|---|---|
| G0 只讀 | 不改變業務物件、許可權或外部狀態 | 已授權資料範圍內可自動執行，保留來源和訪問記錄 |
| G1 可逆草稿寫入 | 只新建隔離草稿或新檔案；物件可識別、可刪除或恢復，不觸達外部接收人，不覆蓋原件 | 可執行後通知，必須保留原件和恢復路徑 |
| G2 業務狀態寫入 | 建立或更新內部待辦、臺賬、日誌、CRM 等業務物件 | 預設每批執行前展示物件、欄位和影響並取得明確確認；只有正式釋出且取得持續授權的有界工作流，才可在核准範圍內執行並接受抽檢 |
| G3 高後果動作 | 對外傳送、公開發布、付款、審批、刪除、主資料修改或其他難撤銷動作 | 每次執行前強制確認並保留審計記錄；抽檢不能替代事前核准 |

「可逆」必須由實際恢復路徑證明。只寫「可以刪除」但無法識別物件、找回原件或驗證恢復結果，不滿足 G1；覆蓋原件也不屬於 G1。G2 的「明確確認」必須讓核准人看到本批物件、欄位和影響，不能用通用彈窗或曾經同意代替。

### 再判斷資料敏感度

| 資料類別 | 典型範圍 | 最小處理要求 |
|---|---|---|
| 公開 | 已合法公開且允許當前用途的資訊 | 保留來源、日期和使用邊界 |
| 內部 | 僅供組織內部使用的一般經營和協作資訊 | 限定成員、系統和用途，保留訪問記錄 |
| 機密/個人或客戶資訊 | 商業機密、個人資訊、客戶資料及可反推身份的資料 | 最小授權、限定用途和留存，控制不低於 G2 |
| 受監管或組織秘密 | 受專門法規、合同或組織最高敏感級規則約束的資料 | 按 G3 控制，並服從適用制度和專業要求 |

### 獨立判斷專業後果

| 專業後果 | 判斷問題 | 典型控制重點 |
|---|---|---|
| 資訊輔助 | 輸出是否只幫助查詢、整理或理解，不直接改變業務決定 | 來源、準確性和適用範圍 |
| 日常運營 | 輸出是否影響常規任務分配、臺賬狀態、客戶跟進或內部運營 | 物件、欄位、許可權、複核和回退 |
| 法律/財務/人事等高後果判斷 | 輸出是否可能影響權利義務、資金、錄用淘汰、薪酬或其他重大決定 | 具備職責或資質的獨立專業複核和明確核准 |

動作等級保持獨立判斷；機密資料或高後果判斷控制不低於 G2；受監管資料、組織秘密或 G3 動作按 G3 控制；組織政策更嚴格時以組織政策為準。控制升級不會改變動作本身的標籤，例如讀取個人資訊仍是 G0 動作，但必須按不低於 G2 的強度限制授權、記錄訪問和安排複核。

### 固定六類責任角色

| 角色 | 固定責任 |
|---|---|
| 業務負責人 | 定義目標、範圍、驗收和停止條件，核准業務上線並對最終結果負責 |
| 流程維護者 | 維護工作流版本、邊界、測試、監控、停用和恢復路徑 |
| 資料/安全責任人 | 確認資料分類、最小授權、日誌、留存、事件處置和持續授權邊界 |
| 使用者 | 在授權範圍提供輸入、執行任務、檢查可見異常並提交驗收記錄 |
| 內容複核者 | 核對事實、數字、來源、表達和所需專業結論，記錄通過或退回 |
| 動作核准人 | 在動作發生前核對物件、範圍和影響，核准或拒絕 G2/G3 動作 |

小團隊可以兼任角色，但 G3 執行者與動作核准人不得為同一人。流程維護者對執行品質負責，內容複核者對其簽署的複核負責，動作核准人對具體動作授權負責；這些分工都不免除業務負責人對最終業務結果的責任。

### 為 G2 持續授權設定有界登記

G2 預設逐批事前確認。只有通過 [團隊工作流釋出階段門](/zh-tw/qwenwork/ch10-pilot-roadmap)、範圍可列舉並可立即停用的工作流，才可申請持續授權。業務負責人和資料/安全責任人必須共同核准，並記錄以下全部欄位：

| 登記欄位 | 必填內容 |
|---|---|
| 允許的業務物件 | 可建立或更新的物件型別、系統和可識別範圍 |
| 欄位 | 允許讀取與寫入的欄位白名單，明確禁止欄位 |
| 單批上限 | 每次執行可影響的最大物件數或金額等業務上限 |
| 執行頻率 | 排程或人工觸發頻率，以及禁止執行時段 |
| 有效期 | 起止日期；預設不超過 90 天 |
| 日誌位置 | 可由責任人訪問、檢索和匯出的審計位置 |
| 抽檢頻率 | 預設至少每週一次，並說明樣本選擇規則 |
| 撤銷人 | 有權立即停用持續授權的具體角色或人員 |
| 撤銷條件 | 許可權、欄位、接收物件、錯誤率或其他邊界變化的觸發規則 |
| 繫結的工作流版本 | 唯一版本號或不可變版本標識，以及對應測試和釋出記錄 |
| 執行賬號/服務身份 | 實際執行所用賬號、服務身份及其最小許可權範圍 |
| 執行環境 | 獲核准的系統、租戶、空間和生產或測試環境 |
| 核准用途 | 允許處理的業務目的，以及明確禁止的二次用途 |

舊授權只對登記的工作流版本、執行賬號/服務身份、執行環境和核准用途有效，不能移用於其他版本、執行主體、環境或用途。許可權、欄位、接收物件或錯誤率任一變化時，持續授權無條件立即失效。工作流邏輯或規則、版本、模型、連接器、執行主體或執行環境任一變化時，持續授權也立即失效。工作流應先停用並恢復逐批確認，再經修訂、重驗和共同核准後重新啟用。預設有效期屆滿也應失效，不能靜默續期。

持續授權期間執行日誌必須覆蓋 100% 的執行，且至少每週抽檢。日誌至少記錄執行 ID、工作流版本、執行主體、物件、關鍵欄位前後值、結果和異常；涉及個人資訊、客戶資訊或其他敏感內容時，只按已核准的日誌策略記錄必要值、受保護引用或內容摘要，並執行相應的訪問和留存期限控制。「100% 留存」是每次執行都有可審計記錄，不代表無限制複製或永久儲存敏感原值。

G3 不允許持續授權豁免單次確認。每次執行前必須向動作核准人展示接收人或物件、具體動作、關鍵內容或欄位、影響範圍和不可逆後果；每次核准都要繫結不可變動作版本或內容摘要、一次性執行 ID 和登記有效期。接收人或物件、動作、關鍵內容、欄位或影響發生變化，有效期屆滿，發生重複執行，或執行失敗後準備重試時，都必須重新展示並取得核准；抽檢不能替代事前核准。

G3 審計記錄同時儲存核准快照標識和實際執行的接收人或物件、動作、關鍵內容或欄位值、結果和異常，以便比對核准內容與實際結果。敏感內容只在授權範圍內留痕，可使用受保護引用或內容摘要，不得借審計之名擴大複製、訪問或留存範圍。

### 辦公動作例子：同一份會議紀要的四種動作

先用普通動作理解等級，再檢視錶格規則。下面的「確認」是對具體物件、內容和影響的確認，不是點過一次就永久授權；階段通過不自動獲得許可權。

| 動作 | 實際例子 | 誰確認、確認什麼 | 失敗時怎麼停 |
|---|---|---|---|
| G0 只讀 | 讀取已授權的會議記錄，提取結論、待辦和來源，不改變業務物件或外部狀態。 | 使用者確認任務範圍；資料/安全責任人確認來源和訪問範圍；內容複核者確認事實能回到原記錄。 | 發現許可權失效、來源版本不明或個人資料超出用途時立即停止讀取和生成，保留已授權原件，轉人工核對，不改用未授權賬號。 |
| G1 隔離草稿 | 根據週報輸入新建一份隔離的會議紀要草稿或新檔案，不覆蓋原件、不觸達收件人。 | 使用者確認草稿位置和輸入版本；內容複核者確認可編輯、可核驗；流程維護者確認物件標識、原件保護和恢復路徑。 | 草稿落錯位置、無法識別物件、覆蓋原件或恢復演練失敗時立即停用，保護原件，人工接管；修正後驗證恢復結果，不能只寫「可刪除」。 |
| G2 內部臺賬/待辦寫入 | 把已確認的會議行動項寫入內部臺賬或待辦，顯示物件、欄位和影響，不對外傳送。 | 動作核准人按本批實際物件確認欄位、數量、影響和回退；業務負責人確認業務範圍；資料/安全責任人確認授權。只有正式釋出、邊界可列舉且共同核准的工作流才可申請 G2 持續授權。 | 物件或欄位不一致、重複寫入、許可權異常或寫入結果不可核對時停止本批和後續排程，先失效持續授權，保護原臺賬，人工核對並恢復；修訂後重驗，不能沿用舊核准。 |
| G3 對外傳送、付款或刪除 | 將會議紀要發給客戶、執行付款、刪除記錄，或做其他難撤銷的外部動作。 | 動作核准人每次確認接收人或物件、具體動作、關鍵內容或欄位、影響和不可逆後果；執行者與核准人分離。業務負責人對最終業務結果負責。 | 任一內容、物件、版本、影響變化，執行失敗或準備重試時，立即停止並阻斷重試，保護原件，人工接管，核對實際影響和核准快照；恢復後驗證，之後仍需重新逐次確認。 |

普通讀者的最小記錄是：輸入版本、人工改了什麼、遇到什麼異常、誰驗收了什麼、最後產生了什麼結果。可用 [第 9 章公開案例圖譜（含 32 個待核驗場景線索）](/zh-tw/qwenwork/ch09-public-case-atlas) 選擇會議紀要或跟進類場景練習；圖譜只能幫助理解動作和產物形態，不能替代本組織的授權、專業複核或核准記錄。

## 案例與證據

同一條「客戶拜訪跟進」工作流可以同時出現多個等級：讀取已授權 CRM 記錄是 G0；另存不觸達客戶的郵件草稿且保留原件是 G1；更新內部 CRM 跟進狀態是 G2；向客戶傳送郵件是 G3。即使 G2 更新已經取得持續授權，最後的對外傳送仍須逐次確認。執行時按輸入版本、人工修改、異常、驗收和結果留痕，才能在失敗後定位是許可權、內容還是動作確認出了問題。

再看候選人狀態整理：動作可能只是 G0 讀取和彙總，但輸入包含個人資訊，因此控制不低於 G2；若輸出參與錄用、淘汰或薪酬等高後果判斷，還必須由相應專業責任人複核。提高控制強度不代表允許自動作出人事決定。

千問辦公官方幫助中心提供隱私與安全說明。 [R9](/zh-tw/qwenwork/appendix-sources#r9) 實際產品能力、資料處理方式和組織配置應以使用時頁面與合同為準；本章 G0–G3、角色分工和持續授權期限屬於社群治理建議，不是產品官方風險評級或法律意見。

## 企業行動

為每條準備試點或已執行的工作流補齊一張治理卡：

1. 逐動作標記 G0–G3，不按整條流程取一個模糊平均等級。
2. 分別標記資料敏感度和專業後果，並應用三者中更嚴格的控制。
3. 指定六類角色；檢查 G3 執行者與動作核准人是否分離。
4. 驗證 G1 原件、物件標識和恢復路徑，實際演練一次恢復。
5. 為 G2 配置逐批預覽和明確確認；確需持續授權時填寫全部登記欄位並共同核准。
6. 為 G3 配置逐次確認、審計記錄和失敗後的人工接管，不設定抽檢豁免。
7. 把未授權動作、重大隱私問題和關鍵業務錯誤接入第 10 章停止規則。
8. 至少每週檢查 G2 日誌和異常；邊界變化時先失效授權，再調查原因。

最小上線證據包括當前工作流版本、授權記錄、角色名單、確認介面或記錄、日誌位置、抽檢結果、停用開關和恢復演練。缺少任一必要控制時，縮小範圍或保持人工執行。

## 邊界與下一步

本章提供通用治理模型，不替代組織制度、合同義務、監管要求或法律、財務、人事等專業判斷。資料類別需要由瞭解組織資料和適用規則的人確認；專業後果不確定時，按更高等級控制並請求專業複核。

治理等級不會證明工作流有效，階段門也不會自動授予許可權。組織應同時使用第 10 章試點階段門和自動化接管鏈，讓工作流既通過品質與價值驗證，也能在許可權、輸入或錯誤率變化時停止、接管和恢復。

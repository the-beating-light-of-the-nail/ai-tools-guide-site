# 崗位路線：用統一場景卡選擇真實任務

## 30 秒結論

<span id="claim-role-scenario-card-01" data-claim-id="claim-role-scenario-card-01"></span>本書建議：崗位 AI 場景統一使用業務問題、角色、輸入、當前步驟、交付物、驗收、禁做動作、指標、風險、基線十個欄位登記，先證明一個任務有效，再組合崗位工作流。

- 崗位名稱不能代替具體業務問題。
- 指標必須與人工基線比較，並同時觀察品質和風險。
- 場景評分、樣本要求和階段門只由第 10 章定義。

## 你可能遇到的場景

你是 HR、銷售、產品、財務法務或內容市場人員，想找一個真正能落地的 AI 任務，而不是泛泛地「給崗位配助手」。輸入例子可以是招聘週會臺賬、客戶拜訪資料、專案風險記錄、合同與明細，或已核驗來源和品牌規範；先按任務卡寫清楚再選路線。

## 最後會得到什麼

最終產物是一張崗位場景卡，結構為：業務問題、角色、輸入、當前步驟、交付物、驗收、禁做動作、指標、風險、基線；卡片還應標明對應的任務頁、負責這項結果的人（Owner）和人工確認人。

## 照著做

1. 先選一個崗位中高頻、輸入可取得、結果可人工判斷且失敗可逆的任務，不用崗位名稱代替問題。
2. 按[任務交付協議](/zh-tw/qwenwork/ch02-task-delivery-protocol)填寫五欄位，再補上崗位角色、禁做動作、指標和基線。
3. **中間檢查點：**讓業務負責人確認交付物和驗收，讓資料或系統 Owner 確認授權，讓內容或專業複核者確認品質邊界。
4. 從對應任務頁開始試跑：交付看[交付新標準](/zh-tw/qwenwork/ch01-delivery-standard)，辦公產物看[辦公交付](/zh-tw/qwenwork/ch06-office-delivery)，研究看[研究與證據鏈](/zh-tw/qwenwork/ch08-research-evidence-chain)。

## 案例參考

崗位路線可以先參考[品勝電子：競品調研與產品物料製作](/zh-tw/qwenwork/case-pisen)的研究與物料任務，也可以看[優克拉：產品研發與考勤算薪](/zh-tw/qwenwork/case-youkela)的研發和算薪任務；這些案例不能替代你自己的基線、許可權和專業確認。

## 做完檢查

逐項檢查場景卡是否能讓另一位同事複述「用什麼輸入、做出什麼產物、按什麼條件通過、哪些動作禁止」；並確認至少有一條品質指標和一條人工基線。無法複述就退回補卡。

## 需要注意

如果場景只有崗位口號、沒有可取得輸入，或驗收依賴錄用、付款、法律意見、路線圖承諾和對外發布等高後果判斷，保留現有人工流程，停止自動化試跑，改成人工整理或只讀分析，由業務和專業負責人確認後再選任務。

## 為什麼重要

「給 HR 一個助手」或「為銷售做智慧體」無法直接驗收。崗位範圍太大，資料許可權和後果也不一致；一個成功的材料整理任務不能證明人員決策、報價或釋出動作可以自動化。

統一場景卡把崗位需求壓縮成可比較的業務單元。企業 AI 負責人可以按真實輸入、當前步驟和風險選擇試點，業務負責人可以確認交付物和禁做動作，運營團隊可以採集同口徑基線。

## 方法或模型

場景卡的十個欄位在所有崗位保持同義；下列五張卡是起步示例，不是固定最佳實踐。

### HR：招聘週會狀態整理

| 欄位 | 場景內容 |
|---|---|
| 業務問題 | 招聘週會前需要快速識別職位阻塞和缺失反饋 |
| 角色 | 招聘負責人、招聘專員、用人經理 |
| 輸入 | 獲授權的職位臺賬、面試反饋、入職準備清單和上週版本 |
| 當前步驟 | 匯出、合併、追問缺失項、整理狀態、準備週會 |
| 交付物 | 職位—階段—阻塞—負責人—下一步的可編輯狀態表 |
| 驗收 | 每個狀態可回到原始反饋；缺失項單列；責任人和截止時間明確 |
| 禁做動作 | 不自動錄用、淘汰、評價候選人，不向無許可權物件傳播個人資訊 |
| 指標 | 準備時長、反饋完整率、狀態誤配率、人工修改量 |
| 風險 | 候選人隱私、反饋偏見、同名誤配、舊狀態覆蓋 |
| 基線 | 記錄當前人工準備時間、缺失反饋、退回和修正樣本 |

### 銷售與商務：客戶拜訪準備與跟進

| 欄位 | 場景內容 |
|---|---|
| 業務問題 | 會前資訊分散，會後行動和承諾容易遺漏 |
| 角色 | 客戶經理、售前、銷售負責人 |
| 輸入 | 公開資訊、獲授權的 CRM 記錄、歷史溝通和產品資料 |
| 當前步驟 | 蒐集、核對、形成提綱、記錄會議、起草跟進 |
| 交付物 | 一頁準備單、事實與待確認問題、郵件草稿、待寫入清單 |
| 驗收 | 事實標註來源和日期；承諾、報價、負責人和截止時間經過確認 |
| 禁做動作 | 不自動報價、承諾、傳送或修改客戶主記錄 |
| 指標 | 準備時長、事實錯誤率、行動遺漏率、CRM 建議採納率 |
| 風險 | 客戶資訊越權、陳舊資訊、虛構承諾、錯誤收件人 |
| 基線 | 採集現有準備用時、會後遺漏、退信和記錄修正情況 |

### 產品與專案：專案風險臺賬

| 欄位 | 場景內容 |
|---|---|
| 業務問題 | 需求、週會和缺陷中的變化無法及時彙總為決策請求 |
| 角色 | 產品經理、專案經理、研發負責人 |
| 輸入 | 需求文件、專案計劃、週會記錄、缺陷和變更日誌 |
| 當前步驟 | 對齊版本、提取變化、判斷影響、分配責任、請求決策 |
| 交付物 | 風險臺賬、變更摘要、待決事項和版本釋出說明草稿 |
| 驗收 | 風險有證據、Owner、截止時間和緩解動作；決定與建議分開 |
| 禁做動作 | 不自動改變優先順序、關閉缺陷、承諾釋出日期或覆蓋路線圖 |
| 指標 | 彙總時長、風險遺漏率、決策等待時長、變更可追溯率 |
| 風險 | 版本混用、責任誤配、未確認狀態被寫成決定 |
| 基線 | 記錄現有彙總步驟、漏項、等待時間和會後修訂 |

### 財務與法務：高後果材料核對

| 欄位 | 場景內容 |
|---|---|
| 業務問題 | 大量明細和條款需要定位異常，但最終判斷必須由專業人員承擔 |
| 角色 | 財務人員、法務人員、業務負責人 |
| 輸入 | 獲授權的明細、報表、合同版本、規則和專業模板 |
| 當前步驟 | 勾稽或條款抽取、異常定位、版本比較、形成複核清單 |
| 交付物 | 財務勾稽表或條款定位表、異常清單、版本差異和待確認項 |
| 驗收 | 金額、日期、公式、條款位置和版本可追溯；專業人員簽署結論 |
| 禁做動作 | 不自動記賬、付款、修改主資料、給出最終法律意見或簽署合同 |
| 指標 | 核對時長、異常檢出率、誤報率、人工修改量、退回次數 |
| 風險 | 金額或版本錯誤、許可權越界、把提示誤當專業結論 |
| 基線 | 儲存人工核對時間、已知異常、漏檢、誤報和複核記錄 |

### 內容與市場：有證據的內容流水線

| 欄位 | 場景內容 |
|---|---|
| 業務問題 | 選題、素材、審校、釋出和覆盤分散，事實與品牌風險難控制 |
| 角色 | 內容運營、市場、品牌和設計負責人 |
| 輸入 | 已核驗來源、選題池、品牌規範、授權素材和渠道要求 |
| 當前步驟 | 研究、選題、起草、設計、事實審校、預覽、釋出、覆盤 |
| 交付物 | 選題證據表、內容草稿、素材清單、釋出預覽和覆盤記錄 |
| 驗收 | 事實有來源和日期；品牌、版權、連結和渠道格式通過檢查 |
| 禁做動作 | 不使用無授權素材，不虛構效果或客戶，不未經確認對外發布 |
| 指標 | 製作時長、事實退回率、品牌問題數、釋出錯誤率、複用率 |
| 風險 | 版權、誤導表述、敏感資訊、過期連結和錯誤渠道 |
| 基線 | 採集現有周期、審校修改、釋出事故和素材複用情況 |

## 案例與證據

五張卡來自現有崗位任務的社群整理，沒有使用未經授權的客戶名稱或效果數字。它們證明的是場景卡如何填寫，不證明這些場景在所有組織中優先順序相同。

指標必須成對觀察效率與品質。例如準備時長下降時，也要檢查事實錯誤、人工修改和風險事件是否上升。沒有人工基線或資料口徑不同的結果不能直接比較。

## 企業行動

每個崗位只選擇一個候選任務：

1. 由業務負責人填寫業務問題、交付物、驗收和禁做動作。
2. 由使用者記錄當前步驟、輸入位置和人工基線。
3. 由資料或系統 Owner 核對授權範圍和高風險動作。
4. 由內容複核者定義品質指標和退回原因。
5. 把完整場景卡交給第 10 章階段門評審，本章不自行評分或設閾值。

停止訊號包括：場景只能用崗位名稱描述；沒有可取得的輸入；交付物不可驗收；禁做動作未明確；指標只記錄速度；基線來自不同口徑或只保留成功樣本。

## 邊界與下一步

場景卡不是崗位績效評價，也不能用 AI 輸出替代錄用、付款、法律意見、路線圖承諾或對外發布決定。組織應按資料敏感度和專業後果增加更嚴格的規則。

本章負責定義崗位場景，不負責評分和推廣階段門。場景卡完成後，團隊仍需建立研究與證據方法，避免把印象寫成業務事實。

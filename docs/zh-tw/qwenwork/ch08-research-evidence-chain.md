# 研究與證據鏈：從問題樹（把大問題拆成小問題的提問框架）到釋出記錄

## 白話導讀

這一章幫你把「搜了一堆資料寫出來的報告」變成能複核、能追責的研究交付。你做競品、市場或經營分析時最常翻車：轉述被寫成官方事實、不同口徑的數字被直接平均、過期頁面撐著當前結論。本章給你兩樣東西——九欄位證據卡和衝突登記——你每查到一條主張就記一張卡，來源、口徑、限制寫清楚；來源打架時你登記差異，不擅用平均數掩蓋。你讀完再做研究，別人能開啟來源、定位原文、複述口徑，你的結論才立得住。

## 30 秒結論

<span id="claim-evidence-card-fields-01" data-claim-id="claim-evidence-card-fields-01"></span>本章將證據卡（記錄來源、口徑和限制的小卡片）唯一規範定義為九個欄位：主張、來源原文、來源型別、日期、統計口徑、適用範圍、限制、衝突、狀態。

<span id="claim-research-question-tree-01" data-claim-id="claim-research-question-tree-01"></span>本書建議：研究先把決策問題拆成可由證據回答的問題樹（把大問題拆成小問題的提問框架），再檢索和寫作，避免「搜尋到什麼就寫什麼」。

白話解釋：這兩條為什麼這麼定？你若先搜再寫，結論會被搜到的材料帶著走，哪篇順手寫哪篇。你先按決定反推問題樹，再為每枝指定來源和停止條件，搜來的東西才有處安放、才敢用。

## 你可能遇到的場景

你要查資料形成一份競品、市場或經營分析結論，但搜尋結果很多，來源口徑和日期卻不一樣。輸入例子是「要支援的預算決定、截止日期、目標市場、已有官方資料和訪談記錄」；你先把決定拆成問題樹，再開始檢索，別拿到關鍵詞就開搜。

## 你會拿到什麼

你照這套備好一套可釋出的研究包，它最少包含：

1. 問題樹和來源計劃：每個子問題、優先來源、備選來源和停止條件；
2. 證據卡（記錄來源、口徑和限制的小卡片）：主張、來源原文、來源型別、日期、統計口徑、適用範圍、限制、衝突、狀態；
3. 衝突登記（把不同來源的差異記下來的記錄）：編號、相關卡片、差異、可能原因、處理動作、負責核對和處理這條證據的人（Owner）和狀態；
4. 分層結論：已核驗事實、基於證據的推斷、建議、待確認問題和釋出前複核記錄。

## 照著做

1. 你先寫讀者要作的決定，再把它拆成可由證據回答的問題樹，並給每個子問題指定來源和停止條件。
2. 你採集標題、連結、日期和原文位置，按九欄位製作證據卡，不把搜尋摘要直接寫成結論。
3. **中間檢查點：**你逐卡核對物件、期間、單位、定義和授權；發現衝突就登記，不用平均數或多數投票掩蓋差異。
4. 你將事實、推斷、建議和待確認問題分層，釋出前由未參與撰寫的人抽檢關鍵主張、高後果結論和敏感資訊。

## 案例參考

可先看[千問辦公公開案例庫：32 個場景圖譜](/zh-tw/qwenwork/ch09-public-case-atlas)，從競品調研、經營分析等相近任務理解「輸入—證據—產物」的關係；你拿它當待核驗的公開線索即可，它不是客戶背書，不能直接算進你的案例數。

## 做完檢查

隨機抽查 3 條關鍵主張，要求複核人能開啟來源、定位原文、複述統計口徑和限制；任何一條無法複述，就降低結論強度、補證，或從釋出稿移出。

白話解釋：你別把抽檢當蓋章。隨機挑 3 條關鍵主張，讓複核人真能開啟來源、定位原文、說出口徑和限制；任一條說不出，你就降級、補證或移出，別帶著含糊結論往外發。

## 需要注意

如果關鍵數字無原文、來源需要登入卻無人負責、不同定義被直接比較，或高後果結論無人複核，保留原始資料和證據卡，停止釋出；回到上一穩定版本，改成人工只讀分析或並列披露衝突，由資料或專業 Owner 確認後再繼續。

白話解釋：你遇到這些紅燈就停發：關鍵數字找不到原文、來源要登入卻沒人認領、不同定義被直接比、高後果結論沒人複核。你先退到上一穩定版，改成只讀分析或把衝突並列擺出來，等 Owner 確認再繼續。

## 為什麼重要

你讀研究報告時最危險的失敗不是篇幅不足，而是語言完整卻無法複核：轉述被寫成官方事實，不同口徑的數字被直接比較，過期頁面支撐當前結論，公開演示被包裝成客戶效果。

問題樹決定需要什麼證據，證據卡儲存每條主張的邊界，衝突登記防止團隊用平均或多數投票消除真實差異。它們共同幫你判斷結論能支援什麼決定，以及哪些問題仍需人工確認。

白話解釋：這節是給管理者看的。你驗收一份研究，別隻看頁數和不漏洞。你問三件事：每條主張能不能回溯來源、不同口徑的差異有沒有登記、高後果結論有沒有人複核；三件缺一件，結論就不能直接拿去拍板。

## 方法或模型

你先從決定反推問題樹：

| 子問題 | 需要的證據 | 優先來源 | 不能直接得出的結論 |
|---|---|---|---|
| 市場是否變化 | 連續期間、規模或增速及完整口徑 | 監管、統計、公司披露 | 用單篇報道預測份額 |
| 客戶是否有痛點 | 訪談原話、工單或使用資料 | 獲授權的一手訪談和內部資料 | 用競品廣告替代客戶需求 |
| 方案是否可行 | 產品說明、測試樣本、成本和失敗記錄 | 官方檔案、受控試點、原始記錄 | 用功能入口推斷穩定交付率 |
| 組織是否能採用 | 權限、流程、責任和專業後果 | 組織制度、系統 Owner、專業意見 | 用 AI 摘要代替合規判斷 |

一張證據卡只支援一個最小主張，固定欄位如下：

| 欄位 | 必填內容 | 不合格訊號 |
|---|---|---|
| 主張 | 一句可核驗、不過度外推的陳述 | 混入評價詞或多個結論 |
| 來源原文 | 標題、機構、連結或位置，以及必要原文摘記 | 只有搜尋摘要或二次轉述 |
| 來源型別 | `official-product`（官方產品）、`regulatory-statistical`（監管統計）、`first-party-disclosure`（一手披露）、`customer-authorized`（客戶授權）、`independent-research`（獨立研究）、`public-demo`（公開演示）、`community-framework`（社群框架） | 不說明誰產生了資料 |
| 日期 | 釋出、訪問和必要的採集日期 | 無法判斷是否過期 |
| 統計口徑 | 物件、期間、單位、樣本、分母和計算方法 | 只有百分比或「顯著提升」 |
| 適用範圍 | 能支援的地域、物件、流程和決定 | 預設外推到全部企業 |
| 限制 | 不能支援什麼、缺什麼、是否未經獨立審計 | 只寫結論不寫邊界 |
| 衝突 | 與其他證據的差異、可能原因和處理動作 | 直接平均不同定義的數字 |
| 狀態 | verified、limited、editor-reviewed、pending 或 stale | 用模糊的「可信」代替釋出狀態 |

白話解釋：你填證據卡最容易漏的是「限制」和「狀態」。限制寫清這張卡不能撐什麼，狀態寫清它是已核驗還是待核；你別用「可信」這種虛詞糊弄，釋出門認的是 verified、limited 這些硬狀態。

來源按原始性和責任邊界使用：監管統計、正式披露和獲授權一手記錄優先支撐事實；完整方法的獨立研究可支撐限定範圍結論；媒體、合作伙伴材料和專家解讀用於補充；搜尋摘要、轉載和社交媒體只用於發現線索。來源數量不能代替質量和口徑一致性。

人機協作採用七步流程：

1. **立題**：明確讀者要作的決定、截止時間和不研究的邊界。
2. **來源計劃**：為每個子問題指定優先來源、備選來源和停止條件。
3. **採集去重**：AI 可整理標題、連結、日期和關鍵詞；人確認原始來源和授權。
4. **製作證據卡**：AI 可抽取結構；人逐卡核對原文、數字、日期和限定條件。
5. **登記衝突**：比較物件、期間、單位、定義和樣本，不用平均掩蓋差異。
6. **形成論證**：把已核驗事實、基於證據的推斷、建議和待確認問題分層。
7. **審閱釋出**：由未參與撰寫的人抽檢關鍵主張，並檢查敏感資訊、版權和失效狀態。

衝突登記至少保留衝突編號、相關卡片、差異內容、可能原因、處理動作、Owner 和當前狀態。若無法在截止日前解決，報告應並列披露差異並降低結論強度。

證據卡是研究任務中的工作記錄，可以包含未釋出線索和倉庫外的授權材料；`evidence-ledger.json` 是公開藍皮書關鍵主張的釋出記錄，只儲存公開安全且符合釋出門的內容。兩者職責不同，但來源型別、狀態、適用範圍和限制必須保持一致。

白話解釋：你別把證據卡和釋出臺賬混為一一對應。證據卡是你研究中的工作本，能塞未釋出的線索；`evidence-ledger.json` 只收公開安全、過釋出門的主張。兩者欄位口徑必須一致，但你別指望工作本直接當釋出記錄用。

## 案例與證據

<span id="claim-demo-boundary-01" data-claim-id="claim-demo-boundary-01"></span>本書主張：公開演示只能證明可觀察的交付形態，不能據此推導客戶身份、實施成本、生產穩定性或業務效果。

公開案例庫中的網頁、看板和報告連結可以幫助讀者理解產物形態。 [R11](/zh-tw/qwenwork/appendix-sources#r11) 若沒有案例級外部記錄 ID、深鏈或許可範圍內的快照，它們只能留作待核驗線索，不能進入公開案例數量。

釋出前抽檢優先覆蓋全部關鍵主張、全部精確數字和全部高後果結論；其他內容按風險抽樣。抽檢人需要在可接受時間內開啟來源、定位原文並複述口徑，否則主張應降級、補證或移出釋出內容。

白話解釋：你記這條邊界——公開演示只證明「長得出來」，證明不了「誰用的、花多少、穩不穩、效果好不好」。案例庫連結沒案例級記錄 ID 的，你只能當線索，別算進公開案例數，也別寫成客戶背書。

## 企業行動

你為一個正在進行的研究任務建立證據工作臺：

1. 讓業務負責人確認決定、問題樹和不研究範圍。
2. 讓研究者按九欄位製作證據卡，不直接從搜尋結果寫結論。
3. 讓資料或專業 Owner 複核口徑、授權和高後果解釋。
4. 建立衝突登記，指定處理人和截止時間。
5. 釋出前由獨立複核者抽檢關鍵主張，並把公開使用的主張同步到釋出臺賬。

可複製的研究呼叫方式放在 [提示詞附錄](/zh-tw/qwenwork/appendix-templates#研究证据链模板)，附錄只呼叫本章欄位，不重新定義證據卡。

停止訊號包括：關鍵數字沒有原文或口徑；來源需要登入卻沒有資料責任人；不同定義被直接比較；高後果結論無人複核；內部或客戶材料沒有公開授權；主張狀態與正文措辭不一致。

白話解釋：你建證據工作臺從決定開始，別從搜尋開始。業務負責人確認決定和問題樹，研究者按九欄位制卡，Owner 複核口徑，獨立人抽檢關鍵主張——任一個停止訊號出現，你就停發補證，別帶病發布。

## 邊界與下一步

研究整理可以由 AI 加速，但法規解釋、投資判斷、醫學、法律和其他高後果結論必須由具備相應職責或資質的人複核。證據卡完整也不保證結論正確，它只讓錯誤更容易被發現和追責。

本章定義研究證據方法，不決定哪些公開案例可以釋出。你要把案例送進藍皮書，還需滿足獨立的來源定位和公開計數門檻。

## 術語翻成人話

| 術語 | 人話 |
|---|---|
| 問題樹 | 把「要不要做」這種大問題，拆成一串能拿證據回答的小問題的框架 |
| 證據卡 | 九欄位的小卡片，你每查到一條主張就記一張：來源、口徑、限制寫清楚 |
| 衝突登記 | 來源互相打架時，你把差異、原因和處理動作記下來的記錄，不擅用平均掩蓋 |
| 來源型別 | 資料是誰產的：官方產品、監管統計、一手披露、客戶授權、獨立研究等 |
| 狀態 | 這條主張的釋出狀態：已核驗 verified、受限 limited、編輯審過、待核 pending、過期 stale |
| 釋出臺賬 | `evidence-ledger.json`，只收公開安全、過釋出門的主張，是你對外發的賬本 |
| 不研究範圍 | 你事先寫清「這次不碰什麼」，避免研究無限攤開、超出授權 |

## 常見問題

**你該怎麼防止搜尋結果帶著結論跑？**
你別先搜後寫。先把讀者要作的決定拆成問題樹，給每枝指定優先來源、備選來源和停止條件，再開搜；搜來的材料按問題樹歸位，哪篇順手寫哪篇的毛病就治住了。

**證據卡九欄位裡你最容易漏填哪兩個？**
你最容易漏「限制」和「狀態」。限制寫清這張卡不能撐什麼，狀態寫清是已核驗還是待核；你別用「可信」這種虛詞，釋出門只認 verified、limited 這些硬狀態。

**兩個來源數字口徑不一樣，你能直接取平均嗎？**
不能。你遇到衝突就登進衝突登記，寫清差異、可能原因和處理動作；截止日前解決不了就並列披露並降低結論強度，絕不用平均數把真實差異抹掉。

**公開演示或案例庫連結，你能當成客戶效果證據嗎？**
不能。公開演示只證明交付形態長得出來，證明不了客戶身份、成本、穩定性或效果；沒案例級記錄 ID 的連結你只能當待核驗線索，別寫進公開案例數，也別當背書。

**釋出前你該抽檢到什麼程度才算放心？**
你優先全覆蓋關鍵主張、精確數字和高後果結論，其餘按風險抽樣；抽檢人要在可接受時間內開啟來源、定位原文、複述口徑，做不到的主張就降級、補證或移出，別帶病發布。

## 怎麼讀案例

先看案例原來的麻煩，再看最後得到的產物；接著核對輸入、複用步驟和驗收條件，最後再看客戶陳述、待核驗項和許可權邊界。具名案例中的結果是客戶材料中的陳述，32 個場景圖譜是待核驗公開場景線索，二者都不能替代你自己的基線和人工判斷。

## 如何複用

1. 用自己的資料、規則、素材、許可權和驗收口徑替換案例輸入，不直接複製示例內容。
2. 先做低風險草稿或只讀分析，記錄人工修改、異常和返工，再決定是否擴大範圍。
3. 客戶材料中的結果不能直接照搬；產品、品牌、HR、財務或其他業務負責人應按場景人工確認最終結論和對外動作。

## 為什麼重要

案例名稱看起來具體，不等於來源可以逐條複核。R11 的訪客頁能展示候選名稱和標籤，但只暴露集合級的 `sheetId=hERWDMS`、`viewId=HdnvUtk` 以及集合級 Wiki 定位；卡片點擊後 URL 不變，訪客也不能通過「源資料」獲得案例級記錄 ID、卡片深鏈或穩定 URL。

這一區別決定了案例能否被引用、糾錯和長期維護。若讀者無法從正文回到某條原始記錄，就無法確認名稱與標籤是否屬於同一條記錄，也無法判斷連結失效、內容更新或歸屬變化。因此，集合級可見性只能產生待核驗線索，不能直接形成公開案例成員。

## 釋出門與核驗方法

公開案例採用逐條釋出門，不按集合頁可見數量計算：

| 釋出門 | 通過條件 | 未通過時的處理 |
|---|---|---|
| 案例身份 | 有案例級外部記錄 ID，且不使用本書自建 ID 冒充外部 ID | 保持 pending |
| 來源定位 | 有案例級穩定深鏈，或在許可範圍內儲存公開快照及內容雜湊 | 不進入公開計數 |
| 內容對應 | 名稱、標籤、來源定位和示例產物能夠穩定對應到同一條記錄 | 記錄衝突並繼續補證 |
| 釋出邊界 | 不包含未經許可的身份、客戶結果或敏感資訊 | 去標識化或停止釋出 |
| 複核記錄 | 儲存核驗日期、狀態、侷限和責任角色 | 不建立代表案例卡 |

結構化口徑以 [案例來源對映](/zh-tw/qwenwork/appendix-case-source-map) 為準：只有 `included_in_public_count` 為 `true` 的條目才進入公開數量和成員清單。證據卡、來源優先順序與衝突處理沿用 [研究與證據鏈](/zh-tw/qwenwork/ch08-research-evidence-chain)，不在本章另建一套判斷標準。

## 企業行動

團隊準備公開一個候選案例時，按以下順序補證：

1. 由案例證據複核者取得案例級外部記錄 ID 和穩定來源定位。
2. 逐項核對原始名稱、原始標籤、來源記錄與示例產物的對應關係。
3. 記錄訪問日期、證據狀態、適用範圍和不能支援的結論；有衝突時先降級。
4. 只有在許可明確時才製作公開快照，並同時登記內容雜湊；沒有許可時不建立快照。
5. 複核公開內容中的身份、結果、敏感資訊和傳播文案，再把結構化狀態改為可釋出。
6. 重新生成附錄並執行內容校驗，讓正文計數、成員清單和結構化資料保持一致。

## 邊界與下一步

本章是截至 2026-08-01 的內容快照，不對 R11 集合頁之外的內部記錄作推斷，也不把無法穩定定位的卡片內容轉錄為公開事實。公開數量會隨補證、失效或撤回而變化，每次釋出都必須重新執行同一發布門。

下一步不是擴寫候選故事，而是逐條取得可複核的案例級定位、確認公開許可並記錄侷限。在此之前，讀者可以藉助待核驗線索理解可能的任務方向，但不能把它們引用為已核驗案例。

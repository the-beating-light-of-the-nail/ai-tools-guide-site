# 可複用資產：Skill（技能）、連接器與專家套件

## 30 秒結論

<span id="claim-skill-asset-boundary-01" data-claim-id="claim-skill-asset-boundary-01"></span>本書將 Skill 定義為封裝可重複方法和工具步驟的版本化資產；它解決"這件事按什麼步驟做"，不自動取得資料許可權，也不替代專業驗收。

- 連接器規定經授權的資料和動作邊界，不承載完整業務方法。
- 專家套件組合多個已釋出工作流和崗位標準，不是若干提示詞的打包。
- 三類資產都必須有負責維護和確認這套資產的人（Owner）、版本、輸入輸出、測試樣本、許可權說明和釋出門。

## 你可能遇到的場景

你每週都要按同一套規則整理經營覆盤，常用資料來自專案臺賬，結果還要交給負責人確認。輸入例子是「本週臺賬、上週模板、異常規則和待辦草稿位置」。這時可以把可重複使用的一套做法（工作流）整理出來，把能把資料送到另一個工具的授權通道（連接器）和組合好的任務包（專家套件）分開管理。

## 最後會得到什麼

最終產物是一份可複用資產登記包，結構為：

1. 方法資產：步驟、判斷規則、輸入輸出和版本；
2. 授權通道：系統物件、讀寫範圍、憑證歸屬、有效期和動作確認；
3. 任務包：已通過驗收的工作流、崗位標準和專業 Owner；
4. 測試與釋出記錄：正常、缺失、衝突、越權樣本，以及上一穩定版本。

## 照著做

1. 先把一次成功任務拆成可重複步驟、判斷規則和交付格式，標為 Skill（技能）候選，不把個人提示詞直接共享。
2. 再列出每個資料來源和動作，單獨申請最小必要的連接器授權；連線成功不代表自動擁有完整讀寫許可權。
3. **中間檢查點：**讓工作流 Owner、系統或資料 Owner、專業品質 Owner 分別確認方法、許可權和責任邊界。
4. 用正常、缺失、衝突和越權輸入測試；只有通過釋出門的資產才能組合進專家套件或團隊流程。

## 案例參考

可先看[品勝電子：競品調研與產品物料製作](/zh-tw/qwenwork/case-pisen)，把它當成「方法步驟」和「資料授權」需要分開的例子；案例本身不能證明連接器已有許可權或可以直接複用。

## 做完檢查

逐項核對資產登記包：必須能指出當前版本、最小許可權、四類測試樣本、Owner 和上一穩定版本；缺一項就只能個人使用或受控試點，不能釋出。

## 需要注意

如果連接器失效、許可權超範圍或測試失敗，保留原始資料和失敗版本，停止正式寫入或外發，回到上一穩定版本；改由人工提供輸入或做只讀分析，並由系統 Owner 和專業 Owner 確認後再恢復。

## 為什麼重要

團隊常把提示詞、賬號連線和崗位知識混在一個「智慧助手」中。出現錯誤時，無法判斷應該改方法、收緊授權，還是更新專業標準；共享時也容易把個人許可權和未驗證步驟一併擴散。

清晰的資產邊界讓企業分別管理內容品質、系統許可權和崗位責任。它也決定複用是否可審計：誰核准了哪個版本，使用了哪些測試樣本，能訪問什麼資料，失敗後回到哪裡。

## 方法或模型

| 資產 | 規範定義 | 適用條件 | 主要 Owner |
|---|---|---|---|
| Skill | 封裝可重複方法、工具步驟、判斷規則和交付格式 | 同類任務輸入穩定，步驟可測試，失敗可識別 | 工作流 Owner |
| 連接器 | 提供經授權的資料讀取或動作呼叫邊界 | 系統物件、賬號、許可權和讀寫範圍明確 | 系統 Owner、資料 Owner |
| 專家套件 | 組合多個已釋出工作流、崗位知識和專業標準 | 崗位任務鏈穩定，組成資產已通過階段門 | 崗位負責人、專業品質 Owner |

每項資產都用同一釋出合同登記：

| 欄位 | 必填內容 | 釋出前證據 |
|---|---|---|
| Owner | 對結果、許可權或專業標準負責的具體角色 | 責任確認和升級聯絡人 |
| 版本 | 版本號、變更內容、相容範圍和回退版本 | 變更記錄、可恢復的上一版本 |
| 輸入輸出 | 輸入欄位、可信範圍、輸出格式和儲存位置 | 合法樣本、缺失樣本、產物示例 |
| 測試樣本 | 正常、邊界、衝突和失敗樣本 | 測試記錄、人工修改和未通過原因 |
| 許可權 | 資料物件、讀寫範圍、憑證歸屬和有效期 | 授權記錄、最小許可權檢查 |
| 釋出門 | 當前階段、通過條件、停止條件和核准人 | 階段評審記錄和釋出決定 |

<span id="claim-connector-authorization-01" data-claim-id="claim-connector-authorization-01"></span>連接器的產品作用是連線外部資料或工具；實際可訪問的資料和可執行動作受當前授權與可用範圍約束，不能因"已連線"推定擁有完整讀寫許可權。

<span id="claim-expert-kit-release-01" data-claim-id="claim-expert-kit-release-01"></span>本書建議：專家套件只能組合已經通過崗位階段門的工作流，不能用套件名稱替代組成資產的測試、許可權和責任記錄。

複用升級遵循第 10 章的階段門，本文不復制樣本數和閾值：個人模板完成 0–30 天階段門後才成為候選資產；團隊工作流完成 31–60 天階段門後才可釋出為團隊 Skill；崗位專家套件只能組合通過 61–90 天階段門的工作流。

## 案例與證據

官方幫助中心分別提供 Skill 和連接器說明。 [R8](/zh-tw/qwenwork/appendix-sources#r8) [R4](/zh-tw/qwenwork/appendix-sources#r4) 本章採用其公開產品語境，但「資產釋出合同」和階段門對映是社群治理方法，不代表官方產品承諾。

一個周度經營覆盤 Skill 可以固定輸入檢查、資料勾稽、異常識別和產物格式；連接器只負責在授權範圍內讀取專案臺賬或建立待辦草稿；專家套件再把經營覆盤、風險升級和管理層彙報等已釋出工作流組合起來。任一連接器失效時，方法資產仍應能降級到人工提供輸入，而不是靜默生成不完整結論。

## 企業行動

對現有共享提示詞做一次資產拆分：

1. 把可重複步驟、判斷規則和交付格式整理為 Skill 候選。
2. 單獨列出每個資料來源和動作，區分讀取、草稿寫入和正式執行。
3. 指定工作流 Owner、系統 Owner 和專業品質 Owner。
4. 為正常、缺失、衝突和越權輸入各準備測試樣本。
5. 登記當前階段門；未通過時只限個人或受控試點使用。

停止釋出的訊號包括：沒有具體 Owner；輸入輸出依賴口頭約定；測試只覆蓋成功樣本；連接器申請超出任務所需許可權；無法回到上一穩定版本；專家套件包含尚未獨立驗收的工作流。

## 邊界與下一步

一個好的提示詞可以是 Skill 的素材，但不是完整的團隊資產。連接器可用也不意味著業務動作已獲核准；專家套件中的專業判斷仍由具備相應職責的人承擔。

本章定義資產邊界和釋出關係，不定義自動化執行中的接管與恢復。資產進入定時或無人值守執行前，還需要獨立的執行控制。

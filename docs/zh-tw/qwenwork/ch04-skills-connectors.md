# 可複用資產：Skill（技能）、連接器與專家套件

## 白話導讀

這一章幫你把團隊裡混在一起的三樣東西拆開：做法、權限、崗位包。你每週按同一套規則做經營復盤時，常把提示詞、賬號連線和崗位知識塞進同一個「智慧助手」，一齣錯你就分不清該改方法、收權限還是補標準。本章把 Skill（做法）、連接器（授權通道）、專家套件（崗位任務包）分開管，各自有 Owner、版本和測試樣本。你讀完就知道：哪類資產你能共享、哪類碰了權限就得單獨審。

## 30 秒結論

<span id="claim-skill-asset-boundary-01" data-claim-id="claim-skill-asset-boundary-01"></span>本書將 Skill 定義為封裝可重複方法和工具步驟的版本化資產；它解決“這件事按什麼步驟做”，不自動取得資料權限，也不替代專業驗收。

白話解釋：這條邊界為什麼這麼定？你容易以為有了 Skill 就能自動讀資料，其實 Skill 只管步驟，權限要你另外申請。你混在一起，共享時就會把個人權限和未驗證步驟一併擴散出去。

- 連接器規定經授權的資料和動作邊界，不承載完整業務方法。
- 專家套件組合多個已釋出工作流和崗位標準，不是若干提示詞的打包。
- 三類資產都必須有負責維護和確認這套資產的人（Owner）、版本、輸入輸出、測試樣本、權限說明和釋出門。

## 你可能遇到的場景

你每週都要按同一套規則整理經營復盤，常用資料來自專案臺賬，結果還要交給負責人確認。輸入例子是“本週臺賬、上週模板、異常規則和待辦草稿位置”。這時可以把可重複使用的一套做法（工作流）整理出來，把能把資料送到另一個工具的授權通道（連接器）和組合好的任務包（專家套件）分開管理。

白話解釋：你從這裡開始分——做法是做法，通道是通道，包是包。把三者分開，哪天連接器失效，你方法資產還能降級到人工喂資料，不會靜默產出半截結論。

## 你會拿到什麼

最終產物是一份可複用資產登記包，結構為：

1. 方法資產：步驟、判斷規則、輸入輸出和版本；
2. 授權通道：系統物件、讀寫範圍、憑證歸屬、有效期和動作確認；
3. 任務包：已通過驗收的工作流、崗位標準和專業 Owner；
4. 測試與釋出記錄：正常、缺失、衝突、越權樣本，以及上一穩定版本。

## 照著做

1. 先把一次成功任務拆成可重複步驟、判斷規則和交付格式，標為 Skill（技能）候選，不把個人提示詞直接共享。
2. 再列出每個資料來源和動作，單獨申請最小必要的連接器授權；連線成功不代表自動擁有完整讀寫權限。
3. 中間檢查點：讓工作流 Owner、系統或資料 Owner、專業質量 Owner 分別確認方法、權限和責任邊界。
4. 用正常、缺失、衝突和越權輸入測試；只有通過釋出門的資產才能組合進專家套件或團隊流程。

白話解釋：第 2 步最容易被你忽略——「連上了」不等於「能讀寫」。連接器只給授權範圍內的邊界，你別因為顯示已連線就預設擁有全部權限，越權申請是釋出停止訊號。

## 案例參考

可先看[品勝電子：競品調研與產品物料製作](/zh-tw/qwenwork/case-pisen)，你把它當成“方法步驟”和“資料授權”需要分開的例子；案例本身不能證明連接器已有權限或可以直接複用。

## 做完檢查

逐項核對資產登記包：必須能指出當前版本、最小權限、四類測試樣本、Owner 和上一穩定版本；缺一項就只能個人使用或受控試點，不能釋出。

白話解釋：你這條檢查卡的是「能不能審計」。指不出當前版本、最小權限、四類樣本和 Owner，資產就只能你個人用，不能往團隊發——因為出錯沒人知道回到哪一版、誰負責。

## 需要注意

如果連接器失效、權限超範圍或測試失敗，保留原始資料和失敗版本，停止正式寫入或外發，回到上一穩定版本；改由人工提供輸入或做只讀分析，並由系統 Owner 和專業 Owner 確認後再恢復。

白話解釋：你遇連接器失效、權限超範圍或測試失敗時，先停正式寫入或外發、留原始資料和失敗版本，回到上一穩定版。你改人工喂輸入或只讀分析，讓系統 Owner 和專業 Owner 確認後再恢復。

## 為什麼重要

團隊常把提示詞、賬號連線和崗位知識混在一個“智慧助手”中。出現錯誤時，你無法判斷應該改方法、收緊授權，還是更新專業標準；共享時你也容易把個人權限和未驗證步驟一併擴散。

清晰的資產邊界讓企業分別管理內容質量、系統權限和崗位責任。它也決定複用是否可審計：誰批准了哪個版本，使用了哪些測試樣本，能訪問什麼資料，失敗後回到哪裡。

## 方法或模型

| 資產 | 規範定義 | 適用條件 | 主要 Owner |
|---|---|---|---|
| Skill | 封裝可重複方法、工具步驟、判斷規則和交付格式 | 同類任務輸入穩定，步驟可測試，失敗可識別 | 工作流 Owner |
| 連接器 | 提供經授權的資料讀取或動作呼叫邊界 | 系統物件、賬號、權限和讀寫範圍明確 | 系統 Owner、資料 Owner |
| 專家套件 | 組合多個已釋出工作流、崗位知識和專業標準 | 崗位任務鏈穩定，組成資產已通過階段門 | 崗位負責人、專業質量 Owner |

白話解釋：你記這張表就看「Owner 那列」——Skill 歸工作流 Owner，連接器歸系統/資料 Owner，專家套件歸崗位和專業質量 Owner。三者責任人不同，正是為了分開管方法、權限和標準。

每項資產都用同一釋出合同登記：

| 欄位 | 必填內容 | 釋出前證據 |
|---|---|---|
| Owner | 對結果、權限或專業標準負責的具體角色 | 責任確認和升級聯絡人 |
| 版本 | 版本號、變更內容、相容範圍和回退版本 | 變更記錄、可恢復的上一版本 |
| 輸入輸出 | 輸入欄位、可信範圍、輸出格式和儲存位置 | 合法樣本、缺失樣本、產物示例 |
| 測試樣本 | 正常、邊界、衝突和失敗樣本 | 測試記錄、人工修改和未通過原因 |
| 權限 | 資料物件、讀寫範圍、憑證歸屬和有效期 | 授權記錄、最小權限檢查 |
| 釋出門 | 當前階段、通過條件、停止條件和批准人 | 階段評審記錄和釋出決定 |

<span id="claim-connector-authorization-01" data-claim-id="claim-connector-authorization-01"></span>連接器的產品作用是連線外部資料或工具；實際可訪問的資料和可執行動作受當前授權與可用範圍約束，不能因“已連線”推定擁有完整讀寫權限。

<span id="claim-expert-kit-release-01" data-claim-id="claim-expert-kit-release-01"></span>本書建議：專家套件只能組合已經通過崗位階段門的工作流，不能用套件名稱替代組成資產的測試、權限和責任記錄。

複用升級遵循第 10 章的階段門，本文不復制樣本數和閾值：個人模板完成 0–30 天階段門後才成為候選資產；團隊工作流完成 31–60 天階段門後才可釋出為團隊 Skill；崗位專家套件只能組合通過 61–90 天階段門的工作流。

白話解釋：你升級複用別跳級。個人提示詞先跑滿 0–30 天才算候選，團隊工作流 31–60 天才發 Skill，專家套件只能裝通過 61–90 天階段門的工作流——套件名字不能替組成資產背書。

## 案例與證據

官方幫助中心分別提供 Skill 和連接器說明。 [R8](/zh-tw/qwenwork/appendix-sources#r8) [R4](/zh-tw/qwenwork/appendix-sources#r4) 本章採用其公開產品語境，但“資產釋出合同”和階段門對映是社群治理方法，不代表官方產品承諾。

一個周度經營復盤 Skill 可以固定輸入檢查、資料勾稽、異常識別和產物格式；連接器只負責在授權範圍內讀取專案臺賬或建立待辦草稿；專家套件再把經營復盤、風險升級和管理層彙報等已釋出工作流組合起來。任一連接器失效時，方法資產仍應能降級到人工提供輸入，而不是靜默生成不完整結論。

## 企業行動

對現有共享提示詞做一次資產拆分：

1. 把可重複步驟、判斷規則和交付格式整理為 Skill 候選。
2. 單獨列出每個資料來源和動作，區分讀取、草稿寫入和正式執行。
3. 指定工作流 Owner、系統 Owner 和專業質量 Owner。
4. 為正常、缺失、衝突和越權輸入各準備測試樣本。
5. 登記當前階段門；未通過時只限個人或受控試點使用。

停止釋出的訊號包括：沒有具體 Owner；輸入輸出依賴口頭約定；測試只覆蓋成功樣本；連接器申請超出任務所需權限；無法回到上一穩定版本；專家套件包含尚未獨立驗收的工作流。

白話解釋：這套拆分對你意味著——你先別急著共享「那個好用的助手」。你先把步驟、連線、崗位包拆開，各指一位 Owner、各備四類測試樣本；出現「沒 Owner」「只測成功樣本」「權限超標」任一訊號，就停發。

## 邊界與下一步

你手上有個好提示詞，它可以是 Skill 的素材，但不是完整的團隊資產。連接器可用也不意味著業務動作已獲批准；專家套件中的專業判斷仍由具備相應職責的人承擔。

本章定義資產邊界和釋出關係，不定義自動化執行中的接管與恢復。資產進入定時或無人值守執行前，還需要獨立的執行控制。

## 術語翻成人話

| 術語 | 人話 |
|---|---|
| Skill（技能） | 把你可重複的做法、步驟、判斷規則封裝成版本化資產，只管「怎麼做」 |
| 連接器 | 經授權把你的資料送到另一工具、或呼叫動作的通道，只給授權邊界 |
| 專家套件 | 把多個已釋出工作流組合成你的崗位任務包，不是提示詞打包 |
| Owner | 對某資產結果真正負責的具體人，你得指一位，不能寫「團隊」 |
| 釋出門 | 你資產從候選到釋出的階段關卡，過不了的只能個人或受控試點 |
| 階段門 | 你按天數劃的升級關卡：0–30、31–60、61–90 天對應不同資產等級 |

## 常見問題

**你手上有個好用的提示詞，能直接當團隊 Skill 發嗎？**
不能。提示詞只是 Skill 的素材，不是完整資產。你先把它拆成步驟、判斷規則和交付格式，你跑滿階段門、指定 Owner、備齊測試樣本，才能釋出。

**連接器顯示「已連線」，你是不是就有權讀寫了？**
不是。已連線只說明通道通了，實際能讀能寫受你當前授權和範圍約束。你別預設擁有完整權限，越權申請會觸發停止釋出。

**專家套件能不能用名字替組成資產背書？**
不能。你只能組合已通過崗位階段門的工作流，組成資產的測試、權限、責任記錄一個都不能少；你別用套件名替它們背書。

**做資產登記時，你必查哪幾項？**
當前版本、最小權限、四類測試樣本（正常/缺失/衝突/越權）、Owner、上一穩定版本。你缺一項就只能個人用或受控試點，不能釋出。

**連接器失效了，你的方法資產會直接崩嗎？**
不該。設計上方法資產應能降級到人工喂輸入，而不是靜默產出半截結論。你驗收時要確認它有這條降級路徑。

# 辦公交付：檔案、資料、彙報與網頁

## 白話導讀

這一章幫你把「檔案、表格、彙報、網頁」四類辦公活兒，統一成一張能驗收的任務卡。你帶團隊做週報、整理資料時常碰見：AI 生成一份 Word 或 PPT，格式好看，數字卻復算不出、連結點不開、合同被整理成法律結論。本章給你六欄位工作流——輸入、處理、產物、驗收、風險、人工確認——你照它做，發出去之前就能抓住「數字對不對、版本清不清、誰拍板」三件事。你讀完就不會再被一份「能下載的檔案」騙過去，你驗收時也知道該退給誰重做。

## 30 秒結論

<span id="claim-office-delivery-acceptance-01" data-claim-id="claim-office-delivery-acceptance-01"></span>本書建議：檔案、資料、彙報和網頁任務都按「輸入—處理—產物—驗收—風險—人工確認」設計，不能把檔案成功生成當成交付通過。

白話解釋：這條為什麼這麼定？你最容易踩的坑，就是把「檔案生成了」當成「活幹完了」。一份 PPT 能開啟不代表數字能復算、不代表結論經過確認；你驗收時得看六欄位齊不齊，而不是看檔案能不能下載。

- 檔案優先檢查事實、結構、版本和可編輯性。
- 資料與彙報必須保留口徑、勾稽和結論證據。
- 網頁釋出及高後果檔案使用必須由責任人明確確認。

## 你可能遇到的場景

你可能要把會議材料整理成檔案、把一批明細做成表格、把經營資料做成彙報，或把活動內容做成網頁。輸入例子可以是「會議紀要和模板」「6 月原始表和欄位字典」「已確認的經營指標」「內容清單、品牌規範和授權素材」。四類任務你都先明確輸入，再處理和驗收，別拿到一句話就開跑。

## 你會拿到什麼

你照四類任務備好交付包，它最少包含這些：

1. 檔案：可編輯正文、版本說明、待確認清單和來源位置；
2. 表格：可編輯明細、彙總、公式或查詢記錄、異常清單和口徑說明；
3. 彙報：可編輯簡報、講述提綱、資料底稿和待決事項；
4. 網頁：可預覽頁面、原始檔、素材清單、測試記錄和釋出變更清單。

## 照著做

1. 你先別在原檔案上試跑：把輸入、處理方式、產物格式、驗收條件和人工確認人寫成任務卡，原件另存。
2. 按檔案、表格、彙報或網頁選擇處理步驟：保留來源、版本、公式、連結和必要的修訂記錄。
3. **中間檢查點：**在生成最終檔案前，你抽查事實、數字、連結、素材授權和格式；有疑問的項進入待確認清單。
4. 生成可編輯或可預覽產物，完成自動檢查後，由負責這項結果的人（Owner）、資料 Owner、業務負責人或釋出責任人確認下一動作。

## 案例參考

可先看[品勝電子：競品調研與產品物料製作](/zh-tw/qwenwork/case-pisen)，觀察研究資料如何轉成產品物料；你也可以檢視[千問辦公公開案例庫：32 個場景圖譜](/zh-tw/qwenwork/ch09-public-case-atlas)尋找表格、網頁或彙報的相近任務。你拿這些案例當參考即可，案例頁面的證據狀態和授權邊界仍需你單獨核對，別直接當成你自己的驗收結論。

## 做完檢查

檔案至少抽查 3 個事實和版本；表格至少復算 1 個彙總並核對期間和單位；彙報至少把 1 個圖表回溯到底稿；網頁至少檢查 1 個桌面端、1 個移動端和全部關鍵連結。任一檢查失敗就不釋出。

白話解釋：你別嫌抽查麻煩。檔案挑 3 個事實回來源、表格復算 1 個彙總、彙報回溯 1 張圖、網頁跑一遍兩端——任一項過不去就壓住不發，你發出去再發現錯，代價比現在大得多。

## 需要注意

發現版本不明、數字不能復算、素材未授權、合同需要專業判斷或網頁可能洩露敏感資訊時，保留原件和失敗產物，停止外發或釋出，回到上一穩定版本；改成人工整理或只讀分析，由對應專業 Owner 確認後再處理。

白話解釋：你遇到這些紅燈，第一反應就是「停、留原件、別發」。版本說不清、數字復算不出、素材沒授權、合同要法務判斷、網頁可能洩密——任一條出現，你都先退回上一穩定版，等專業 Owner 確認再動。

## 為什麼重要

Office 檔案和網頁容易製造「已經完成」的視覺錯覺：格式完整，但數字無法復算；頁面漂亮，但連結失效；合同條款被整理，卻被誤當成法律結論。業務負責人真正需要的是可使用且可承擔後果的產物，而不是一個可下載檔案。

統一工作流欄位讓不同工具和崗位使用同一驗收語言。你帶團隊時能用同一套話問「輸入齊不齊、口徑對不對、誰確認」，也能比較人工與 AI 輔助版本的返工、錯誤和交付時長。

## 方法或模型

### 檔案工作流

| 欄位 | 規範內容 |
|---|---|
| 輸入 | 原始檔案、會議材料、模板、術語表、讀者和版本範圍 |
| 處理 | 識別事實、觀點、決定和待確認項；按模板重組；保留修訂痕跡 |
| 產物 | 可編輯檔案、版本說明、待確認清單和來源位置 |
| 驗收 | 結構回答原始任務；事實可查；版本清晰；標題、表格和引用可繼續編輯 |
| 風險 | 人名、金額、日期誤寫；舊版本覆蓋；敏感內容外洩；專業結論越界 |
| 人工確認 | 內容複核者批准事實與表達；業務負責人決定外發或進入下一流程 |

白話解釋：檔案這類產物，你最該盯的是「事實、版本、可編輯」。人名金額日期寫錯、舊版覆蓋了新版、敏感內容漏出去，都是高發風險；你讓內容複核者批事實、業務負責人拍板外發，別讓 AI 替你做這兩個決定。

會議紀要屬於檔案工作流：行動項必須有負責人、截止時間、交付物和驗收標準。合同屬於高後果檔案示例；AI 可以定位條款、比較版本和整理協商清單，不能代替法務判斷或給出最終法律意見。

### 資料工作流

| 欄位 | 規範內容 |
|---|---|
| 輸入 | 原始表、欄位字典、資料期間、單位、主鍵、版本和授權範圍 |
| 處理 | 保留原件；檢查缺失、重複和異常；鎖定口徑；清洗、計算並勾稽 |
| 產物 | 可編輯明細、彙總、圖表、口徑說明、公式或查詢記錄、異常清單 |
| 驗收 | 期間與單位明確；口徑一致；明細和彙總勾稽；關鍵結果可復算 |
| 風險 | 補造缺失值、混用期間或單位、主鍵錯配、覆蓋原表、越權使用資料 |
| 人工確認 | 資料 Owner 確認口徑和範圍；內容複核者抽查公式、樣本和結論 |

白話解釋：資料這類產物，你最該盯的是「口徑和復算」。期間、單位、主鍵一混，彙總就錯；你讓資料 Owner 確認口徑、複核者抽公式，關鍵結果必須能復算回去，不能只看圖表漂亮。

### 彙報工作流

| 欄位 | 規範內容 |
|---|---|
| 輸入 | 決策問題、受眾、資料底稿、事實來源、時間限制和既有模板 |
| 處理 | 先寫結論和證據關係；確定講述順序；一頁一個問題；標註單位與來源 |
| 產物 | 可編輯簡報、講述提綱、資料底稿和待決事項 |
| 驗收 | 結論有證據；適合受眾；講述順序支援決定；圖表與底稿一致 |
| 風險 | 用視覺強調替代證據、隱藏不確定性、圖表截斷、對外承諾未經批准 |
| 人工確認 | 業務負責人確認結論與行動；內容複核者核對數字、來源和表達 |

白話解釋：彙報這類產物，你最該盯的是「結論有沒有證據、對外承諾批沒批」。你別用大字號和配色掩蓋證據缺口，也別把沒批准的承諾寫進 PPT；業務負責人確認結論、複核者核對數字，兩道都要過。

### 網頁工作流

| 欄位 | 規範內容 |
|---|---|
| 輸入 | 內容清單、資訊架構、品牌規範、素材授權、互動需求和釋出環境 |
| 處理 | 結構設計、內容與資料繫結、桌面和移動端測試、連結與表單檢查 |
| 產物 | 可預覽網頁、原始檔、素材清單、測試記錄和釋出變更清單 |
| 驗收 | 內容正確；連結可達；移動端可用；具備基本可訪問性；無敏感資訊洩露 |
| 風險 | 未授權素材、表單誤收集資料、金鑰暴露、失效連結、未經批准公開發布 |
| 人工確認 | 內容 Owner 批准文案與素材；釋出責任人確認域名、範圍和回退方案 |

白話解釋：網頁這類產物，你最該盯的是「素材授權和釋出權限」。未授權圖、誤收資料的表單、洩露的金鑰、失效連結，任何一條都夠你撤下重做；釋出前由內容 Owner 批素材、釋出責任人確認域名和回退，別讓網頁自己跑上線。

完整呼叫模板集中在 [提示詞附錄](/zh-tw/qwenwork/appendix-templates)，本章只保留工作流和驗收規範。

## 案例與證據

官方產品簡介列出 Word、Excel、PPT、網頁等產物形態。 [R3](/zh-tw/qwenwork/appendix-sources#r3) 產物型別是產品事實；四條工作流、驗收項和人審邊界屬於社群實踐，不能據此推斷具體任務的一次通過率。

例如經營資料彙報應保留一條完整證據鏈：原始明細、清洗說明、彙總勾稽、圖表資料和演示結論。若演示中的數字無法回到明細或公式，即使 PPT 已生成，也不得通過交付驗收。

白話解釋：你拿經營彙報當例子記這條——PPT 生成了不等於交付過了。數字回不到明細、公式對不上，你只能標草稿，不能拿「已經做完了」去開會。

## 企業行動

你從當前返工最多的一類辦公產物開始：

1. 用六個欄位重寫現有流程，補齊缺失的人工確認。
2. 選取真實的通過、退回和邊界樣本，記錄人工基線。
3. 要求 AI 先生成中間產物和校驗記錄，不直接外發或釋出。
4. 由內容複核者按本章驗收項逐項退回或通過。
5. 記錄返工原因，只固化連續穩定的步驟。

停止訊號包括：無法確認輸入版本；關鍵數字不能復算；合同或專業材料缺少持責人員；檔案不可編輯；網頁存在失效連結或敏感資訊；釋出物件、域名或回退方式不明確。

白話解釋：你挑返工最多的那類先動手，比挑好看的先做有用。把六個欄位補上、留好人工基線，讓 AI 先出中間產物再外發；任一個停止訊號出現，你就退回，別硬發。

## 邊界與下一步

本章給出跨崗位通用的辦公交付規範，不替代財務、法務、品牌、隱私和無障礙等專業標準。你落地時應在六個欄位中追加自己組織的強制要求，但不要刪除來源、驗收和人工確認。

通用工作流需要落到具體崗位的業務問題、指標和禁做動作，才能形成可運營的場景組合。

## 術語翻成人話

| 術語 | 人話 |
|---|---|
| 六欄位工作流 | 輸入、處理、產物、驗收、風險、人工確認——你給每類辦公活兒寫的一張驗收卡 |
| 可編輯性 | 產物能在你約定工具裡接著改，關鍵結構沒被壓平成一坨文字 |
| 口徑 | 統計的期間、單位、分母和演算法；你口徑不一致，數字就不能拿來比 |
| 勾稽 | 明細加起來對得上彙總、公式對得上底稿，一環扣一環能追回去 |
| 高後果檔案 | 合同、法務、對外承諾這類錯一處就要擔責的檔案，AI 只能整理不能拍板 |
| 人工確認 | 真要外發、釋出前的那次責任人授權，是收口那道關鍵閘 |

## 常見問題

**你該怎麼判斷一份辦公產物算不算「交付通過」？**
你不能只看檔案能不能開啟。你按六欄位逐一看：輸入版本清不清、數字能不能復算、連結通不通、誰確認外發或釋出；任一項不滿足就標草稿，別拿「生成了」當「完成了」。

**四類任務裡你最該優先管住哪類？**
你從返工最多的一類先管，通常是資料或彙報。資料盯口徑和復算，彙報盯結論證據和對外承諾；檔案盯版本和可編輯，網頁盯素材授權和釋出權限。

**合同、法務這類高後果檔案，你能讓 AI 直接出結論嗎？**
不能。AI 能定位條款、比版本、整理協商清單，但不能替法務判斷或給最終法律意見；你讓專業 Owner 確認，AI 只做整理，拍板留給人。

**網頁釋出前你要確認什麼才不會翻車？**
你確認素材都有授權、表單不會誤收資料、金鑰沒洩露、連結全可達、移動端能用，並由內容 Owner 批文案、釋出責任人確認域名和回退方案；任一項沒過就壓住。

**驗收退回後你該留下什麼記錄？**
你留下退回原因、缺哪條證據、誰確認的，以及重做後的通過結論。這些記錄是你的返工基線，下一輪才知道哪類任務該加檢查點、哪類能放心交給 AI。

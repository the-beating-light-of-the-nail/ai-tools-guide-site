# 來源清單怎麼讀才不張冠李戴？給你 R1–R15 的核驗邊界

## 白話導讀

你引用本藍皮書的產品事實或案例結論時，最怕來源說不清、邊界對不上。這份附錄把 R1–R15 全部公開來源列出來，並標了訪問日期和核驗邊界，你寫報告、做決策時照著引用就不會張冠李戴。你在什麼場景翻它、每條怎麼讀、連結失效怎麼辦，下面講清。

## 這份附錄給誰用，什麼時候該翻它

產品介面、價格、權益、模型列表、可用地區與連接器範圍更新較快，應以使用時的官方頁面為準。你引用 R2、R3、R12 裡的價格或連接器範圍時，若照搬訪問日資料，可能和當前頁面不一致。你讀到帶【訪問於】的條目，就以該日期的快照理解，落地前你再核一次官方頁。

## 每條來源怎麼讀，讀錯了會怎樣

你逐條讀來源時，先看型別：R1 是方法參考（MIT 許可），R2–R9、R12–R13 是官方頁面，R10–R11 是阿里知識庫。你若把社群知識庫當官方承諾，會高估產品能力；你若漏看【訪問於】日期，會把舊快照當現狀。每條的侷限都寫在正文裡，你引用前讀完，別隻抄標題。

## 常見問題

**你引用本藍皮書時，應該按哪條來源標註？**
按正文中方括號編號對應的 R 條目標註，例如產品簡介引 R3、連接器引 R4。你別把社群知識庫 R10、R11 當官方承諾來寫，它們只用於理解定位，實際能力以賬號實測和官方頁為準。

**你看到正文寫 R14 或 R15，該去哪裡找原文？**
R14、R15 是相容重定向，分別指向 R8（技能）和 R4（連接器），不是獨立來源。你引用時直接標 R8 或 R4，別讓編號看起來多出來兩條。

**連結打不開或頁面改版了，你怎麼辦？**
先按條目裡的【訪問於】日期理解當時快照，再開啟官方頁核當前版本。你若發現價格、權益或連接器範圍和訪問日不一致，以使用時頁面為準，並在引用處註明核對日期。

**你做案例結論時，R11 能給到你什麼、給不到什麼？**
R11 幫你核驗案例名稱、任務標籤、角色標籤和公開產物連結；它多數條目未披露客戶名稱或量化成效。你別從案例庫反推「效果資料」，沒有公開量化的，就只寫到「形態可證」這一層。

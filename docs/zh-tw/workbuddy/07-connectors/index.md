# WorkBuddy 的連接器是什麼？接上騰訊系工具讓它直接替你辦事

你用 WorkBuddy 寫完一份紀要，想順手發到騰訊檔案、或者讓它幫你建個明天的會議。可它預設碰不到這些外部服務——它待在自己的世界裡，看不見你的郵箱和日曆。連接器就是那道門：你把微信、騰訊檔案、騰訊會議這些賬號授權給它，它就能真的去發訊息、建會議、讀檔案，而不只是口頭說說。

理解連接器，你先得認識它背後的標準：**MCP**，也就是 Model Context Protocol（模型上下文協議）。這是 Anthropic 在 2024 年底推出並開源的一個開放標準協議，如今已經是 AI 領域最熱門的基礎設施之一。你把它想成 AI 世界的「USB-C 介面」就對了。

## 為什麼需要 MCP

過去，你想讓一個 AI 助手（Agent）連上外部工具（比如 GitHub、本地檔案系統、PostgreSQL 資料庫、Slack 等），開發者得為「每一個 AI 應用」和「每一個工具」都寫一套專門的對接程式碼。要是有 10 個 AI 應用和 10 個工具，就得寫 100 個介面——這是個 N × M 的整合噩夢。

有了 MCP，工具開發者只需按 MCP 標準開發一個「MCP Server」（相當於 USB-C 裝置），而任何支援 MCP 的 AI 應用（如 Cursor、各類 Agent 框架）只要內建「MCP Client」（相當於 USB-C 介面），就能**即插即用**。這就把 N × M 的複雜開發，簡化成了 N + M，你不用再為每個組合單獨寫程式碼。你作為使用者，根本不用管底層那一百個介面怎麼寫。

## MCP 的核心特點

- 統一的標準化協議（告別重複造輪子）

MCP 提供了一套通用規範（基於 JSON-RPC）。無論是讀本地檔案、查資料庫，還是調第三方 SaaS API，AI 都能通過同一套協議邏輯去理解和呼叫。這大幅降低了 Agent 開發中工具整合的門檻，讓你把精力放在核心邏輯上，而不是寫繁瑣的對接程式碼。

- 支援三大核心能力

MCP 不光讓 AI「做事」，還讓它「看資料」和「按套路出牌」，它把三種核心原語標準化了：

- **Tools（工具）**：讓你的 AI 執行操作。例如：跑一段程式碼、在 Jira 建一個任務、往資料庫寫資料。
- **Resources（資源/上下文）**：讓你的 AI 讀取外部資料。例如：拿 Git 倉庫的檔案列表、查向量資料庫裡的特定片段，作為回答的上下文。
- **Prompts（提示詞模板）**：提供預定義的互動模板，讓你或 AI 以標準化方式觸發特定複雜工作流。

- C/S 架構與高度解耦

MCP 採用客戶端-服務端（Client-Server）架構：

  - MCP Host：你用的 AI 宿主應用（如 IDE、Agent 平臺）。
  - MCP Client：Host 內部負責和 Server 保持 1:1 連線的元件。
  - MCP Server：輕量級的獨立程式，專門負責暴露特定工具或資料的能力。

你看，這三層各管一攤，互不綁架。這意味著你可以隨時換底層大模型，或隨時加新資料來源，而不用重構整個 Agent 系統。

- 本地優先與安全性（隱私友好）

MCP 支援通過本地標準輸入輸出（stdio）或本地 HTTP 通訊。這意味著你的 MCP Server 可以完全跑在本地電腦上，你的資料留在本地。敏感資料（如原生程式碼、私有資料庫內容、電商後臺資料）不用上傳到雲端第三方伺服器，AI 模型只在需要推理時取必要的上下文——你不用擔心資料被偷偷傳走。

## 新建連接器

你還想接自己的業務系統？你到連接器管理頁右上角點「自定義連接器」，按引導配置 MCP（含服務地址、鑑權方式），並留意自定義連接器的訪問範圍由你自己配置。

## 新手常見問題

**連接器、MCP、API 這幾個詞我總搞混，先記哪個？**
你先記 MCP：它是讓 AI 接工具的「USB-C 介面」標準。連接器是 WorkBuddy 已經按這個標準幫你封好的現成服務（微信、騰訊檔案等）。API 是更底層、各家自己定義的介面，MCP 在它上面蓋了扇更統一的門。

**現在能接哪些連接器？**
當前已支援 QQ 郵箱、騰訊檔案、騰訊樂享、騰訊會議、TAPD 等。你也能在管理頁點「自定義連接器」，按引導配 MCP 接更多服務。

**連接器會不會亂動我的賬號？**
它只在你授權範圍內動作，訪問範圍由你配置。你讓它建會議它就建會議，沒授權的它碰不到。第一次用你先在小事上驗證，確認它只幹了你吩咐的。

**我自己的業務系統能接嗎？**
能。你走「自定義連接器」，填服務地址和鑑權方式即可。範圍自己定，你別一次放開全部權限。

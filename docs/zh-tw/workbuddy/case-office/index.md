# Word、Excel、PPT 怎麼讓 AI 幫你做？三件套的正確開啟方式

你第一次感受到 WorkBuddy 值不值，多半就在辦公三件套上：Word 檔案、Excel 表格、PPT 彙報。這些活又碎又重複，正適合交給它幹。但很多人用不好，不是模型不會寫，而是你沒把交付標準說清。你照著這篇走，把三類產物各自的打法一次講透，省得你來回試錯。

## 共同工作流：先把任務拆成五個問題

無論你要的是哪類檔案，很多「AI 做得不好」的辦公任務，根源不是模型不會寫，而是你沒把交付標準說清楚。你先把下面五個問題想明白，再開口派活，AI 才出得了能用的東西：

| 問題 | 要說清什麼 | 示例 |
| --- | --- | --- |
| 目標 | 這份材料要幫助誰做什麼決定 | 給部門負責人看，用於判斷專案是否繼續投入 |
| 受眾 | 閱讀者是誰，懂不懂背景 | 管理層只看結論；專案組需要過程和責任人 |
| 材料 | 哪些檔案是事實來源，哪些只是參考 | `data.xlsx` 是唯一資料口徑，舊版 PPT 只參考結構 |
| 格式 | 要 Word、Excel、PPT，還是三者聯動 | 一份復盤 Word、一張風險臺賬 Excel、一份 8 頁簡報 PPT |
| 驗收 | 怎麼判斷結果可用 | 數字能回到原始檔，表格公式可重新整理，PPT 投屏不溢位 |

## 先選對 Skill：辦公任務的推薦組合

你照這張表挑 Skill，別上來就瞎試。你先看清楚每類檔案對應哪個能力，再決定用單個 Skill 還是組合拳：

| Skill | 適合處理 | 注意點 |
| --- | --- | --- |
| Word / DOCX | 建立、檢查、編輯 DOCX，標題、編號、表格、修訂 | 適合本地 docx 檔案 |
| Excel / XLSX | 讀取、清洗、寫入工作簿，公式、日期、模板保留 | 先確認資料口徑 |
| Powerpoint / PPTX | 建立、編輯、檢查 PPTX，版式、佔位符、圖表 | 適合需要可編輯 PPTX 的場景 |
| Office Document Specialist Suite | Word / Excel / PPT 綜合處理與多檔案聯動 | 複雜任務建議分步驗收 |
| wps / kdocs skill | WPS 三件套與金山雲檔案 | 通常需要 API Key |
| 騰訊檔案 | 線上 Word、Excel、幻燈片的建立與編輯 | 通常需要授權 |
| Markdown Converter | 把 PDF、Word、PPT、Excel 轉成 Markdown | 適合讀材料，不等於最終排版 |
| PPT Generator / PPT Workflow | 從主題、講稿或材料自動生成演示稿 | 生成後仍要人工審稿 |
| Excel公式生成 | 自然語言轉 Excel/WPS/Google Sheets 公式 | 公式要在樣例資料上驗證 |
| 騰訊會議 | 預約會議、獲取轉寫與 AI 紀要 | 需要會議平臺授權 |

實用搭配：你本地檔案優先 **Word / DOCX、Excel / XLSX、Powerpoint / PPTX**；線上協作優先**騰訊檔案**或 **kdocs**；材料很多時先用 **Markdown Converter** 抽取結構；會議類流程疊加**騰訊會議**。你照上面的搭配來，基本覆蓋日常辦公九成場景，別一上來就堆一堆 Skill。

## Word：從空白頁到正式檔案

Word 的真實難點通常有四個：你不知道按什麼結構寫、語氣不夠正式、標題編號混亂、內容沒有證據來源。WorkBuddy 適合解決的不是「替你拍腦袋」，而是**把已有材料變成結構穩定、語氣一致、可以繼續修改的檔案初稿**。你給它一份材料，它交回一份能接著改的初稿，你別指望它替你做判斷。

你適合交給 Word 的任務：正式方案（活動、專案、營銷、培訓），管理檔案（制度、通知、紀要、復盤、週報月報），產品材料（PRD、需求說明、競品分析）。

### 推薦流程

| 步驟 | WorkBuddy 做什麼 | 人要確認什麼 |
| --- | --- | --- |
| 1 | 讀取材料，列出可用資訊和缺失項 | 哪些材料是事實來源，哪些只是參考 |
| 2 | 生成檔案大綱和寫作口徑 | 讀者是誰，檔案是彙報、審批還是執行 |
| 3 | 按大綱生成 Word 初稿 | 標題層級、章節順序、關鍵資訊是否完整 |
| 4 | 根據反饋潤色、補充、刪減 | 哪些可以定稿，哪些必須標“待確認” |
| 5 | 輸出可編輯 docx 和修改說明 | 是否能直接發給同事審閱 |

你按這五步走，每一步都先讓 AI 給大綱再生成，別一上來就要成品。

### 示例：生成一份團建活動策劃

```text
幫我生成一份公司團建活動策劃的 Word 檔案框架。
公司約 80 人，包含：活動目標、活動主題建議、整體流程安排（含時間節點）、
分組與互動遊戲建議、預算構成清單、人員分工、風險預案和注意事項。
語言簡潔實用，不需要寫得過於詳細，重點把整體框架和關鍵決策項列清楚，
適合直接拿去和領導確認活動方向。
```

### 二次修改不要重寫，要說差異

```text
請在上一版公司團建活動策劃 Word 檔案基礎上進行修改，不要重新生成整篇。
修改要求：
將活動目標壓縮為 3 條，每條不超過 50 字；
將流程安排改成表格，列為：時間、環節、主要內容、負責人、所需物料；
在節目型別建議中增加適合 100 人規模公司的互動環節，並刪除執行難度過高的方案；
將預算構成進一步細化，增加：預算專案、預計金額、數量、單價、備註，並補充預算總額；
新增風險預案部分，覆蓋人員遲到、裝置故障、節目超時和突發安全問題；
整體語言更加正式、簡潔，適合直接提交給領導審批。
輸出修改後的 v2 版 Word 檔案，並在 changelog.md 中列出本次修改內容。
```

## Excel：把表格變成能回答問題的分析

Excel 的問題通常不在「會不會做圖」，而在「這個表到底能回答什麼問題」。你混著空值、合併單元格、多個口徑的表格直接丟給 AI，很容易得到一份看似專業、其實沒有業務價值的圖表。你用 Excel 的順序很重要：**先定義業務問題，再決定圖表**。

你適合交給 Excel 的任務：資料清洗（去重、補空值、統一格式、多表合併），經營分析（銷售額、利潤率、轉化率、庫存週轉），報表生成（週報月報、預算執行、考勤彙總），公式輔助（生成或解釋公式、排查 `#N/A`），視覺化（圖表、透視表、儀表盤）。你把這些交給它，比自己拖公式快，也比瞎做圖靠譜。

### 推薦流程

| 階段 | 提示重點 | 輸出 |
| --- | --- | --- |
| 讀表 | 先描述工作簿結構、欄位含義、明顯髒資料 | 資料字典、問題清單 |
| 定指標 | 說明要回答的業務問題，而不是“分析一下” | 指標口徑表 |
| 清洗 | 說明空值、重複值、異常值如何處理 | 清洗後的 xlsx / csv |
| 計算 | 生成公式、透視表，保留可重新整理結構 | 彙總表、公式說明 |
| 視覺化 | 根據業務問題選圖表，避免堆砌 | 圖表、分析結論 |

### 示例：銷售資料分析

```text
請讀取 電商銷售資料.xlsx，先不要修改原檔案。
業務問題：分析本月各產品線的銷售表現和盈利能力，判斷哪些產品線貢獻高、
哪些利潤表現較弱，並識別本月銷售過程中的異常波動。
請輸出：
說明資料欄位含義，並檢查缺失值、重複記錄、異常值和欄位格式問題；
按產品線統計銷售額、毛利、毛利率、銷售額佔比和毛利貢獻佔比，並進行排名；
按日彙總銷售額和毛利率，分析本月銷售表現的日度變化；
生成柱狀圖對比各產品線銷售額和毛利，生成折線圖展示本月每日銷售額變化；
識別銷售額、毛利率或單筆訂單金額明顯異常的日期或記錄，結合資料說明，不要推測業務原因；
總結本月表現最好的產品線、需要重點關注的產品線，以及 3 條可直接用於業務復盤的結論。
輸出 output/sales-analysis.xlsx 和 output/summary.md。
要求：保留原始資料，統計過程和公式可追溯；無法確認的原因標註為待核實，不要編造。
```

### 進階：多表合併、對賬與異常清單

基礎辦公里最有價值的不是「做個圖表」，而是你先把資料口徑和異常暴露出來：

```text
合併 input/sales 中 6 個區域的周銷售表。
先檢查列名、資料型別、日期範圍、幣種和主鍵，不一致時停止並列差異。
按訂單號去重，但保留重複來源；彙總前輸出總行數、空值、異常值和重複數。
生成 clean-sales.xlsx、exception-list.xlsx 和 reconciliation.md。
金額彙總必須與各源表合計對賬，差異不為 0 時不生成管理結論。
```

## PPT：不是套模板，而是把材料變成敘事

「幫我做一份高階感 PPT」只能讓 AI 猜風格，生成一堆好看的空話。你真正可用的 PPT 必須先回答三個問題：這次彙報**給誰看**、對方聽完要**做什麼決定**、你有多少時間講。PPT Skill 可以負責頁面生成，但故事線你必須先確認——頁面越漂亮，越容易掩蓋邏輯問題。

你適合交給 PPT 的任務：專案彙報、經營彙報、培訓課件、方案展示。你先把故事線想清楚，頁面再交給它生成。

### 推薦流程

| 步驟 | WorkBuddy 做什麼 | 人要確認什麼 |
| --- | --- | --- |
| 1 | 把 Word、Excel、舊 PPT 轉成材料摘要 | 哪些內容必須保留，哪些可以刪 |
| 2 | 生成 6-10 頁故事線和每頁標題 | 彙報物件、時長、決策目標 |
| 3 | 根據確認後的大綱製作 PPT | 每頁是否只有一個核心觀點 |
| 4 | 補圖表、備註、來源對映和匯出版本 | 關鍵數字是否來自 Excel |
| 5 | 版式檢查：文字溢位、圖片缺失、字號 | 投屏後是否能讀，是否適合現場講 |

### 示例：從材料包製作簡報 PPT

```text
請根據當前工作區材料製作一份 8 頁以內的 AI Agent 主題分享 PPT。
受眾：對 AI 有基礎認知，但不瞭解 Agent 的業務和管理人員。彙報時長：10 分鐘。
目標：讓聽眾理解 AI Agent 是什麼、與普通 AI 對話工具有什麼區別、
能解決哪些問題，以及企業應該如何判斷是否值得落地。
素材：AI術語全景手冊.md 是主要內容材料；不要補充工作區材料之外的事實和資料。
全文控制在 8 頁以內，每頁只表達一個核心結論；
案例、資料和關鍵判斷必須標註素材來源，無法確認的內容不要自行補充；
PPT 標題儘量直接表達觀點，不使用"AI Agent 介紹"這類泛化標題；
輸出 output/ai-agent.pptx；生成後檢查文字溢位、頁面留白、圖表口徑、圖片缺失、
字型一致性和頁碼。
整體風格：專業、簡潔、有科技感，但不要過度使用漸變、發光和裝飾性元素。
```

## 三件套聯動：會議之後自動形成交付包

很多辦公任務不是單檔案，而是「會議之後要有東西」：你先整理紀要，再補 PRD，再做任務表，收尾做成簡報 PPT。WorkBuddy 的價值在於把這些交付物串成**同一條事實鏈**。

你以產品評審會為例，把這套鏈路一次性交給它，可用的 Skill 組合：

| 環節 | 推薦 Skill | 作用 |
| --- | --- | --- |
| 獲取會議內容 | 騰訊會議 / 智慧紀要類 | 獲取轉寫、AI 紀要、決議、行動項 |
| 生成 PRD | Word / DOCX、騰訊檔案 | 把會議內容改寫成產品需求檔案 |
| 生成任務表 | Excel / XLSX | 輸出負責人、截止日期、優先順序、驗收標準 |
| 生成彙報 | Powerpoint / PPTX | 把 PRD 和任務進度轉成管理層彙報 |

你把這四步一次性交給它，約束寫清楚，它就把會議變成一套能推進研發的交付包：

```text
請讀取本次產品評審會議的轉寫和 AI 紀要，生成一個辦公交付包。
目標：把會議內容轉成可以推進研發的材料。
請輸出：
1. Word：output/feature-prd.docx，包含背景、目標使用者、核心問題、需求列表、
   流程說明、驗收標準、風險和待確認問題；
2. Excel：output/action-items.xlsx，欄位包含事項、負責人、優先順序、截止日期、
   依賴、狀態、驗收標準；
3. PPT：output/review-summary.pptx，6 頁以內，面向管理層，突出本次會議決議、
   資源請求和風險。
約束：會議中沒有明確確認的內容，不要寫成既定結論；人名、日期、功能範圍必須保留來源；
缺少負責人或時間時標為待確認；先輸出大綱和任務表字段預覽，等我確認後再生成檔案。
```

## 常見錯誤與修正方式

你常踩的坑和更好的寫法，都在下表裡。對著看，比事後返工省事：

| 常見錯誤 | 為什麼會發生 | 更好的寫法 |
| --- | --- | --- |
| “幫我做個 PPT，要高階一點” | 沒有受眾、目標和材料約束 | 說明受眾、時長、頁數、決策目標、必須保留的資料 |
| “分析一下這個 Excel” | 沒有業務問題，模型只能泛泛總結 | 說明要回答什麼問題、統計哪些指標、按什麼維度比較 |
| “寫一份報告” | 沒有檔案型別和語氣要求 | 說明是方案、總結、申請、紀要還是 PRD，並指定讀者 |
| “全部自動完成，不用問我” | 關鍵口徑沒確認，風險被放大 | 先讓 WorkBuddy 輸出材料清單、風險清單和大綱，確認後再生成 |
| “把這堆材料合成一個檔案” | 沒有區分事實、參考和待確認 | 指定唯一資料來源、參考檔案和不能編造的欄位 |

## 常見問題

**AI 做 Word 檔案，是不是把要求一扔就行？**
不行。你先把目標、受眾、材料、格式、驗收這五個問題想清，AI 才出得了結構穩定、能繼續改的初稿。否則它只能替你拍腦袋。

**Excel 我直接丟表給 AI 做圖可以嗎？**
不建議。你表裡有空值、合併單元格、多個口徑，直接做圖容易得到好看但沒業務價值的圖。先定義業務問題，再決定圖表。

**PPT 怎麼才不像空話堆砌？**
你先回答給誰看、聽完做啥決定、講多久。故事線你先確認，頁面才讓 Skill 生成——頁面越漂亮越容易蓋住邏輯漏洞。

**二次修改為什麼要說差異，不直接重寫？**
省時也更可控。你像示例那樣寫明「把目標壓成 3 條、流程改表格、預算細化」，AI 在上一版上改，不會把已經滿意的部分推倒重來。

**會議後的一堆交付物怎麼一次生成？**
你把它們串成同一條事實鏈：先紀要，再 PRD，再任務表，收尾簡報 PPT。給清約束——沒確認的別寫成結論、人名日期保留來源，先出大綱你確認再生成檔案。

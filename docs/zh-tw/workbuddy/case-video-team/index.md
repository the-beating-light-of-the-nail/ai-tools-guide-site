# 怎麼一句話召喚 AI 影片團隊？生成和拆解兩支隊伍一次講清

你想做短影片，但卡在兩件事上：要麼一條影片從選題到成片累死人，要麼別人爆了你也看不出人家到底贏在哪。在 WorkBuddy 裡，你把這事拆成兩支 AI 專家團：一支負責自動生產影片，一支負責拆解爆款影片。

| 團隊 | 負責什麼 | 適合什麼任務 |
| --- | --- | --- |
| 影片生成團隊 | 從主題出發，完成熱點採集、選題篩選、指令碼、分鏡、配音、渲染、字幕和釋出 | AI 週報、產品更新、知識科普、行業分析、產品評測 |
| 爆款影片拆解團隊 | 從影片連結出發，下載影片、提取音訊、轉寫文案、分析鏡頭語言，生成拆解報告和仿拍建議 | 學習爆款結構、復盤競品影片、沉澱拍攝手冊 |

這兩個團隊不是互相替代的關係：生成團隊解決「今天怎麼做一條出來」，拆解團隊解決「為什麼別人那條能火，我能學到什麼」。你一個負責生產，一個負責學習，組合起來才有持續迭代的可能。

![兩支 AI 影片團隊：生成與拆解](/workbuddy/case-video-team/assets/002_two-ai-video-teams_SXcUb9mpMo.png)

## 如何召喚：從一句話開始，但不要停在一句話

你開頭只要一句話，但別真停在一句話——後面讓團隊自己拆：

```text
召喚影片生成團隊，製作一條 46 秒 AI 週報短影片。
```

## 第一支團隊：影片生成團隊

四個核心角色：主理人**凌導**、資訊採集員**靈閱**、內容策劃師**靈樞**、影片製作師**靈映**。它們不是四個換名字的聊天視窗，而是一條有上下游交接關係的影片生產線。

![影片生產線四角色：凌導、靈閱、靈樞、靈映](/workbuddy/case-video-team/assets/004_video-team-roles_ZOJ8b7aQ7o.png)

| 角色 | 定位 | 交付物 |
| --- | --- | --- |
| 凌導 | 主理人 / 團長 | 拆解任務、安排並行與序列流程、彙總產物、處理檢查點 |
| 靈閱 | 資訊採集員 | 熱點池、來源表、去重後的結構化摘要、選題候選 |
| 靈樞 | 內容策劃師 | 選題判斷、指令碼、分鏡、旁白、轉場、素材清單、BGM 和字幕節奏 |
| 靈映 | 影片製作師 | HTML 影片工程、配音、字幕對齊、轉場動畫、素材拼接、渲染成片 |

這才是多 Agent 的關鍵：**不是角色越多越好，而是每個角色都有清晰輸入和輸出**。你讓資訊採集員不直接寫成片指令碼，策劃師不重新編造熱點，製作師不重寫事實，團長負責讓流程不斷檔。

### 生產引擎：HyperFrames

你先搞清楚這條流水線怎麼轉，後面才好派活。這條流水線基於 HyperFrames（開源影片渲染框架）搭建：用 HTML 渲染影片，天然適合 Agent 生成結構化工程，再交給渲染工具輸出 MP4，自帶 CLI 工具鏈、TTS、字幕、去背景和影片元件模板。你把它當成一條標準生產線，每個環節都有交付物。

### 流程一：資訊採集員先讓熱點有來源

你先用流程一讓熱點有來源，別一上來就拍。做影片最耗時間的往往不是剪輯，而是「今天到底拍什麼」。你讓靈閱抓 RSS、搜新聞、掃社媒、聚合 AI 熱點並去重。這個階段的產物至少包含：標題、來源、釋出時間、事件發生時間、原始連結、熱度線索、為什麼值得關注。**熱度只能幫助排序，不能替代你做事實核驗。**

![靈閱的熱點採集報告：標題、來源、熱度線索](/workbuddy/case-video-team/assets/007_collection-report_KPn1bXgYQo.png)

### 流程二：內容策劃師把主題變成鏡頭

你先用流程二把主題變成鏡頭，指令碼卡住就先停。選題有了之後，真正費腦子的是「這條影片怎麼講」。你讓靈樞負責選題評估、指令碼、分鏡、旁白、鏡頭節奏、BGM 節奏和情緒節點。

![靈樞：選題評估、指令碼與分鏡設計](/workbuddy/case-video-team/assets/008_planner-full_YPM3boyNTo.png)

你建議在這裡設定第一次人工檢查：開頭 3 秒是否有鉤子、46 秒是否塞入過多資訊、旁白是否準確、畫面是否真的支撐觀點。指令碼不過關，不要進入配音和渲染。

### 流程三：影片製作師把分鏡變成成片

你先用流程三把分鏡變成成片，前面指令碼過關再進這步。你讓靈映把確認後的指令碼轉成 HTML，再呼叫 HyperFrames 渲染 MP4，自動完成 Azure TTS 配音、Whisper 字幕對齊、動畫與轉場生成、素材拼接和影片渲染。

![靈映：指令碼轉 HTML、渲染、配音與字幕](/workbuddy/case-video-team/assets/009_video-producer_PohnbE1jKo.png)

成片驗收你不要只看「能不能播放」：檢查旁白與字幕是否一致、鏡頭時長是否匹配、文字是否遮擋主體、BGM 是否可用、素材是否有版權風險、畫面是否適合目標平臺安全區。

### 流程四：釋出可以自動化，但預設要人工確認

你先把釋出當成可選動作，預設留人工確認。釋出 Agent 自動生成標題、打標籤、上傳封面，並通過雲手機發布到抖音、影片號和 B 站。能力很強，但**預設不要直接自動釋出**，除非賬號、素材、標題和合規邊界都已經過你確認。

![釋出 Agent：標題、標籤、封面與多平臺上傳](/workbuddy/case-video-team/assets/011_publish-demo_DdTYbbBxLo.png)

## 第二支團隊：爆款影片拆解團隊

你光會生成還不夠，得懂別人為什麼能爆。光會生成還不夠。你真正需要的是理解「為什麼別人能爆」：提取影片、轉錄文案、分析景別運鏡、剪輯節奏、色調風格，並給出仿拍建議。

![拆解團隊：下載、轉錄、分析鏡頭語言](/workbuddy/case-video-team/assets/013_anatomy-team_OI1Ubltu1o.png)

| 角色 | 職責 | 工具 / 技術 |
| --- | --- | --- |
| 阿爆 | 團長 / 拆解總控 | 任務排程、流程編排、結果彙總 |
| 小凱 | 音訊處理與轉錄 | ffmpeg、ASR，把影片音訊轉成完整口播文案 |
| 小淼 | 影片理解與鏡頭裁切 | 影片理解 API、ffmpeg，分析鏡頭語言並裁切片段 |

### 拆解流程一：影片下載要有降級策略

你下載影片時要有降級策略，別卡在第一步。最複雜的一步是拿到影片，設計上你用三層降級：官方 API → Playwright → yt-dlp，只要有一層成功流程就繼續。

![影片獲取三層降級：官方 API → Playwright → yt-dlp](/workbuddy/case-video-team/assets/015_anatomy-flow_CuFcbaM9Ao.png)

> 邊界：影片下載和分析要遵守平臺條款、版權授權和合理使用範圍。你拆解的目的是學習結構和方法，不是搬運原影片。

### 拆解流程二：音訊提取與文案轉寫

你讓小凱用 ffmpeg 把 video.mp4 轉成 audio.mp3，再呼叫語音識別 API 自動轉錄完整口播文案。以前一句句聽、一句句敲的工作，現在可以被穩定自動化。

### 拆解流程三：影片理解與鏡頭語言分析

最有意思的一步：你讓小淼分析整條影片的景別、運鏡、轉場、剪輯節奏、色調、鏡頭時長。很多看起來「有感覺」的爆款影片，背後其實有穩定的鏡頭規律。

![小淼的鏡頭語言分析：景別、運鏡、節奏、色調](/workbuddy/case-video-team/assets/018_video-understand_VwxLb62b1o.png)

## 兩支團隊如何形成閉環

```mermaid
flowchart LR
    A[爆款视频链接] --> B[拆解团队：转写、镜头、节奏、仿拍建议]
    B --> C[形成拍摄手册和内容规律]
    C --> D[生成团队：热点、脚本、分镜、渲染]
    D --> E[人工验收与发布]
    E --> F[数据复盘]
    F --> B
```

你先用拆解團隊學習鏡頭語言和節奏，再讓生成團隊生產新影片，釋出之後繼續分析資料，反過來最佳化下一版內容。這就是專家團比單個工具更有意義的地方：它不只是幫你做一條影片，而是讓「學習、生產、釋出、復盤」變成一個可以重複運轉的系統。

## 常見問題

**一句話真的能召喚整個團隊嗎？**
能開頭，但你別隻給一句話。你給個主題（比如「46 秒 AI 週報」），團隊會自動拆成採集、策劃、製作、釋出幾段，你在關鍵節點拍板就行。

**生成團隊和拆解團隊你要同時用嗎？**
看階段。你起步時先用生成團隊把一條影片做出來；想持續進步，再用拆解團隊研究爆款結構，反哺生成。兩條線合起來才是閉環。

**指令碼階段你為什麼要介入？**
因為指令碼決定一條影片講不講得通。你檢查開頭 3 秒有沒有鉤子、46 秒是不是塞太滿、旁白準不準——指令碼不過關別進配音渲染，返工更貴。

**釋出能全自動化嗎？**
能力上能，但你預設別開自動釋出。賬號、素材、標題、合規邊界都確認過，再讓它發。自動點贊、刷評論、繞風控這些不在推薦範圍。

**拆解影片會不會踩版權？**
會，如果你越界。你只把拆解當學習結構和方法用，下載和分析遵守平臺條款和合理使用，不搬運原影片。

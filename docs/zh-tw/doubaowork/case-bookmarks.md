# 從隨手收藏到以後真正能搜

> 場景：收藏存了很多，真正要用時怎麼也找不到；隨手記的靈感當時只一句話，過幾天再看已經想不起為什麼記、本來準備拿它做什麼。

這是兩個獨立任務，遇到哪個用哪個——不需要為了整理一條靈感，先把整個收藏夾清一遍：

| 獨立任務 | 什麼時候使用 | 主要交付 |
| --- | --- | --- |
| 收藏很多，要用時搜不到 | 連線知識庫、收藏夾和文件目錄的唯讀許可權，先盤點再整理 | 可檢索目錄、建議歸檔或刪除清單 |
| 靈感只記了一句話 | 把碎片筆記、語音或截圖直接交給豆包工作，資訊不足時先追問 | 筆記草稿，確認後再寫入知識庫 |

## 收藏很多，真正要用時卻搜不到

整理時不能只重新分類、調整資料夾，還要**補齊檢索和判斷所需的資訊**：同一知識在多個工具裡各有一份時主版本不清楚；按檔案類型或個人習慣分類，未必符合日後真正的搜尋方式；很多收藏缺少摘要、關鍵詞和適用場景；沒有提前明確操作邊界，自動整理還可能誤刪或移動原檔案。

```text
整理這些收藏與資料，讓我以後能按真實問題找到它們。
先識別每份內容解決什麼問題、適用什麼情景、可信度、時間敏感性和原始來源。
合併重複收藏，把只有連結但無法訪問、已經過時或沒有說明用途的內容單獨列出。
按"以後會怎麼搜尋"生成簡短摘要、關鍵詞和關聯主題，而不只按檔案類型分類。
輸出可檢索目錄、建議歸檔或刪除清單；未經確認不移動或刪除原內容。
```

把知識庫路徑設為工作目錄後，這段提示詞可以**分五步逐句推進**，每步都有對應產出：

1. 「整理這些收藏與資料……」→ 掃描梳理目錄，呈現資料關聯，生成按實際問題組織的索引結構圖；
2. 「先識別每份內容解決什麼問題……」→ 逐份分析，彙總核心結論，生成"可信度 × 時間敏感性"熱力圖和資料後設資料表；
3. 「合併重複收藏……」→ 不改動原檔案的前提下歸併重複項，待確認內容單獨列出；
4. 「按'以後會怎麼搜尋'生成摘要……」→ 生成檢索地圖、檢索表和摘要表；
5. 「輸出可檢索目錄、歸檔或刪除清單……」→ 彙總成可檢索目錄、資料分佈圖和處置建議清單——**所有歸檔刪除只作為建議呈現，確認前不改動原檔案**。

最終確認：是否移動、歸檔或刪除，最後由人決定；正式操作前再檢查一遍版本、來源和分類有沒有判斷錯。

## 靈感只記了一句話，怎樣變成以後找得到的筆記

保留原句，再補上必要的上下文、標題、摘要、關鍵詞和關聯內容。原始記錄太簡略時，整理工具最大的風險是**替你補全意思**——最後的筆記看起來很完整，卻已經偏離你當時真正想表達的內容：

```text
把這條碎片靈感整理成一張以後能理解和複用的筆記。
保留原始內容和記錄時間，再補充它來自什麼情景、觸發了什麼問題、
可能關聯哪些專案或主題、下一步能做什麼。
如果原句含義不清，最多問我 3 個關鍵問題，不要替我編造當時想法。
生成一個可搜尋標題、簡短摘要、關鍵詞和相關筆記建議。
輸出筆記草稿，由我確認後再寫入知識庫。
```

實測把收件箱裡 6 條靈感碎片整理成了可複用筆記：先核對原始內容和時間戳、補充情景/觸發問題/關聯專案/下一步行動；"最多問 3 個關鍵問題"這一句會去掉筆記中帶推測的內容，含義不清的部分標為"待確認"；隨後新增檢索卡（可搜尋標題 + 摘要 + 關鍵詞 + 相關筆記建議），方便以後全庫搜到；最後輸出草稿供審閱，確認無誤才寫入知識庫。

驗收習慣：抽查一到兩條結論能否回到原檔案或原始記錄；檢查數字、日期、版本和物件有沒有寫錯；**只要結果會影響他人、資金、許可權、合規或生產系統，就先保留為草稿**。

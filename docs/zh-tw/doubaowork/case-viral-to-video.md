# 想把公眾號爆款改成短影片，怎麼讓豆包工作跑通從指令碼到本地成片的全流程？

你看到一篇爆款公眾號文章，想改成一條短影片。很多人做法是複製全文扔給 AI，說一句「幫我改成 60 秒口播」。AI 很配合地刪掉一半，加一句「你敢相信嗎」，補一個「趕緊點贊收藏」——字少了，影片卻不一定能用，原文的條件、時間和個人實測還容易變味。這篇帶你跑通一條完整鏈路，從指令碼到本地 MP4 成片。

你大概也試過這種偷懶法，結果影片發出去被自己都嫌假。你真想把文章變成能用的影片，得把編劇和剪輯拆開走。你跟著下面的鏈路，從指令碼一路跑到本地成片；你不用自己寫剪輯工程，Remotion Skill 幫你渲染；你只要把原文事實和素材管住，你就不會被套路臺詞帶偏。

實測拿公眾號文章《我把電腦外包給豆包後，效率飛昇！【附教程】》跑通完整鏈路（只到本地成片，未上傳發布）：

```text
公眾號原文
→ 短影片指令碼與逐秒分鏡
→ 真人口播 + 產品錄屏 + 配圖素材包
→ Remotion Skill
→ 程式碼檢查、渲染、ffprobe 和抽幀驗收
→ 本地 MP4 成片
```

工具分工：編劇和剪輯是兩件事。指令碼不好要改的是資訊取捨，素材缺失要補拍，成片黑屏或音軌不對是剪輯工程——兩個流程拆開，哪一步出問題你一眼就能看出來。

| 階段 | 採用 | 負責什麼 |
| --- | --- | --- |
| 原文整理 | 網頁正文提取 | 留住原文事實、條件和案例順序 |
| 指令碼與分鏡 | 短影片指令碼編劇（工作夥伴） | 選角度、寫口播、拆逐秒畫面、事實自檢 |
| 素材管理 | 本地電腦能力 + 素材清單 | 核對影片、錄屏、圖片和路徑是否存在 |
| 真正剪輯 | Remotion Skill | 複用專案、組織時間線、渲染 H.264 MP4 |
| 驗收 | ffprobe + 均勻抽幀 | 檢查時長、解析度、幀率、音軌、黑屏和截斷 |

## 第一步：獲取原文，找編劇夥伴

你直接把原文連結交給豆包工作提取內容。然後到「技能·連接器·夥伴」切到「工作夥伴·小隊」，搜尋「影片」找到短影片指令碼編劇——它和普通寫作 Skill 的區別是：不只交付一段口播，還會按時間段安排動作、畫面和字幕。你上傳事實母稿，把目標時長、受眾、素材條件和安全邊界一次性寫進提示詞：

```text
我是一名公眾號作者，準備把自己的長文《文章標題》改成一條 3 分鐘以內、
可以直接拍攝和剪輯的短影片。

輸入材料：
- 原文連結：【連結】
- 已從原文清洗並核驗的事實母稿：上傳的《公眾號原文事實母稿.md》

請你以"短影片指令碼編劇"的工作方式處理：
1. 先讀取事實母稿，列出不能改壞的事實和需要保留限定詞的數字。
2. 從原文的真實任務裡挑最適合短影片表達的 3 個，
   不要為了塞滿而把所有內容念一遍。
3. 寫一版 150—180 秒的第一人口播稿。開頭 5 秒直接製造反差。
4. 口語化、短句、有停頓感，保留本人實測的語氣；
   不要寫成產品釋出會，也不要加入沒發生過的功能。
5. 把口播稿拆成逐鏡頭表格，包含：時間段、口播、畫面、素材型別、
   螢幕大字、轉場、風險備註。
6. 優先複用現有口播影片、產品操作錄屏和文章配圖；
   缺素材的鏡頭明確標"需補拍"，不要假裝素材已經存在。
7. 最後做一次事實自檢，逐項檢查平臺差異、幀率、時長、數量、釋出日期
   和"效率提升"是否仍保留原文條件。

最終請交付：口播稿 + 逐鏡頭剪輯表。
聊天裡只彙總：成片建議時長、鏡頭數、複用素材數、需補拍數。

安全邊界：只生成本地指令碼和分鏡，不上傳、不釋出，不修改原素材，
也不要把個人實測寫成普遍承諾。
```

實測交付了 3 套指令碼（總覽角度 / 手機佈置電腦執行 / AI 幹活但滿足感仍屬於人），每套按時碼拆開，列了平臺、目標受眾、傳播目標和拍攝條件，還把釋出前檢查分成「已通過」和「仍待人工」兩類。

## 第二步：整理素材包

指令碼解決拍什麼，素材包決定畫面：前段真人口播（開場、問題和能力解釋）、中段操作錄屏與口播（真實任務的電腦操作）、結尾真人口播（結論和行動提示）、影片封面，加上工作任務模式截圖（解釋「不是隻聊天」）和技能連接器截圖（解釋為什麼有現成工具要優先用）。你給每個素材起一個能說明用途的名稱，豆包工作剪輯時就知道什麼情況用哪個素材。

## 第三步：上傳 Remotion Skill 做剪輯

技能頁搜尋「影片剪輯」若無結果，你走「新建 → 上傳技能」（[Remotion 官方提供 AI Skill](https://www.remotion.dev/docs/ai/skills)）。上傳包必須包含 `SKILL.md`——把本地驗證過的 Remotion Best Practices Skill 打包成 ZIP 上傳，安裝後在「我的技能」裡開啟開關。

> Skill 不是影片模板，它更像一份給 Agent 的專業工作說明，告訴它建立 composition、處理素材、做時間線、渲染和驗收時應該遵守什麼規則；真正的素材和專案仍由你提供。

你呼叫時把四件事說清——用哪個 Skill、讀哪些素材和專案、怎麼驗收、哪些動作禁止：

```text
請使用當前已安裝的 Remotion Skill，把素材包剪成一條可播放的影片。

輸入：
- 口播影片、操作錄屏和配圖：以《素材清單.md》中列出的本地路徑為準
- 口播稿與逐鏡頭剪輯表：使用上一階段已驗收的檔案
- 已有 Remotion 專案：【替換成你自己的本地專案絕對路徑】

執行要求：
1. 先檢查素材清單和檔案是否存在，缺失項先列出來，不要編造。
2. 複用已有 composition，不要重建專案，不要覆蓋原始影片。
3. 保留真人口播主線，在對應段落插入產品操作錄屏、介面圖和章節提示；
   避免用裝飾動畫蓋住真實介面。
4. 畫面比例、解析度、時長以現有 composition 為準；
   所有數字和功能描述必須符合事實母稿。
5. 執行程式碼檢查和型別檢查，再渲染 H.264 MP4。
6. 渲染後用 ffprobe 核對時長、解析度、幀率、影片編碼和音軌；
   再均勻抽幀檢查開頭、三個案例段、結尾有沒有黑屏、錯字、截斷和隱私資訊。

最終交付：本地 MP4 成片 + 一張接觸表或多張驗收抽幀
         + 一份簡短驗收記錄（檔案路徑、媒體引數、已知限制）。

安全邊界：只在本地專案中生成新檔案，不刪除或覆蓋原素材，不上傳、不釋出。
```

提交後它先讀 Remotion Skill、再探查現有專案和素材清單——這才算真正用到了 Skill。最終交付裡除了成片，還列出 composition、畫面和音訊引數、時間線結構。

## 人的部分仍然最值錢

以前你覺得「根據文章做條影片」不難，真跑一遍才發現：文章裡最有價值的是事實和觀點，影片裡最費勁的是口播、素材和剪輯——需要一條完整生產線才能提高產能。AI 能把這條生產線整合起來，但最有價值的部分仍然屬於你：把重複勞動交給 Agent，把省下來的時間留給那些只有你能做的選擇。

## 新手常見問題

**為什麼不能直接把文章丟給 AI 說「改 60 秒口播」？**
那樣它容易刪掉原文的條件、時間和你的個人實測，再塞兩句套路臺詞。你用事實母稿 + 編劇夥伴，先鎖死不能改壞的事實，影片才不變味。

**Remotion Skill 是什麼，要自己寫嗎？**
你不用寫。Remotion 官方提供了 AI Skill，你打包成 ZIP 上傳、開啟開關就行。它本質是一份給 Agent 的工作說明，不是現成影片模板。

**缺素材它會自己編嗎？**
你提示詞裡寫「缺素材的鏡頭標需補拍，不假裝存在」。該補拍就補拍，它不會用假素材糊弄你。

**成片怎麼驗收？**
它用 ffprobe 核時長、解析度、幀率、音軌，再均勻抽幀查黑屏、錯字、截斷和隱私資訊。你拿到成片，重點看開頭、三個案例段和結尾這幾處抽幀。

**全流程跑下來最貴的是哪一步？**
最貴的是你——口播、素材和剪輯的判斷。AI 整合生產線，但選題、補拍、最終取捨還是你的活。把重複勞動交給它，省下的時間留給只有你能做的選擇。

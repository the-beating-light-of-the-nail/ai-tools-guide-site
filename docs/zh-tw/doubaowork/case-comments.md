# 從評論區找到下一篇內容，並複盤

> 場景：很多人做內容複盤，最後只留下三句話——播放一般、收藏不錯、下次繼續最佳化。這不叫複盤，最多算看了一眼後台。

真正能幫到下一篇的複盤要回答得更具體：大家究竟在問什麼？哪幾個問題反覆出現？哪些評論雖少卻關係到信任和安全？收藏率達標了，完播為什麼還掉得厲害？下次到底保留什麼、最佳化什麼、只測試哪一個變數？實測把兩個複盤流程分別跑了一遍：

```text
任務一：32 條評論 → 完整性檢查 → 主類別標註 → 主題聚類 → 事實與推斷分開
        → 8 個候選打分 → Top 3 → 只推薦一個下一篇主題

任務二：72 小時發布指標 + 發布前目標與製作記錄 → 凍結統計口徑 → 彙總和手算複核
        → 按來源、日期比較 → 對照目標與製作成本 → 保留 / 停止 / 測試 → 下一篇 brief
```

工具組合：評論區洞察用「使用者研究與需求洞察」Skill + 本地 CSV（覆蓋原聲打標、定量分析和需求歸納）；發布後複盤用「資料分析」Skill + 指標 CSV + 目標與製作記錄（先凍結口徑，再做對帳和經營複盤）。兩個任務都是單份本地材料的結構化分析，**不需要**專家團、MCP 或平台連接器——能完成任務的最小組合，通常才是最優組合。

> 處理真實評論時：先從平台後台匯出或用已授權的唯讀連接器取數；不要把使用者名稱、手機號、公司、群號、私信內容等個人資訊直接交給 AI。

## 任務一：評論區在問什麼，單獨做使用者洞察

只要有一批可合法使用的評論就能執行，不要求先拿到後台指標。提示詞最關鍵的 4 點：**每條評論只計一個主類別**（防止統計重複）；**每個主題都要給評論數、互動量、代表性 ID、原話和來源**；**使用者原話能證明的事實和分析者的推斷分開**；**只生成分析檔案，不回評論、不私信、不發布**。

```text
我負責一個面向普通職場人的 AI 工具帳號。請使用"使用者研究與需求洞察"能力，
只分析你剛剛找到並讀取的 32 條評論檔案：
【comments.csv 路徑，或改成"只分析當前對話中的【檔名】"】

資料說明：這是用於內部練習的脫敏樣例資料，不對應真實帳號或真實評論者。
不要聯網補充評論，也不要根據帳號畫像推斷年齡、性別、職業、地域、收入等個人敏感屬性。

請按下面步驟完成：
1. 先做資料完整性檢查：確認總行數、欄位、空值、重複評論和疑似垃圾資訊。
2. 給每條評論標一個"主類別"：提問、認可、反對、誤解、補充案例、產品需求、
   情緒表達、垃圾資訊。必要時可加副標籤，但統計只按主類別計算。
3. 把評論聚成使用者問題主題。每個主題必須給出：評論數、互動量（點贊+回覆）、
   代表性 comment_id、1—2 條原話和對應 source_url。
4. 明確區分"使用者原話能直接證明的事實"和"你的推斷"。推斷必須單獨標註，
   不得寫成使用者共識。
5. 單獨列出：適合公開回復的問題、需要私下處理或謹慎回應的風險、可以忽略的垃圾資訊。
6. 生成 8 個下一篇內容候選。分別按需求頻次、互動強度、可操作性、信任/安全價值
   四項各 1—5 分打分，並給總分和證據 comment_id。
7. 選出 Top 3；再明確推薦下一篇只做一個主題，並給出選題標題、讀者問題、
   文章承諾、必須回答的 5 個問題、需要準備的證據、不能誇大的邊界。
8. 做一次自檢：分類總數是否等於有效評論數，引用能否回到 comment_id/source_url，
   是否把推斷寫成事實。

請儲存為《評論使用者問題地圖.md》。聊天裡只彙總：有效評論數、垃圾評論數、
Top 3 選題和推薦的下一篇主題。

安全邊界：只生成分析檔案；不要公開回復、發私信、發布內容，也不要寫回任何平台。
```

實測：完整性檢查發現 32 條記錄中 1 條垃圾資訊，有效評論 31 條；Top 3 為「長音訊轉寫與人工校對實操」（16/20，C026 互動 108 全場最高）、「AI 自動執行許可權清單」（15/20，多條評論指向同一類許可權焦慮）、「真實失敗案例與修正過程」（15/20，兩條高互動評論合計 149）。最終只推薦一個主題：**長音訊轉寫與人工校對實操**——C026 明確說"每天都要整理訪談"，還能同時回應會議錄音、新手不知從哪開始等相鄰問題。

人工還要再查三件事：引用有沒有斷章取義；少量但涉及信任、安全、隱私的問題有沒有被平均數淹沒；推薦主題能不能拿出真實截圖、資料或失敗過程來回答。

## 任務二：發布後複盤，下一篇別再從零開始

這個任務和任務一彼此獨立：只要一份指標表 + 發布前目標和製作記錄。**複盤最容易踩的坑是分母混亂**——完播率是完播除以播放還是除以 3 秒播放？不先寫清，同一份資料能算出完全不同的結果：

```text
這是一個新的、獨立的發布後複盤任務。請使用"資料分析"能力，唯讀取下面兩份本地材料：
1. 【metrics.csv 路徑】
2. 【goals-and-log.md 路徑】

資料是脫敏樣例，不代表真實帳號表現。不要聯網補數，不要連線內容平台，
也不要把單次發布推斷成長期規律。

請按以下步驟：
1. 凍結統計口徑：72 小時；確認行數、欄位、空值、重複、各指標單位。明確每個比率分母。
2. 彙總曝光、播放、3 秒播放、完播、點贊、收藏、分享、評論、主頁點選、關注。
3. 計算並複核：曝光→播放率、3 秒留存率、完播率、點贊率、收藏率、分享率、評論率、
   主頁點選率、關注轉化率。至少手算抽查 3 個指標。
4. 按日期和來源分別比較，指出變化最大的環節；事實與解釋假設分開。
5. 對照發布前目標、內容結構和 490 分鐘製作投入，回答：目標是否達成、
   哪裡值得保留、哪裡應停止、下次還需測試什麼。
6. 不能把相關性寫成因果。樣本只有一次發布，所有原因判斷都標為"假設"，
   同時寫出驗證辦法。
7. 輸出一張複盤卡片：事實摘要、漏斗、來源對比、目標對照、保留/停止/測試、資料限制。
8. 再給下一篇內容 brief：一個選題、目標讀者、核心問題、內容承諾、結構、所需證據、
   成功指標和發布前檢查。選題只能來自本次材料中明確出現的評論或限制，不得憑空擴充套件。
9. 做自檢：總量能否與分來源/分日期相加，公式口徑一致，結論都有來源，未執行外部操作。

請儲存為《發布後複盤卡片.md》和《下一篇內容brief.md》。
聊天裡只彙總：收藏率是否達標、完播率、表現最強來源、保留/停止/測試各一條和下一篇選題。

安全邊界：只生成分析檔案，不寫回選題庫，不發布，不回覆評論，不呼叫外部平台。
```

實測 72 小時總量：曝光 51,400、播放 22,890、完播 7,537、收藏 1,190。三個關鍵比率：曝光→播放率 44.53%；完播率 32.93%；**收藏率 5.20%，超過發布前 3% 的目標**。分來源看，粉絲頁 9 項比率中 8 項最高，搜尋的收藏率和分享率領先，推薦流貢獻約 70% 曝光但轉化偏低。更重要的是它點出了四個明確動作：

| 決策 | 本次輸出 |
| --- | --- |
| 保留 | 實操案例 + 收藏引導結構 |
| 停止 | 把 4 個不相關案例壓進一條影片的高密度做法 |
| 測試 | 單獨展示失敗重試過程，觀察完播和具體問題數量 |
| 下一篇 | 《豆包電腦版失敗了怎麼辦：3 個真實報錯與重試全過程》 |

注意"資訊密度導致中段流失"仍然只是假設，必須通過 A/B 或同類內容對照驗證——單次發布 n=1，不總結長期規律。

> 複盤不是給過去找一個聽起來合理的故事，而是**給下一次準備一個可以驗證的動作**。

## 壓縮成一張檢查清單

**評論洞察**：先脫敏再交給 AI；先查總數、空值、重複和垃圾；每條評論只計一個主類別；主題必須帶 comment_id、原話和來源；原話和推斷分開；先排 8 個候選 → Top 3 → 只定一個下一篇；不自動回覆、不私信、不發布。

**發布後複盤**：固定統計視窗和指標分母；總量、分來源、分日期必須對帳；至少手算抽查 3 個關鍵比率；和發布前目標、內容結構、製作成本一起看；結論落到保留、停止、測試；單次發布只提假設；先生成複盤卡片和 brief，不直接寫回選題庫。

評論區像一份免費的、持續更新的使用者訪談；後台指標告訴你下次該改哪裡。把兩種材料分開處理，再把結果放回下一篇內容——選題就不需要每次從空白文件開始了。

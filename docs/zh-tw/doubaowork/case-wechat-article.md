# 從熱點到公眾號成稿

> 場景：寫熱點文章最費時間的不是寫字，而是行文思路——先核實數字真假，再決定哪些能寫，正文寫完還要起標題、做封面。分開做特別容易前後打架：正文寫「官方稱接近」，標題一激動變成「全面吊打」。

這一篇拿 GLM-5.3-Flash 做了一次完整實測：不是一句話生成，而是把整篇文章的行文思路拆成**四個工作流**——事實包 → 長文 → 標題候選與風險檢查 → 封面。步驟看著多，反而更省事：每一步都有上一份成果可查，後面每一步都是前一步的結果，整個流程形成邏輯閉環。

## Skill 組合

| 任務 | 組合 | 為什麼這樣選 |
| --- | --- | --- |
| 動筆前核對事實 | VOC 與輿情調研 + 公開網頁檢索 | 能同時讀多來源、找衝突、留下原始連結和證據缺口 |
| 把材料寫成長文 | 公眾號圖文與營運策略 + 本機事實包 + Lark Doc | 寫作時有明確事實邊界，成稿還能交給編輯審核 |
| 生成標題防標題黨 | 爆款標題與選題日曆 + 已完成文章 | 不只給標題，還逐個標記誤導風險和使用場景 |
| 製作公眾號頭圖 | 創意設計 + 圖片生成與檢查 | 先定概念和構圖，再生成並檢查比例、裁切和文字風險 |

## 任務一：動筆前，先把事實、數字和來源找齊

很多人寫科技熱點的順序是：看到驚人標題 → 馬上開寫 → 寫到一半再找資料補洞。這次反過來：**先不寫正文**，先讓豆包工作交付一份「什麼能寫、什麼不能直接寫」的事實包。提示詞裡直接給四個公開來源（官方部落格、Hugging Face 模型卡、官方定價頁、36 氪文章），並規定四類分級：

```text
我是科技 / AI 類公眾號編輯，準備寫一篇面向普通職場人和開發者的 GLM-5.3-Flash 文章。
請先製作「寫作事實包」，此時不要寫正文。

請優先完整讀取並核驗下面的公開來源：
1. Z.ai 官方部落格：https://z.ai/blog/glm-5.3-flash
2. 官方 Hugging Face 模型卡：https://huggingface.co/zai-org/GLM-5.3-Flash
3. Z.ai 官方定價頁：https://docs.z.ai/guides/overview/pricing
4. 36 氪公開文章：https://36kr.com/p/xxxxx

工作要求：
- 先列出文章需要回答的 6—8 個關鍵問題。
- 對發布時間、參數規模、激活參數、上下文、原生的多模態、開源授權、
  支援框架、價格、跑分、國產晶片部署等逐項核驗。
- 把內容分成「官方可確認事實」「廠商自報評測或判斷」「媒體轉述」
  「仍缺獨立證據」四類。
- 不用搜尋摘要代替原文；無法開啟或原文沒有明確寫出的內容標為「待確認」。
- 來源衝突時並列說明，不替任何一方下結論。
- 每條事實給出原始連結、頁面日期或造訪日期、證據強度和可以安全寫進文章的表述。
- 單獨檢查「價格只有 1/40」「57 分持平」「10 萬張國產晶片」等傳播性強的說法，
  說明能否直接使用。

最終交付：關鍵問題、事實表、可用案例、不能直接寫的說法、仍缺證據的問題和來源清單。
儲存為 Markdown 成果檔案。未經確認，不寫文章、不發布、不發送訊息、不修改線上文件。
```

一個好用的提示詞習慣：**不僅告訴 AI 要查什麼，還要規定它怎樣表達不確定性**——否則它很容易把「搜尋到了」誤當成「已經證實」。實測中出現兩個典型情況（Hugging Face 因安全策略無法抓取、定價頁首次造訪沒顯示 Flash），它沒有悄悄跳過，而是記錄情況並繼續透過快取和多來源交叉確認。

最終事實包總結了三處最容易翻車的說法：「價格只有 1/40」是媒體對用戶價格的粗略概括，不能寫成硬體成本；「57 分持平」只在特定版本的綜合指數上成立，不能擴展成所有能力都一樣；國產晶片數量在官方英文部落格和中文媒體之間存在口徑差異，不能去掉來源直接下結論。**綠燈內容可以寫，黃燈內容要加來源和限定，紅燈內容先別碰。**

## 任務二：把事實包寫成能讀完的長文

事實包解決真實性和正確性，但還不是大家願意讀完的文章。第二步是在**不突破事實邊界**的前提下，把資訊源變成一條自然的敘事線。用「公眾號圖文與營運策略」技能，把事實包檔案交給它並明確「只使用事實包裡的材料」：

```text
請使用「公眾號圖文與營運策略」技能，讀取這份事實包：
【素材說明】請直接上傳你的事實包，或把路徑替換成你自己的實際檔案路徑。

基於它寫一篇面向普通職場人和開發者的微信公眾號長文。

寫作目標：解釋 GLM-5.3-Flash 為什麼值得關注，以及普通人應該怎樣判斷它，
而不是複述發布會或媒體文章。

要求：
- 先確認讀者最關心的問題，再設計自然推進的結構。
- 只使用事實包中已經記錄的材料；官方自報跑分必須明確來源屬性，
  待確認內容不能寫成定論。
- 不編造「我親測了」「我採訪了」等個人經歷，也不仿寫原文句式。
- 保留必要的反方觀點和限制：模型實際表現會受推理框架、工具、參數和任務影響。
- 文風口語化、資訊密度高，像一個認真研究過的朋友在講清來龍去脈；
  不要寫空泛口號和模板化金句。
- 正文約 1800—2500 個中文字符，包含標題佔位、摘要、正文小標題、
  結尾判斷和來源清單。

把結果儲存為 Markdown 成果檔案，並建立一份新的飛書文件回傳連結。
先交人工編輯，不自動發布，不發送訊息，不修改其他線上文件。
```

它先讀事實包、確認讀者最關心的問題，再把文章定位成「專業解讀 + 判斷方法」，而不是從第一句就開始寫正文。成稿裡事實包的限制被保留：沒寫「能力等於 Opus」，只限定在某個綜合指數；沒把「1/40」當精確結論；國產晶片數量的口徑差異明確留在正文裡。

## 任務三：想要爆款標題，但也不能純標題黨

正文寫得再嚴謹，標題也可能在最後一分鐘把努力全毀掉。用「爆款標題與選題日曆」技能，先讓它讀取成稿、提煉新資訊和核心衝突，再生成標題，並加三條硬邊界：

```text
請使用「爆款標題與選題日曆」技能，讀取這份文章：
【素材說明】請直接上傳你的公眾號成稿，或把路徑替換成你自己的實際檔案路徑。

先概括文章真正的新資訊、最強證據、核心衝突和目標讀者，
再生成 20 個標題：事實型、問題型、反差型、結果型各 5 個。

硬性邊界：
- 不得加入正文沒有的數字、結論、人物背書或親測經歷。
- 不用故意製造誤解的半句話，不把廠商自報跑分包裝成獨立實測。
- 每個標題說明抓住了什麼，並標記誤導風險、行銷強度和適合場景。

最後推薦 3 個標題，分別說明更適合公眾號頭條、社群轉發還是搜尋流量；
再選出一個用於本次封面製作。把結果儲存為「標題候選與風險表.md」。
未經確認，不發布、不發送訊息、不修改線上文件。
```

它為每個標題標註「抓住了什麼、誤導風險、行銷強度、適用場景」——風險和標題放在同一張表裡，比事後憑感覺刪靠譜得多。實測推薦：頭條用「別人在傳 1/40 價格，正文裡寫的是 1/30 到 1/100」（反差型）、社群轉發用「官方說接近 Opus，傳播變成了持平 Opus」、搜尋流量用全參數寫法。

> 實話實說：所有 AI 起的標題都一般。更好的做法是平時**收集爆款標題形成標題庫**，讓 AI 知道什麼樣的標題是爆款再跑這個工作流；標題庫夠大，甚至可以用倉頡 Skill 蒸餾一套自己的下標題 Skill。

## 任務四：製作公眾號封面

封面最怕兩件事：只顧「科技感」滿屏機器人和電路板；標題沒定就畫圖，畫面和正文說的完全不是一回事。用「創意設計」能力，**把正文和標題風險表一起交給它**：

```text
請使用「創意設計」及圖片生成與檢查能力，讀取：
【素材說明】請直接上傳你的成稿和標題風險表，或把路徑替換成實際檔案路徑。
- 《公眾號成稿.md》
- 《標題候選與風險表.md》

為最終推薦標題製作微信公眾號頭圖。

先給出 3 個明顯不同的封面概念，每個說明主體、構圖、色彩、情緒、文字策略
以及它為什麼符合正文。然後選擇資訊最清楚、手機縮圖最容易識別的一版生成成圖。
```

視覺主題限定為「高能力與低成本之間的理性權衡」，配色只用深藍、冷白和少量亮綠；不用真人、品牌 Logo、機器人、密集電路板，也不在生成圖裡硬塞容易亂碼的中文。實測黑底 + 白色標題效果最顯眼；需要品牌元素（如智譜 logo）時，找張 logo 圖讓它融入即可。豆包工作內部整合了字節的 seedream 生圖模型，做封面完全夠用。

## 記住這條內容生產線

壓縮成一句話：**先收緊事實，再放開表達；先檢查標題，再放大傳播。**

```text
公開來源 → 事實包 → 公眾號正文 → 標題風險表 → 封面 → 人工複核
```

AI 不應該替你把每一個數字說得更響。真正省時間的，是它幫你把來源、邊界和中間成果接起來，讓後一步始終知道前一步已經確認了什麼、還沒確認什麼。這樣做出來的文章，也許沒有「一句話生成爆款」聽起來刺激，但更像真正能交給編輯、同事和主管的工作成果。

# 老同事的經驗別躺平：把飛書知識庫變成可重用 Skill

> 場景：知識庫裡躺著老同事攢下的營運經驗，沒人翻、沒人用。把經驗文件整理成可重用的 Skill，既減少重複整理，也讓 Agent 在實際任務中直接調用。

> 前置條件：豆包登入的帳號和要使用的飛書知識庫保持一致。

## 順手的知識庫接入方式

在豆包工作裡可以用 **@ 引用**飛書文件，也可以 @ 聯絡人、雲端硬碟檔案和對話，把相關內容載入為上下文。順帶一個實作彩蛋——引用聯絡人和會前文件後，一句話就能約會議：

```text
給我在飛書上約個會議，加上他 @聯絡人，
並把會前文件 @內部：小紅書營運知識經驗 發給他。
```

真的是動動嘴的事情。

## 打造經驗 Skill 的實作

**第一步先盲問**，確認豆包工作能否讀取目標知識庫：

> 你幫我看看，小紅書營運知識庫看得到嗎？

確認看得到之後，由於一開始還沒有明確的結構方案，先讓它根據知識庫內容給建議：

```text
將這個小紅書營運知識庫整理成一個「小紅書營運 Skill」，
把裡面的知識融合進 skill 裡面去，你會怎麼寫這個 skill？
```

它的定位建議很關鍵：現有技能裡已有 `doubao-newmedia-writing`（負責小紅書圖文/短影片的**內容創作**），這個新 Skill 應避開重複，定位為**營運全鏈路的方法論與 SOP**——當用戶問起號、定位、選題、標題封面、漲粉、變現、引流、開店、投放、違規申訴這類「營運怎麼做」的問題時觸發，輸出基於知識庫沉澱的結構化方法。

## Skill 目錄結構

明確職責邊界後，豆包工作把 Skill 拆成 `SKILL.md` 主檔案（觸發判斷 + 鏈路路由 + 工作流）和按六大主題分類的 `references` 資料目錄：

```text
xiaohongshu-operation/
├── SKILL.md                        # 觸發判斷 + 鏈路路由 + 工作流
└── references/
    ├── 01-起號定位/     # 賽道選擇、帳號定位、對標與 IP、主頁裝修
    ├── 02-平台機制/     # 演算法與流量、收錄與搜尋、限流與規則
    ├── 03-內容創作/     # 選題方法、標題公式、文案寫作、封面設計、拍攝修圖、影片剪輯
    ├── 04-漲粉營運/     # 養號流程、發布與維護、資料與復盤、漲粉技巧
    ├── 05-變現商業化/   # 變現方式、開店與選品、接單與合作、付費投放
    └── 06-引流與合規/   # 引流 SOP、私域營運、合規與資質
```

每個參考檔案都標註了來源（來自知識庫裡哪份課程或文件），保證知識可回溯。Skill 製作完成後，用一個實際營運問題測試，它就能按 Skill 裡沉澱的方法論作答——老同事的經驗從此不再躺平，而是變成每次任務都能調用的「標準做法」。

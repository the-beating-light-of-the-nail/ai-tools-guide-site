# 怎麼把老同事攢下的飛書運營經驗，變成每次任務都能直接調出來的標準做法？

你開啟飛書知識庫，看到裡面躺著老同事一條條攢下來的運營經驗。檔案不少，可真到要用的時候，你翻半天也拼不出一套能直接照著做的打法。經驗就在那兒，卻沒人翻、沒人用——這比沒有還讓人著急。這篇帶你把這份經驗整理成一個可複用的 Skill，以後遇到運營問題，讓豆包工作直接按老同事沉澱的方法去答，你少走一遍彎路。

> 場景：知識庫裡躺著老同事攢下的運營經驗，沒人翻、沒人用。把經驗檔案整理成可複用的 Skill，既減少重複整理，也讓 Agent 在實際任務中直接呼叫。

> 前置條件：豆包登入的賬號和要使用的飛書知識庫保持一致。

## 先把知識庫接進來

在豆包工作裡，你可以用 **@ 引用**飛書檔案，也能 @ 聯絡人、雲盤檔案和對話，把相關內容載入成上下文。順手一個省事的小招：你把聯絡人和會前檔案都引用進來後，一句話就能把會約了：

```text
給我在飛書上約個會議，加上他 @聯絡人，
並把會前檔案 @內部：小紅書運營知識經驗 發給他。
```

真的是動動嘴的事情，不用你再去翻通訊錄、貼檔案連結。

## 怎麼把經驗做成 Skill

你先別急著讓它整理，第一步先盲問一句，確認豆包工作到底能不能讀到你的目標知識庫：

> 你幫我看看，小紅書運營知識庫能看到嗎？

確認讀得到之後，你再讓它給方案——畢竟一開始你手上還沒有清晰的結構，不如先讓它根據知識庫內容提建議：

```text
將這個小紅書運營知識庫整理成一個"小紅書運營 Skill"，
把裡面的知識融合進 skill 裡面去，你會怎麼寫這個 skill？
```

它給的定位建議很關鍵。你要留意一點：現有技能裡已經有一個 `doubao-newmedia-writing`，專門負責小紅書圖文和短影片的**內容創作**。你的新 Skill 得避開這塊，定位成運營全鏈路的方法論與 SOP——當使用者問起號、定位、選題、標題封面、漲粉、變現、引流、開店、投放、違規申訴這類「運營怎麼做」的問題時觸發，輸出基於知識庫沉澱的結構化方法。

## Skill 長什麼樣

職責邊界定清楚後，豆包工作會把 Skill 拆成 `SKILL.md` 主檔案（觸發判斷 + 鏈路路由 + 工作流）和按六大主題分類的 `references` 資料目錄：

```text
xiaohongshu-operation/
├── SKILL.md                        # 觸發判斷 + 鏈路路由 + 工作流
└── references/
    ├── 01-起號定位/     # 賽道選擇、賬號定位、對標與 IP、主頁裝修
    ├── 02-平臺機制/     # 演算法與流量、收錄與搜尋、限流與規則
    ├── 03-內容創作/     # 選題方法、標題公式、文案寫作、封面設計、拍攝修圖、影片剪輯
    ├── 04-漲粉運營/     # 養號流程、釋出與維護、資料與復盤、漲粉技巧
    ├── 05-變現商業化/   # 變現方式、開店與選品、接單與合作、付費投放
    └── 06-引流與合規/   # 引流 SOP、私域運營、合規與資質
```

每個參考檔案都會標註來源——它來自知識庫裡哪份課程或檔案，保證知識可回溯。Skill 做完之後，你拿一個實際運營問題測一下，它就能按 Skill 裡沉澱的方法論作答。老同事的經驗從此不再躺平，而是變成每次任務都能呼叫的「標準做法」。

## 新手常見問題

**豆包工作能直接讀我的飛書知識庫嗎？**
能，但有個前提：你豆包登入的賬號，要和你用的飛書知識庫是同一個。賬號對不上，它讀不到內容，這一步你在開頭就確認好。

**為什麼不直接讓聊天豆包讀知識庫？**
聊天豆包是回答問題，它不會把經驗整理成可複用的結構。豆包工作能把檔案變成 Skill，以後每次觸發都按同一套方法論走，省得你反覆交代背景。

**新 Skill 和已有的內容創作技能會打架嗎？**
你要主動避開重複。已經有 `doubao-newmedia-writing` 管內容創作，你的新 Skill 就定位在運營全鏈路的方法論和 SOP，分工清楚才不混亂。

**做出來的 Skill 怎麼知道它真的能用？**
你拿一個真實的運營問題測一下就行。比如問起號或漲粉的具體做法，看它回的是不是基於你知識庫的方法，而不是泛泛而談。

**參考檔案會亂標來源嗎？**
每個參考檔案都標註了它來自知識庫裡哪份課程或檔案。你驗收時順著來源回去核對，知識可回溯，不怕它張冠李戴。

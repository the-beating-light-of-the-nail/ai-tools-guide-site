# 今天寫什麼拿不定？熱點、同行、產能三步串成一條能複用的選題線

你桌面上躺著二三十個題目，卻不知道今天先寫哪個——怕熱點是舊聞、怕同行拆解寫成低配復刻、怕選題攢出來了產能跟不上。這篇不讓你豆包工作直接「拍腦袋選題」，而是把真實流程分成三步，最後交到你手上的不只是一串題目，是一條能重複使用的內容生產線。

> 場景：桌面上躺著二三十個題目，卻不知道今天先寫哪個——怕熱點是舊聞、怕同行拆解寫成低配復刻、怕選題攢出來了產能跟不上。

你這一條生產線分三步：

1. 先做一份帶來源、帶時間的熱點早報；
2. 再挑一篇同行內容，拆解方法，不照抄內容；
3. 最後結合賬號定位和實際產能，把候選題排成一週能執行的行動日曆。

## 用到的 Skill 組合

| 任務 | 組合 | 為什麼這樣選 |
| --- | --- | --- |
| 當日熱點早報 | VOC 與輿情調研 + 公開網頁檢索 | 能篩選內容、溯源原帖，把舊聞和新報道分開 |
| 同行內容拆解 | 公眾號圖文與運營策略 + 連結讀取 + Lark Doc | 一次完成讀原文、事實驗真、結構拆解和飛書交付 |
| 本週選題排期 | 爆款標題與選題日曆 + Lark Doc | 不只給標題，還按讀者收益、可驗證性和執行成本排產能 |

## 任務一：熱點早報，別隻問「今天有什麼新聞」

你在「技能·連接器·夥伴」搜尋「VOC 與輿情調研」新增（注意：該 Skill 只適合網頁端和電腦端，手機上不會觸發）。只問「今天有什麼熱點」，AI 很容易把今天新發的舊聞塞進來——你要同時交代時間窗、信源順序、篩選標準和待核驗規則：

```text
我是一名科技 / AI 類公眾號編輯，今天需要為編輯部準備一份「AI 行業選題早報」。

請使用「VOC與輿情調研」技能及公開網頁檢索能力，檢索並核驗
【起始日期 00:00】至【今天當前時間】公開發布的 AI 行業資訊，重點關注：
- 大模型與 Agent 產品更新；
- AI 辦公、內容創作和開發者工具；
- 會真正影響普通職場人的新功能或變化。

請按下面的步驟處理：
1. 先說明本次檢索的截止時間和覆蓋範圍。
2. 區分「事件發生時間」和「文章釋出時間」，舊聞不得寫成今日新聞。
3. 合併同一事件的重複報道，優先使用官方公告、官方部落格或產品更新頁。
4. 篩選 5 條最值得編輯部關注的資訊，每條給出：事件、為什麼值得關注、
   可以怎麼寫、原始來源連結、時間依據、待確認點。
5. 最後只推薦 3 個最值得今天動手的選題，
   按「賬號匹配度、時效性、讀者收益、可驗證性」說明推薦理由。
6. 對不能確認的數字、價格、版本號和產品能力單獨標註，不要補寫或猜測。

最終交付一份結構清晰的中文 Markdown 早報，
包含「今日資訊表」「今日優先選題」和「待人工複核」三部分。

未經我確認，不要釋出內容，不要傳送訊息，不要修改線上檔案或資料。
```

你實測它會先確認北京時間和檢索視窗，再載入輿情能力、搜尋、核驗，最終交付約 20KB 的早報：5 條重點資訊 → 3 個優先選題 → 10 項寫作前必複核資訊，還抓出 4 條「文章近期出現、但事件不在時間窗內」的舊聞。你最容易翻車的情況是把其他媒體今天重發的舊聞誤寫成「產品今天剛釋出」——在提示詞裡把「事件發生時間」和「文章釋出時間」拆開，就能過濾掉。

> 你把早報當選題雷達，不要直接當成可釋出稿：所有帶「待確認」的價格、跑分、使用者量，正式寫作前都要回到官方來源再核一遍。

## 任務二：同行爆文，拆解而不照抄

你熱點早報裡出現一篇 36 氪的爆款文章。不是讓豆包工作「仿寫一篇」，而是把它當作同行樣本來拆。用「公眾號圖文與運營策略」技能（含選題、驗真、文章評估和運營復盤，成果先交付為飛書檔案）：

```text
我是一名科技 / AI 類公眾號編輯。請使用「公眾號圖文與運營策略」技能，
拆解下面這篇公開文章，但不要照抄文章表達：

文章連結：https://36kr.com/p/xxxxx

請按下面的順序處理：
1. 先讀取文章，列出實際讀取到的標題、作者 / 媒體、釋出時間和原始連結；
   讀不到的欄位標為「待確認」，不要猜。
2. 把文章中的「可核驗事實」和「作者的判斷 / 修辭」分開。
   涉及引數、價格、跑分、使用者量和效能對比時，說明原文依據是否足夠。
3. 從 6 個維度拆解它為什麼容易吸引點選和讀完：
   開頭鉤子、標題承諾、敘事結構、資訊密度、證據用法、結尾動作。
4. 輸出一張拆解表，每個結論都要帶文章中的位置依據或內容摘要；
   不要連續摘抄原文，不要複製有辨識度的句式。
5. 總結 5 個可以學的方法、3 個不能照搬的元素、5 個寫作前必須複核的事實。
6. 基於同一事件，給我的公眾號設計 3 個全新的選題角度，
   面向普通職場人和開發者，強調實測、教程或決策價值，不做同義改寫。
7. 做一次自檢：是否把作者觀點寫成事實，是否混淆文章釋出時間和事件發生時間，
   是否出現無法追溯的數字。

請將最終結果寫入一份新的飛書檔案，並返回可訪問連結。
未經我確認，不要釋出內容，不要傳送訊息，不要修改其他線上檔案或資料。
```

你最關鍵的是三句邊界：事實和觀點分開、每條結論給位置依據、不能連續摘抄——沒有這三句，拆解很容易變成高階一點的洗稿。你實測產出：13 項可核驗事實逐條判斷依據是否充分；8 處作者判斷或修辭單獨標出；6 維傳播拆解；5 個可學方法 + 3 個不能照搬元素 + 5 個必複核事實；3 個需要原創實測支撐的新選題。比如原文「價格只有 1/40」很有衝擊力，但輸入輸出如何加權並不明確——豆包工作沒有把這些數字當鐵證，而是留在複核清單裡。

你這一步回答三個問題：它憑什麼吸引人點開？哪些寫法可以學？哪些事實必須重新驗證？

## 任務三：把選題排成這週真正能做的

你有了熱點和拆解，還有個現實問題：時間不夠。用「爆款標題與選題日曆」技能，候選題之外一定要寫清真實產能：

```text
我負責一個科技 / AI 類公眾號，想把本週的候選題目排成一份真正能執行的內容日曆。

賬號定位：
- 面向想用 AI 提升工作效率的普通職場人和開發者；
- 主要寫 AI 工具實測、開源專案、保姆級教程和真實工作案例；
- 語氣口語化，強調「看完能照著做」，不寫空泛趨勢稿。

本週可用產能：
- 可以完成 5 篇公眾號圖文；
- 其中 2 篇可以完整實測並製作 6—10 張步驟截圖；
- 其他 3 篇需要控制在半天內完成。

候選題目：
1.【題目一】 2.【題目二】 ……（列出你的候選題）

請使用「爆款標題與選題日曆」技能，按下面的順序處理：
1. 先檢查輸入是否足夠，不足的地方列成待確認項，不自行編資料。
2. 給每個選題按 1—5 分評估：賬號匹配度、讀者獲益、時效性、可證明性、執行成本。
3. 結合產能選出 5 個選題，排入週一至週五，標明「深度實測」或「半天快寫」。
4. 每個選題給出：推薦理由、讀者收益、建議內容形式、需要準備的材料、
   一個主標題和一個 A/B 備選標題。
5. 對未入選的選題，說清「為什麼這週先不做」，不要用「不夠熱」一句帶過。
6. 做一次自檢：工作量是否超出產能，是否有兩篇以上搶同一類讀者需求，標題是否誇大。

請把最終結果寫入一份新的飛書檔案，並返回可訪問連結。
未經我確認，不要釋出內容，不要傳送訊息，不要修改其他線上檔案或資料。
```

你實測它會先檢查當天日期、候選題和產能——因為實測當天是週四，它把「本週」解釋為下一個完整工作周，並把這個假設寫進待確認項等你確認。最終排期 2 個深度實測 + 3 個半天快寫；兩個落選選題的原因也很具體：一個需要 1—2 周深度測試當前產能不夠，另一個偏運營方法、與賬號核心讀者不夠貼。它還主動留下 4 個待確認項（排期起點、釋出時間、標題裡真實經歷能否成立、工具數量承諾是否實測過）。

## 記住這套提示詞骨架

你換成法務、HR、銷售、產品經理也能直接套這四層：

1. 先寫清角色和受眾：你是誰，內容給誰看；
2. 再寫清約束：時間窗、產能、資料權限、不能做什麼；
3. 規定判斷標準：匹配度、收益、時效、證據、成本；
4. 要求留下複核清單：哪些是事實、哪些是假設、哪些數字還不能寫。

你 AI 真正好用的地方，是把 30 個候選篩到 3 個，並告訴你為什麼是這 3 個、今天先做哪個、寫之前還要複核什麼——這才是內容團隊能落地的「今天寫什麼」。

## 常見問題

**只問「今天有什麼熱點」不行嗎？**
你最好別。AI 容易把今天重發的舊聞塞進來。把「事件發生時間」和「文章釋出時間」拆開、寫清信源順序和待核驗規則，舊聞才過濾得掉。

**同行爆文能直接仿寫嗎？**
你別照抄。把它當樣本拆：事實和觀點分開、每條結論給位置依據、不能連續摘抄——少了這三句，拆解就變成高階洗稿。

**產能寫不寫都行吧？**
你一定要寫。不寫產能，排出來的日曆你這週根本做不完。把候選題和「深度實測 / 半天快寫」一起排，落選的也要說清為什麼這週先不做。

**早報能直接當稿子發嗎？**
不能。你把它當選題雷達：帶「待確認」的價格、跑分、使用者量，正式動筆前都要回官方來源再核一遍。

**選題骨架能套到其他崗位嗎？**
能。你換成法務、HR、銷售、產品經理，照樣是四層：角色受眾、約束、判斷標準、複核清單。AI 的價值是把候選篩到少數幾個，並說清今天先做哪個。

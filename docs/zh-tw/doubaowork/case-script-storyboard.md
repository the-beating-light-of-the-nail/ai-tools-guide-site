# 公眾號長文怎麼變成能拍的短影片？兩段式拆解，口播和分鏡一次到位

你寫完一篇公眾號長文，領導順手來一句「改成一分鐘影片，今天拍出來」。你照著文章念是最省事也最糟的做法——文章為了講透，短影片為了讓人看完。就算你把口播寫順了，鏡頭表裡寫滿「配相關畫面」「這裡加 B-roll」，攝影和剪輯還是不知道拍什麼。你用兩個任務，把長文變成能直接照著拍的東西。

> 場景：公眾號文章寫完，領導順手一句「改成一分鐘影片，今天拍出來」。照著文章念是下策——文章為了講透，短影片為了讓人看完；就算口播寫順了，鏡頭表裡寫滿「配相關畫面」「這裡加 B-roll」，攝影和剪輯還是不知道拍什麼。

你拿一篇已經核驗過的長文，在豆包工作裡連續跑兩個任務：

```text
已核驗長文
→ 改成 60—75 秒自然口播
→ 人工確認口播事實和節奏
→ 拆成 9 個連續鏡頭
→ 補齊動作、景別、螢幕文字、素材狀態
→ 最後檢查版權、隱私和事實邊界
```

你跑完會拿到一份約 290 字、正常語速 65—70 秒的口播稿，和一份 68 秒、9 個鏡頭的分鏡執行表。

工具選擇：新媒體寫作 Skill 做口播（明確覆蓋短影片指令碼，擅長口語節奏、開頭和聽覺理解）；創意影片 Skill 做分鏡（離真實拍攝更近，能把機位、動作、B-roll、聲音和剪輯要求拆開）。你最好把兩個任務分開——先人工確認口播，再開新任務拆分鏡，分鏡只圍繞定稿安排畫面，不會邊拆鏡頭邊改事實。你如果想補 AI 素材，可以選配 Seedance 2.5 影片生成。

## 任務一：先把長文改成「能說出口」的口播

你如果只寫「把這篇文章改成一分鐘口播」，AI 最容易做的就是刪字。你要把五件事寫清：說給誰聽、講多久、只保留什麼、什麼絕對不能改、按什麼格式交付：

```text
請使用「新媒體寫作」能力，把下面這篇已經核驗過的長文改成一段可以直接對鏡頭說的
短影片口播稿。

目標：
- 平臺：影片號 / 抖音都能使用
- 時長：60—75 秒
- 受眾：企業裡的普通打工人、內容運營新手
- 只講一個核心問題：【在這裡寫核心問題】
- 只保留一條清晰結論和一個容易聽懂的例子
- 開頭 5 秒內進入問題，不用"震驚""一定要"等誇張鉤子
- 句子要短，像真實的人在說話，不要論文腔
- 必須保留原文裡的關鍵限制條件，不能把有條件判斷改成絕對承諾
- 標註建議停頓【停頓】和需要重讀的詞【重讀】
- 不要生成分鏡、鏡頭或字幕檔案
- 不要補寫原文沒有的數字、案例和結論

請按以下結構輸出：
1. 核心資訊取捨：用 3 行說明保留了什麼、刪掉了什麼、為什麼
2. 最終口播稿：可直接照著念，約 260—320 字
3. 簡介補充資訊：列出 2—3 條不適合塞進口播、但值得放在影片簡介裡的邊界資訊

原始長文：
【把你的已核驗長文完整貼上在這裡；或上傳檔案後寫：只讀取《檔名》】
```

你實測結果：第一句就丟擲大家最關心的問題（「很多人做一稿多發，就是把公眾號文章複製到小紅書……」），中間只保留一個對比例子，並主動保住最危險的一句——原文說「在資訊完整、事實已核驗的前提下可以提效」，不能改成「用 AI 一定能提效」。全文約 290 字、估算 65—70 秒，標了停頓和重讀位置。

> 你判斷口播能不能用，最笨也最有效的方法：自己完整念一遍。凡是需要回頭看上一句才明白的地方，都要重新改。

## 任務二：口播確認後，拆成真正能拍的分鏡

分鏡最怕脫離現實：你只有一部手機，就別讓它設計三機位軌道鏡頭；你只有自己拍的素材，就別讓它預設用影視片段和相簿。普通人第一次拍口播，你用手機 + 三腳架 + 安靜的房間就能開錄。

> 你做任何形式的自媒體，一開始都要極致輕量化，把大部分精力放在選題與標題（短影片就是開頭）上。每次投入夠少、又在做正確的事，才堅持得下去，也更容易進入正反饋迴圈。

你要把條件寫死：9:16 豎屏、一位職場人在辦公桌前、手機加三腳架，可用素材只有本人正面口播、手部操作、文章錄屏和自制關鍵詞卡片：

```text
請使用【創意影片】能力，把下面這份已經確認的口播稿拆成一份可以直接照著拍的分鏡執行表。
只做拍攝與剪輯方案，不要生成實際影片，也不要生成字幕檔案。

成片條件：
- 比例：9:16 豎屏；總時長：65—70 秒
- 場景：一位職場人在辦公桌前對鏡口播
- 可用裝置：手機、三腳架、筆記型電腦
- 已有素材：本人可拍的正面口播、手部操作電腦、文章頁面錄屏、自制關鍵詞卡片
- 不使用未經授權的相簿、影視片段或他人賬號截圖
- 節奏：清楚、剋制、像實用教程，不要快切炫技

執行要求：
1. 按 0—5 秒、5—12 秒這類連續時間段拆成 8—10 個鏡頭，
   時間總和必須覆蓋 65—70 秒，不能重疊、不能留空。
2. 每個鏡頭都給出：對應口播原句、人物動作、景別、機位 / 構圖、螢幕文字、
   B-roll 或截圖、轉場、聲音要求。
3. 螢幕文字只保留關鍵詞，每屏不超過 12 個漢字，不能把整段口播再貼一遍。
4. 不要寫"配相關畫面"這種空話，要明確拍什麼、螢幕錄什麼、文字放哪裡。
5. 標出每項素材狀態：【已有】【需補拍】【需製作】【需確認版權】。
6. 不改寫口播裡的事實和邊界，尤其要保留原稿的限制條件。
7. 最後附一份按拍攝順序整理的拍攝清單，和按時間順序整理的剪輯檢查清單。

請按以下結構輸出：
A. 拍攝設定（機位、光線、收音、背景）
B. 逐秒分鏡執行表
C. 拍攝清單
D. 剪輯檢查清單
E. 版權與隱私檢查

已確認口播稿：
【把上一輪人工確認後的完整口播稿貼上在這裡】
```

它先按口播字數和停頓估算每段時長，再拆鏡頭——你記住先算時長再拆很重要：先寫 9 個鏡頭最後硬湊時間，最容易出現口播念不完或中間空出五秒。你實測時間線（9 段相加正好 68 秒，無空擋無重疊）：

| 時間 | 畫面任務 |
| --- | --- |
| 0—7 秒 | 中近景說出"複製貼上式一稿多發"，右手敲桌面三次 |
| 7—13 秒 | 近景強調"省時間不等於有效果" |
| 13—21 秒 | 插入手部滾動文章，解釋平臺閱讀方式不同 |
| 21—30 秒 | 文章錄屏對比"公眾號順著看、影片號聽你說" |
| 30—37 秒 | 拿起"結構"卡片，強調改的是表達結構 |
| 37—49 秒 | 錄屏展示"背景/測試/結論" vs "問題/結論/例子" |
| 49—58 秒 | 用"有條件/絕對化"卡片守住事實邊界 |
| 58—63 秒 | 近景強調"有條件判斷不能變成絕對承諾" |
| 63—68 秒 | 拉遠收尾，桌面全景定格 |

結果最後還有三個兜底清單：按拍攝順序安排先拍什麼、按時間順序檢查怎麼剪、版權與隱私怎麼查。

> 你分鏡寫得越詳細不代表越專業。真正有用的分鏡，是拍攝的人今天拿到，能立刻列出「已有、要補拍、要製作、要確認版權」的清單。

## 記住這套兩段式公式

長文轉口播你寫清：誰聽、在哪個平臺聽、要聽多久；只講哪個問題、只保留哪條結論；哪些限制條件不能刪；哪些內容移到簡介；輸出要有停頓、重讀和字數檢查。

口播轉分鏡你寫清：裝置、場景、比例和已有素材；時間段連續且合計等於總時長；每個鏡頭有動作、景別、機位、文字、素材和聲音；每項素材標狀態；最後查版權、隱私和事實邊界。

長文、口播和分鏡是三種不同的東西：長文負責把事情說完整，口播負責讓人一遍聽懂，分鏡負責讓現場真的拍得出來。你拆成兩次任務，不僅更容易得到好結果，也更容易在每一步發現：到底是內容有問題、表達有問題，還是拍攝執行有問題。

## 常見問題

**口播和分鏡能用同一個提示詞一次跑完嗎？**
最好別。你先人工確認口播，再開新任務拆分鏡，分鏡只圍繞定稿安排畫面，不會邊拆鏡頭邊改事實。混在一起容易把結論改歪。

**分鏡裡寫「配相關畫面」為什麼不行？**
太空。你要把條件寫死——拍什麼、螢幕錄什麼、文字放哪裡，攝影和剪輯才看得懂。

**事實邊界怎麼守住？**
你讓它在口播和分鏡裡都保留原稿的限制條件，尤其不能把「有條件判斷」改成「絕對承諾」。原文說「在資訊完整、事實已核驗的前提下可以提效」，就不能寫成「用 AI 一定能提效」。

**我沒有專業裝置能拍嗎？**
能。普通人第一次拍口播，你用手機 + 三腳架 + 安靜的房間就能開錄。你只要把裝置、場景和已有素材交代清楚。

**時間線總對不上怎麼辦？**
你記住先算時長再拆鏡頭。先寫 9 個鏡頭最後硬湊時間，最容易出現口播念不完或中間空出五秒。

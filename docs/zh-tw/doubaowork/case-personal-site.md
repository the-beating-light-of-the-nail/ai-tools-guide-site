# 想做個人網站卻總在「等準備好」？設計驅動的建站法，半天做出真正像你的站

你盯著建站工具發呆，照片還沒挑好、專案介紹沒寫完、一句自我介紹改了好幾遍。這種「等準備好了再做」的狀態很常見，讓你遲遲開不了頭，網站永遠停在腦子裡。其實可以先換一個問題問起：你希望誰看到這個網站、他看完記住什麼、又願意接著做什麼？把這幾件事說清，內容和設計就有了方向，不用等所有材料齊全。

> 場景：想做個人網站，卻一直卡在「等準備好了再做」——照片沒挑好、介紹沒寫完。換個起點：先說清楚你是誰、網站為什麼存在。

## design-led-website-builder 在解決什麼

你想做網站，AI 很容易先給你一個「能開啟」的網頁。真正的麻煩在後面：它也容易生成一個換掉名字以後還能交給任何人的網頁——白底、通用字型、幾張等寬卡片，頁面看著完整，卻沒什麼屬於你的東西。填半天內容，結果出來還是像模板。

`design-led-website-builder` 這個 Skill 把設計研究放在寫程式碼之前，完整流程七步、順序固定：

1. 它先接收你已提供的材料，判斷這是現成品牌、零散個人內容，還是一個參考網站；
2. 鎖定網站用途（閱讀歸檔為主的出版型，還是強調作品氣質的視覺型）——需求確實有分叉時，只問你一輪，選定後再繼續；
3. 研究 3—5 個用途相近的真實網站，研究物件跟著網站任務走，不會拿炫技作品集去指導需要長期閱讀的部落格；
4. 尋找 3—8 份可用素材（紙張、木紋、插畫、公開授權照片、氛圍圖）；真實頭像、作品、客戶案例和成績，只能用你提供或確認過的內容；
5. 用一小段話說明設計方向、參考網站、已找到的素材、不會照抄的部分，以及接下來準備實現什麼；
6. 開始搭建：先確定字型、顏色、間距、圖片裁切和互動規則，再落實到頁面；
7. 完成檢查：首屏要讓人很快看懂這是誰的網站、這裡有什麼、下一步能做什麼；移動端、鍵盤操作、動效降級、圖片來源和頁面效能也在檢查範圍內。

你拿到成品前可以先想清楚：參考網站只用來理解層級、排版、圖片裁切和互動，不能直接複製有辨識度的佈局與素材；生成的圖片能負責氣氛和插畫，但不能冒充你的照片、產品介面、客戶或獎項。

## 安裝並跑一遍

你直接告訴豆包工作把 Skill 裝上：

```text
請安裝這個個人網站設計 skill：
https://github.com/liucongg/liucong-skills/tree/main/skills/design-led-website-builder
```

然後你一句話開工（提示詞裡交代了人和目的，Skill 可以直接進入研究階段）：

```text
$design-led-website-builder 我想製作一個自媒體博主的個人網站，
我全網 ID 都是劉聰NLP，主要想展示我之前分享的一系列文章內容。
```

如果你只寫「幫我做一個個人網站」，它會先判斷可能的幾種產品形態，再用一輪問題請你鎖定方向。

## 部署到 GitHub Pages

網站做好後，你一句話部署：

```text
幫我把這個網站，通過 GitHub 部署到 GitHub Pages 中。
```

你沒登入 GitHub 的話會先引導登入，隨後自動完成部署——從設計研究到上線，全程不需要寫一行程式碼。

## 常見問題

**它真能做出不像模板的網站嗎？**
能，前提是你開頭把「誰看、記住什麼、接著做什麼」說清。它先研究真實網站再做設計，而不是套一套現成佈局。你提供的頭像、作品和成績，也只能用確認過的，不會拿生成圖冒充。

**我完全不會寫程式碼能搞定嗎？**
能。從裝 Skill、開工到部署 GitHub Pages，都是一句話交代。你全程只在開頭說清需求、最後驗收，不需要碰程式碼。

**參考網站會被直接抄過去嗎？**
不會。參考網站只用來理解層級、排版和互動，有辨識度的佈局和素材不能照搬。生成圖也只能做氣氛和插畫，不能當你的照片或客戶案例。

**GitHub Pages 部署要我自己配倉庫嗎？**
不用。你一句話讓它部署，沒登入會先引導登入，之後自動完成。最後拿到一個能訪問的連結就行。

**提示詞只要寫一句話就夠嗎？**
開頭可以。但你交代得越具體——身份、想展示什麼、全網 ID——它越能直接進研究階段，少問一輪。只寫「幫我做網站」也行，它會先和你確認方向。

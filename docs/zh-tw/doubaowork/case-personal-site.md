# 用一個精美的個人網站包裝你自己

> 場景：想做個人網站，卻一直卡在「等準備好了再做」——照片沒挑好、介紹沒寫完。換個起點：先說清楚你是誰、網站為什麼存在。

想做個人網站的人，常常卡在第一步：照片還沒挑好、專案介紹沒寫完、一句自我介紹都要改好幾遍。其實可以先從一個更簡單的問題開始——**你希望誰看到這個網站，他看完以後記住什麼，又願意繼續做什麼？**把這幾件事說清楚，內容和設計就有了方向。

## design-led-website-builder 在解決什麼

AI 很容易生成一個「能打開」的網頁；真正麻煩的是，它也很容易生成一個**換掉名字以後還能交給任何人**的網頁——白底、通用字體、幾張等寬卡片，頁面看著完整，卻沒有多少屬於你的東西。

`design-led-website-builder` 這個 Skill 把**設計研究放在寫程式之前**，完整流程七步、順序固定：

1. 接收你已提供的材料，判斷是現成品牌、零散個人內容，還是一個參考網站；
2. 鎖定網站用途（閱讀歸檔為主的出版型，還是強調作品氣質的視覺型）——需求確實有分叉時，只問一輪，選定後再繼續；
3. 研究 3—5 個用途相近的**真實網站**，研究對象跟著網站任務走，不會拿炫技作品集去指導需要長期閱讀的部落格；
4. 尋找 3—8 份可用素材（紙張、木紋、插畫、公開授權照片、氛圍圖）；**真實頭像、作品、客戶案例和成績只能使用你提供或確認過的內容**；
5. 用一小段話說明設計方向、參考網站、已找到的素材、不會照抄的部分，以及接下來準備實現什麼；
6. 開始搭建：先確定字體、顏色、間距、圖片裁切和互動規則，再落實到頁面；
7. 完成檢查：首屏要讓人很快看懂這是誰的網站、這裡有什麼、下一步能做什麼；行動裝置、鍵盤操作、動效降級、圖片來源和頁面效能也在檢查範圍內。

參考網站只用來理解層級、排版、圖片裁切和互動，不能直接複製有辨識度的版面與素材；生成圖片可以負責氣氛和插畫，不能冒充你的照片、產品介面、客戶或獎項。

## 安裝並跑一遍

直接告訴豆包工作把 Skill 裝上：

```text
請安裝這個個人網站設計 skill：
https://github.com/liucongg/liucong-skills/tree/main/skills/design-led-website-builder
```

然後一句話開工（提示詞裡交代了人和目的，Skill 可以直接進入研究階段）：

```text
$design-led-website-builder 我想製作一個自媒體博主的個人網站，
我全網 ID 都是劉聰NLP，主要想展示我之前分享的一系列文章內容。
```

如果只寫「幫我做一個個人網站」，它會先判斷可能的幾種產品形態，再用一輪問題請你鎖定方向。

## 部署到 GitHub Pages

網站做好後，一句話部署：

```text
幫我把這個網站，透過 GitHub 部署到 GitHub Pages 中。
```

沒登入 GitHub 的話會先引導登入，隨後自動完成部署——從設計研究到上線，全程不需要寫一行程式。

# Skill 怎麼挑、怎麼用？一次看懂它替你省在哪

你大概聽同事說過「裝個 Skill 就好用了」，可你點開技能市場，滿屏分類看不懂：金融、法律、新媒體創作……你也不知道哪個跟自己有關。更懵的是，它明明叫「技能」，到底和你在聊天框裡敲的那段提示詞差在哪？這一篇就說清兩件事：它是什麼、你該怎麼挑著用，順帶讓你看懂它為什麼能替你省掉反覆叮囑的功夫。

豆包工作自己負責聽懂你的任務、安排執行；而 Skill 是一包可以反覆用的東西——說明、指令碼、參考資料、素材都在裡面——它告訴 Agent 某類活該怎麼做、調什麼工具、交什麼格式。這套思路來自 Anthropic：2025 年 10 月推出 Agent Skills，12 月開放成標準，現在不少產品都跟著做。

## 一個標準 Skill 長什麼樣

它本質上是個資料夾，裡面不一定全要，但有一份是命根子：

```text
my-skill/
├── SKILL.md          # 唯一必需的檔案
├── scripts/
│   └── check.py
├── references/
│   └── guide.md
└── assets/
    └── template.pptx
```

只有 `SKILL.md` 少不了，核心就是一段「這類活怎麼做」的說明，你讀一眼就懂它在管什麼：

```markdown
---
name: tech-article-writing
description: 用于撰写 AI 产品、模型评测和科技行业相关文章
---

收到写作任务后：

1. 先确认文章核心角度
2. 查找一手资料
3. 对核心事实交叉验证
4. 根据用户写作风格完成初稿
5. 检查禁用句式和 AI 味表达
```

## 它幹活的方式：用到才翻開

Skill 最巧的不是這份說明本身，而是「漸進式披露」。你想，Agent 裝了一百個 Skill，要是把一百份全文全塞進上下文，既燒你的 Token，又讓模型被無關指令帶偏。標準做法是三層：

1. 啟動的時候，只加載每個 Skill 的名字和 description，每份也就幾十到一百來個 Token；
2. 任務對上了，才載入完整的 `SKILL.md`——比如你說「幫我寫一篇豆包工作的公眾號文章」，Agent 看 description 認出 `tech-article-writing` 相關，這時才讀全文；
3. 幹到細處，才繼續讀 `references/style.md`、跑 `scripts/check-ai-phrases.py`。

OpenAI 的 Codex 也是類似機制。所以它解決的是個老難題：怎麼給 Agent 塞很多知識和工作方法，又不把所有東西永遠壓在你的每次 Prompt 裡。

## 它替你乾的四種事

**1 · 補上只有你們公司才懂的知識。** 大模型懂的通用知識多，但你公司的事它未必知道：`canonical user_id` 在哪張表、`subscriptions` 表是 append-only、查退款要排除某個狀態、Grafana 對應哪個 dashboard ID。Anthropic 內部幾百個 Skill 主要集中在九類：API 與內部庫使用、產品驗證、資料分析、業務流程自動化、程式碼腳手架、程式碼審查、CI/CD、故障 Runbook 和運維。

**2 · 把複雜流程固定下來。** 普通提示詞說「詳細調研一下豆包工作」，模型每次得現想：去哪找、先查啥、怎麼驗、跟誰比、出什麼結構。Skill 把流程釘成：官網 → 官方公眾號和釋出會 → 產品檔案 → 實際產品測試 → 同類產品對比 → 核心觀點提煉 → 事實核驗。這種叫 Encoded Preference Skill（按你的工作方式組織既有能力）；另一種 Capability Uplift Skill 補的是模型本來做不好或不穩的能力，比如複雜檔案、PDF 和 PPT 處理。

**3 · 不用反覆叮囑同一句話。** 你總得嘮叨的「別寫太 AI、長短句結合、別堆點列、技術內容克制、別編例子」，天然適合做成一個 `writing-style` Skill。以後你寫提示詞只寫一句「寫一篇豆包工作文章」，寫作習慣、資料標準、停用表達都由 Skill 兜著。

**4 · 把經驗變成能管的資產。** 以前你的提示詞散在聊天記錄、檔案、個人腦子裡；Skill 是檔案，能進 Git、回滾版本、團隊共享、做 A/B、自動評測、持續更新。

## 在豆包工作裡怎麼找 Skill

你開啟左側「技能·連接器·夥伴」，按金融、法律、新媒體創作、辦公協作、程式設計、學術這些分類翻，也能在頂部搜尋框按名字或需求搜。看中了點右側「+」加上；部分技能支援「在對話中試用」。加過的統一在「我的技能」裡管。

你也能自己建或傳一個：點頁面右上角「新建」，選「與豆包對話新建技能」或「上傳技能」。傳之前你先看清這包技能從哪來、指令碼幹啥、權限範圍到哪。

## 用它跑通一個任務

比如你的文章要去 AI 痕跡：你在技能市場搜「去 AI 味」，加上後回到工作任務，在輸入框敲 `/` 或點「更多技能」選中它，把文章和具體要求附上。豆包工作會照技能說明自己排步驟，還把執行過程和結果攤給你看。

交回來後你重點核三件事：指定句式刪乾淨沒、事實和語氣保住沒、專有名詞有沒有被它順手改錯。

## 新手常見問題

**Skill 和我在聊天框寫的提示詞，到底差在哪？**
提示詞是你一次性交代；Skill 是把「這類活怎麼幹」存成檔案，以後你一句話就能調，還能團隊共享、版本管理。臨時問一句用提示詞，反覆要乾的活才值得做成 Skill。

**我裝了一堆 Skill，會不會把上下文撐爆？**
不會。它用到才翻開：啟動只記名字和簡介，任務對上了才讀全文，幹細處才讀參考資料、跑指令碼。這就是漸進式披露，Token 花在你的刀刃上。

**找不到現成技能，能自己做一個嗎？**
能。你點右上角「新建」，跟豆包對話生成，或上傳現成技能包。傳之前你看清來源、指令碼和權限範圍，別把來路不明的包接進來。

**加完技能，怎麼確認它真按要求做了？**
你回工作任務裡調起它、附上材料，交回來後逐條核：指定句式刪沒刪、事實語氣留沒留、專有名詞改沒改。別隻看它自己寫的「已完成」，你親自過一遍才穩。

**「我的技能」在哪看，會不會加亂了？**
加過的統一在「我的技能」裡管理，你隨時能停用或刪。市場裡點「+」是新增，頁面右上角「新建」才是自己造，兩處你別搞混。

# 来源清单怎么读才不张冠李戴？给你 R1–R15 的核验边界

## 白话导读

你引用本蓝皮书的产品事实或案例结论时，最怕来源说不清、边界对不上。这份附录把 R1–R15 全部公开来源列出来，并标了访问日期和核验边界，你写报告、做决策时照着引用就不会张冠李戴。你在什么场景翻它、每条怎么读、链接失效怎么办，下面讲清。

## 这份附录给谁用，什么时候该翻它

产品界面、价格、权益、模型列表、可用地区与连接器范围更新较快，应以使用时的官方页面为准。你引用 R2、R3、R12 里的价格或连接器范围时，若照搬访问日数据，可能和当前页面不一致。你读到带【访问于】的条目，就以该日期的快照理解，落地前你再核一次官方页。

## 每条来源怎么读，读错了会怎样

你逐条读来源时，先看类型：R1 是方法参考（MIT 许可），R2–R9、R12–R13 是官方页面，R10–R11 是阿里知识库。你若把社区知识库当官方承诺，会高估产品能力；你若漏看【访问于】日期，会把旧快照当现状。每条的局限都写在正文里，你引用前读完，别只抄标题。

## 常见问题

**你引用本蓝皮书时，应该按哪条来源标注？**
按正文中方括号编号对应的 R 条目标注，例如产品简介引 R3、连接器引 R4。你别把社区知识库 R10、R11 当官方承诺来写，它们只用于理解定位，实际能力以账号实测和官方页为准。

**你看到正文写 R14 或 R15，该去哪里找原文？**
R14、R15 是兼容重定向，分别指向 R8（技能）和 R4（连接器），不是独立来源。你引用时直接标 R8 或 R4，别让编号看起来多出来两条。

**链接打不开或页面改版了，你怎么办？**
先按条目里的【访问于】日期理解当时快照，再打开官方页核当前版本。你若发现价格、权益或连接器范围和访问日不一致，以使用时页面为准，并在引用处注明核对日期。

**你做案例结论时，R11 能给到你什么、给不到什么？**
R11 帮你核验案例名称、任务标签、角色标签和公开产物链接；它多数条目未披露客户名称或量化成效。你别从案例库反推「效果数据」，没有公开量化的，就只写到「形态可证」这一层。

# 可复用资产：Skill（技能）、连接器与专家套件

## 白话导读

这一章帮你把团队里混在一起的三样东西拆开：做法、权限、岗位包。你每周按同一套规则做经营复盘时，常把提示词、账号连接和岗位知识塞进同一个「智能助手」，一出错你就分不清该改方法、收权限还是补标准。本章把 Skill（做法）、连接器（授权通道）、专家套件（岗位任务包）分开管，各自有 Owner、版本和测试样本。你读完就知道：哪类资产你能共享、哪类碰了权限就得单独审。

## 30 秒结论

<span id="claim-skill-asset-boundary-01" data-claim-id="claim-skill-asset-boundary-01"></span>本书将 Skill 定义为封装可重复方法和工具步骤的版本化资产；它解决“这件事按什么步骤做”，不自动取得数据权限，也不替代专业验收。

白话解释：这条边界为什么这么定？你容易以为有了 Skill 就能自动读数据，其实 Skill 只管步骤，权限要你另外申请。你混在一起，共享时就会把个人权限和未验证步骤一并扩散出去。

- 连接器规定经授权的数据和动作边界，不承载完整业务方法。
- 专家套件组合多个已发布工作流和岗位标准，不是若干提示词的打包。
- 三类资产都必须有负责维护和确认这套资产的人（Owner）、版本、输入输出、测试样本、权限说明和发布门。

## 你可能遇到的场景

你每周都要按同一套规则整理经营复盘，常用资料来自项目台账，结果还要交给负责人确认。输入例子是“本周台账、上周模板、异常规则和待办草稿位置”。这时可以把可重复使用的一套做法（工作流）整理出来，把能把资料送到另一个工具的授权通道（连接器）和组合好的任务包（专家套件）分开管理。

白话解释：你从这里开始分——做法是做法，通道是通道，包是包。把三者分开，哪天连接器失效，你方法资产还能降级到人工喂数据，不会静默产出半截结论。

## 你会拿到什么

最终产物是一份可复用资产登记包，结构为：

1. 方法资产：步骤、判断规则、输入输出和版本；
2. 授权通道：系统对象、读写范围、凭证归属、有效期和动作确认；
3. 任务包：已通过验收的工作流、岗位标准和专业 Owner；
4. 测试与发布记录：正常、缺失、冲突、越权样本，以及上一稳定版本。

## 照着做

1. 先把一次成功任务拆成可重复步骤、判断规则和交付格式，标为 Skill（技能）候选，不把个人提示词直接共享。
2. 再列出每个资料来源和动作，单独申请最小必要的连接器授权；连接成功不代表自动拥有完整读写权限。
3. 中间检查点：让工作流 Owner、系统或数据 Owner、专业质量 Owner 分别确认方法、权限和责任边界。
4. 用正常、缺失、冲突和越权输入测试；只有通过发布门的资产才能组合进专家套件或团队流程。

白话解释：第 2 步最容易被你忽略——「连上了」不等于「能读写」。连接器只给授权范围内的边界，你别因为显示已连接就默认拥有全部权限，越权申请是发布停止信号。

## 案例参考

可先看[品胜电子：竞品调研与产品物料制作](/qwenwork/case-pisen)，你把它当成“方法步骤”和“资料授权”需要分开的例子；案例本身不能证明连接器已有权限或可以直接复用。

## 做完检查

逐项核对资产登记包：必须能指出当前版本、最小权限、四类测试样本、Owner 和上一稳定版本；缺一项就只能个人使用或受控试点，不能发布。

白话解释：你这条检查卡的是「能不能审计」。指不出当前版本、最小权限、四类样本和 Owner，资产就只能你个人用，不能往团队发——因为出错没人知道回到哪一版、谁负责。

## 需要注意

如果连接器失效、权限超范围或测试失败，保留原始资料和失败版本，停止正式写入或外发，回到上一稳定版本；改由人工提供输入或做只读分析，并由系统 Owner 和专业 Owner 确认后再恢复。

白话解释：你遇连接器失效、权限超范围或测试失败时，先停正式写入或外发、留原始资料和失败版本，回到上一稳定版。你改人工喂输入或只读分析，让系统 Owner 和专业 Owner 确认后再恢复。

## 为什么重要

团队常把提示词、账号连接和岗位知识混在一个“智能助手”中。出现错误时，你无法判断应该改方法、收紧授权，还是更新专业标准；共享时你也容易把个人权限和未验证步骤一并扩散。

清晰的资产边界让企业分别管理内容质量、系统权限和岗位责任。它也决定复用是否可审计：谁批准了哪个版本，使用了哪些测试样本，能访问什么数据，失败后回到哪里。

## 方法或模型

| 资产 | 规范定义 | 适用条件 | 主要 Owner |
|---|---|---|---|
| Skill | 封装可重复方法、工具步骤、判断规则和交付格式 | 同类任务输入稳定，步骤可测试，失败可识别 | 工作流 Owner |
| 连接器 | 提供经授权的数据读取或动作调用边界 | 系统对象、账号、权限和读写范围明确 | 系统 Owner、数据 Owner |
| 专家套件 | 组合多个已发布工作流、岗位知识和专业标准 | 岗位任务链稳定，组成资产已通过阶段门 | 岗位负责人、专业质量 Owner |

白话解释：你记这张表就看「Owner 那列」——Skill 归工作流 Owner，连接器归系统/数据 Owner，专家套件归岗位和专业质量 Owner。三者责任人不同，正是为了分开管方法、权限和标准。

每项资产都用同一发布合同登记：

| 字段 | 必填内容 | 发布前证据 |
|---|---|---|
| Owner | 对结果、权限或专业标准负责的具体角色 | 责任确认和升级联系人 |
| 版本 | 版本号、变更内容、兼容范围和回退版本 | 变更记录、可恢复的上一版本 |
| 输入输出 | 输入字段、可信范围、输出格式和保存位置 | 合法样本、缺失样本、产物示例 |
| 测试样本 | 正常、边界、冲突和失败样本 | 测试记录、人工修改和未通过原因 |
| 权限 | 数据对象、读写范围、凭证归属和有效期 | 授权记录、最小权限检查 |
| 发布门 | 当前阶段、通过条件、停止条件和批准人 | 阶段评审记录和发布决定 |

<span id="claim-connector-authorization-01" data-claim-id="claim-connector-authorization-01"></span>连接器的产品作用是连接外部数据或工具；实际可访问的数据和可执行动作受当前授权与可用范围约束，不能因“已连接”推定拥有完整读写权限。

<span id="claim-expert-kit-release-01" data-claim-id="claim-expert-kit-release-01"></span>本书建议：专家套件只能组合已经通过岗位阶段门的工作流，不能用套件名称替代组成资产的测试、权限和责任记录。

复用升级遵循第 10 章的阶段门，本文不复制样本数和阈值：个人模板完成 0–30 天阶段门后才成为候选资产；团队工作流完成 31–60 天阶段门后才可发布为团队 Skill；岗位专家套件只能组合通过 61–90 天阶段门的工作流。

白话解释：你升级复用别跳级。个人提示词先跑满 0–30 天才算候选，团队工作流 31–60 天才发 Skill，专家套件只能装通过 61–90 天阶段门的工作流——套件名字不能替组成资产背书。

## 案例与证据

官方帮助中心分别提供 Skill 和连接器说明。 [R8](/qwenwork/appendix-sources#r8) [R4](/qwenwork/appendix-sources#r4) 本章采用其公开产品语境，但“资产发布合同”和阶段门映射是社区治理方法，不代表官方产品承诺。

一个周度经营复盘 Skill 可以固定输入检查、数据勾稽、异常识别和产物格式；连接器只负责在授权范围内读取项目台账或创建待办草稿；专家套件再把经营复盘、风险升级和管理层汇报等已发布工作流组合起来。任一连接器失效时，方法资产仍应能降级到人工提供输入，而不是静默生成不完整结论。

## 企业行动

对现有共享提示词做一次资产拆分：

1. 把可重复步骤、判断规则和交付格式整理为 Skill 候选。
2. 单独列出每个数据源和动作，区分读取、草稿写入和正式执行。
3. 指定工作流 Owner、系统 Owner 和专业质量 Owner。
4. 为正常、缺失、冲突和越权输入各准备测试样本。
5. 登记当前阶段门；未通过时只限个人或受控试点使用。

停止发布的信号包括：没有具体 Owner；输入输出依赖口头约定；测试只覆盖成功样本；连接器申请超出任务所需权限；无法回到上一稳定版本；专家套件包含尚未独立验收的工作流。

白话解释：这套拆分对你意味着——你先别急着共享「那个好用的助手」。你先把步骤、连接、岗位包拆开，各指一位 Owner、各备四类测试样本；出现「没 Owner」「只测成功样本」「权限超标」任一信号，就停发。

## 边界与下一步

你手上有个好提示词，它可以是 Skill 的素材，但不是完整的团队资产。连接器可用也不意味着业务动作已获批准；专家套件中的专业判断仍由具备相应职责的人承担。

本章定义资产边界和发布关系，不定义自动化运行中的接管与恢复。资产进入定时或无人值守运行前，还需要独立的运行控制。

## 术语翻成人话

| 术语 | 人话 |
|---|---|
| Skill（技能） | 把你可重复的做法、步骤、判断规则封装成版本化资产，只管「怎么做」 |
| 连接器 | 经授权把你的资料送到另一工具、或调用动作的通道，只给授权边界 |
| 专家套件 | 把多个已发布工作流组合成你的岗位任务包，不是提示词打包 |
| Owner | 对某资产结果真正负责的具体人，你得指一位，不能写「团队」 |
| 发布门 | 你资产从候选到发布的阶段关卡，过不了的只能个人或受控试点 |
| 阶段门 | 你按天数划的升级关卡：0–30、31–60、61–90 天对应不同资产等级 |

## 常见问题

**你手上有个好用的提示词，能直接当团队 Skill 发吗？**
不能。提示词只是 Skill 的素材，不是完整资产。你先把它拆成步骤、判断规则和交付格式，你跑满阶段门、指定 Owner、备齐测试样本，才能发布。

**连接器显示「已连接」，你是不是就有权读写了？**
不是。已连接只说明通道通了，实际能读能写受你当前授权和范围约束。你别默认拥有完整权限，越权申请会触发停止发布。

**专家套件能不能用名字替组成资产背书？**
不能。你只能组合已通过岗位阶段门的工作流，组成资产的测试、权限、责任记录一个都不能少；你别用套件名替它们背书。

**做资产登记时，你必查哪几项？**
当前版本、最小权限、四类测试样本（正常/缺失/冲突/越权）、Owner、上一稳定版本。你缺一项就只能个人用或受控试点，不能发布。

**连接器失效了，你的方法资产会直接崩吗？**
不该。设计上方法资产应能降级到人工喂输入，而不是静默产出半截结论。你验收时要确认它有这条降级路径。

# 岗位路线：用统一场景卡选择真实任务

## 白话导读

这一章帮你把一个虚的「给 HR 配个助手」变成一张能挑任务的实卡。你带团队落地 AI 时最常卡在：岗位名喊得响，真要验收却说不清输入是什么、产物归谁、哪些动作禁止。本章给你十字段场景卡——业务问题、角色、输入、当前步骤、交付物、验收、禁做动作、指标、风险、基线——你照它填，就能先证明一个小任务有效，再拼成岗位工作流。你读完就不会再用岗位口号去申请预算，而是拿一张能复述、能比较、能追责的卡去谈试点。

## 30 秒结论

<span id="claim-role-scenario-card-01" data-claim-id="claim-role-scenario-card-01"></span>本书建议：岗位 AI 场景统一使用业务问题、角色、输入、当前步骤、交付物、验收、禁做动作、指标、风险、基线十个字段登记，先证明一个任务有效，再组合岗位工作流。

白话解释：这条为什么这么定？你拿「岗位」当单位去验收，范围太大、权限太杂，一个材料整理成功证明不了录用或报价能自动化。你把它拆成十字段的小任务卡，先跑通一个，再谈组合，失败也知道卡在哪。

- 岗位名称不能代替具体业务问题。
- 指标必须与人工基线比较，并同时观察质量和风险。
- 场景评分、样本要求和阶段门只由第 10 章定义。

## 你可能遇到的场景

你是 HR、销售、产品、财务法务或内容市场人员，想找一个真正能落地的 AI 任务，而不是泛泛地「给岗位配助手」。输入例子可以是招聘周会台账、客户拜访资料、项目风险记录、合同与明细，或已核验来源和品牌规范；你先按任务卡写清楚再选路线，别拿岗位名去凑任务。

## 你会拿到什么

你照十字段备好一张岗位场景卡，它至少包含：业务问题、角色、输入、当前步骤、交付物、验收、禁做动作、指标、风险、基线；卡片还应标明对应的任务页、负责这项结果的人（Owner）和人工确认人。

## 照着做

1. 你先选一个岗位中高频、输入可取得、结果可人工判断且失败可逆的任务，不用岗位名称代替问题。
2. 按[任务交付协议](/qwenwork/ch02-task-delivery-protocol)填写五字段，再补上岗位角色、禁做动作、指标和基线。
3. **中间检查点：**你让业务负责人确认交付物和验收，让数据或系统 Owner 确认授权，让内容或专业复核者确认质量边界。
4. 从对应任务页开始试跑：交付看[交付新标准](/qwenwork/ch01-delivery-standard)，办公产物看[办公交付](/qwenwork/ch06-office-delivery)，研究看[研究与证据链](/qwenwork/ch08-research-evidence-chain)。

## 案例参考

岗位路线可以先参考[品胜电子：竞品调研与产品物料制作](/qwenwork/case-pisen)的研究与物料任务，也可以看[优克拉：产品研发与考勤算薪](/qwenwork/case-youkela)的研发和算薪任务；你拿这些案例当填卡样例即可，它们不能替代你自己的基线、权限和专业确认。

## 做完检查

你逐项核对场景卡能不能让另一位同事复述「用什么输入、做出什么产物、按什么条件通过、哪些动作禁止」；并确认至少有一条质量指标和一条人工基线。无法复述就退回补卡。

白话解释：你别把填完当合格。拿这张卡给没参与的人，看他能不能原样说出输入、产物、通过条件和禁做动作；说不出就退回补，否则上线后人各做各的，出了问题谁都接不住。

## 需要注意

如果场景只有岗位口号、没有可取得输入，或验收依赖录用、付款、法律意见、路线图承诺和对外发布等高后果判断，保留现有人工流程，停止自动化试跑，改成人工整理或只读分析，由业务和专业负责人确认后再选任务。

白话解释：你遇到这些红灯就退回去：只有岗位口号没有真输入、验收要靠录用付款法律意见这类高后果决定——你先留人工流程，别让 AI 碰这些，等业务和专业负责人确认再谈自动化。

## 为什么重要

「给 HR 一个助手」或「为销售做智能体」无法直接验收。岗位范围太大，数据权限和后果也不一致；一个成功的材料整理任务不能证明人员决策、报价或发布动作可以自动化。

统一场景卡把岗位需求压缩成可比较的业务单元。你作为企业 AI 负责人可以按真实输入、当前步骤和风险选试点，业务负责人可以确认交付物和禁做动作，运营团队可以采集同口径基线。

## 方法或模型

场景卡的十个字段在所有岗位保持同义；下列五张卡是起步示例，不是固定最佳实践。

白话解释：这五张卡只是给你打个样，不是标准答案。你填自己岗位时，字段含义不变，但业务问题、禁做动作、指标都得换成你组织的真情况；你别照抄卡片就当成试点方案。

### HR：招聘周会状态整理

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 招聘周会前需要快速识别职位阻塞和缺失反馈 |
| 角色 | 招聘负责人、招聘专员、用人经理 |
| 输入 | 获授权的职位台账、面试反馈、入职准备清单和上周版本 |
| 当前步骤 | 导出、合并、追问缺失项、整理状态、准备周会 |
| 交付物 | 职位—阶段—阻塞—负责人—下一步的可编辑状态表 |
| 验收 | 每个状态可回到原始反馈；缺失项单列；责任人和截止时间明确 |
| 禁做动作 | 不自动录用、淘汰、评价候选人，不向无权限对象传播个人信息 |
| 指标 | 准备时长、反馈完整率、状态误配率、人工修改量 |
| 风险 | 候选人隐私、反馈偏见、同名误配、旧状态覆盖 |
| 基线 | 记录当前人工准备时间、缺失反馈、退回和修正样本 |

### 销售与商务：客户拜访准备与跟进

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 会前信息分散，会后行动和承诺容易遗漏 |
| 角色 | 客户经理、售前、销售负责人 |
| 输入 | 公开信息、获授权的 CRM 记录、历史沟通和产品资料 |
| 当前步骤 | 搜集、核对、形成提纲、记录会议、起草跟进 |
| 交付物 | 一页准备单、事实与待确认问题、邮件草稿、待写入清单 |
| 验收 | 事实标注来源和日期；承诺、报价、负责人和截止时间经过确认 |
| 禁做动作 | 不自动报价、承诺、发送或修改客户主记录 |
| 指标 | 准备时长、事实错误率、行动遗漏率、CRM 建议采纳率 |
| 风险 | 客户信息越权、陈旧信息、虚构承诺、错误收件人 |
| 基线 | 采集现有准备用时、会后遗漏、退信和记录修正情况 |

### 产品与项目：项目风险台账

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 需求、周会和缺陷中的变化无法及时汇总为决策请求 |
| 角色 | 产品经理、项目经理、研发负责人 |
| 输入 | 需求文档、项目计划、周会记录、缺陷和变更日志 |
| 当前步骤 | 对齐版本、提取变化、判断影响、分配责任、请求决策 |
| 交付物 | 风险台账、变更摘要、待决事项和版本发布说明草稿 |
| 验收 | 风险有证据、Owner、截止时间和缓解动作；决定与建议分开 |
| 禁做动作 | 不自动改变优先级、关闭缺陷、承诺发布日期或覆盖路线图 |
| 指标 | 汇总时长、风险遗漏率、决策等待时长、变更可追溯率 |
| 风险 | 版本混用、责任误配、未确认状态被写成决定 |
| 基线 | 记录现有汇总步骤、漏项、等待时间和会后修订 |

### 财务与法务：高后果材料核对

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 大量明细和条款需要定位异常，但最终判断必须由专业人员承担 |
| 角色 | 财务人员、法务人员、业务负责人 |
| 输入 | 获授权的明细、报表、合同版本、规则和专业模板 |
| 当前步骤 | 勾稽或条款抽取、异常定位、版本比较、形成复核清单 |
| 交付物 | 财务勾稽表或条款定位表、异常清单、版本差异和待确认项 |
| 验收 | 金额、日期、公式、条款位置和版本可追溯；专业人员签署结论 |
| 禁做动作 | 不自动记账、付款、修改主数据、给出最终法律意见或签署合同 |
| 指标 | 核对时长、异常检出率、误报率、人工修改量、退回次数 |
| 风险 | 金额或版本错误、权限越界、把提示误当专业结论 |
| 基线 | 保存人工核对时间、已知异常、漏检、误报和复核记录 |

### 内容与市场：有证据的内容流水线

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 选题、素材、审校、发布和复盘分散，事实与品牌风险难控制 |
| 角色 | 内容运营、市场、品牌和设计负责人 |
| 输入 | 已核验来源、选题池、品牌规范、授权素材和渠道要求 |
| 当前步骤 | 研究、选题、起草、设计、事实审校、预览、发布、复盘 |
| 交付物 | 选题证据表、内容草稿、素材清单、发布预览和复盘记录 |
| 验收 | 事实有来源和日期；品牌、版权、链接和渠道格式通过检查 |
| 禁做动作 | 不使用无授权素材，不虚构效果或客户，不未经确认对外发布 |
| 指标 | 制作时长、事实退回率、品牌问题数、发布错误率、复用率 |
| 风险 | 版权、误导表述、敏感信息、过期链接和错误渠道 |
| 基线 | 采集现有周期、审校修改、发布事故和素材复用情况 |

## 案例与证据

五张卡来自现有岗位任务的社区整理，没有使用未经授权的客户名称或效果数字。它们证明的是场景卡如何填写，不证明这些场景在所有组织中优先级相同。

指标必须成对观察效率与质量。例如准备时长下降时，也要检查事实错误、人工修改和风险事件是否上升。没有人工基线或数据口径不同的结果不能直接比较。

白话解释：你读案例时要盯住一件事——指标要成对折。准备时长降了，你同时看事实错没错、风险升没升；没有人工基线或口径不一样的数字，你别拿来直接比，比了也是假结论。

## 企业行动

你给每个岗位只选一个候选任务：

1. 由业务负责人填写业务问题、交付物、验收和禁做动作。
2. 由使用者记录当前步骤、输入位置和人工基线。
3. 由数据或系统 Owner 核对授权范围和高风险动作。
4. 由内容复核者定义质量指标和退回原因。
5. 把完整场景卡交给第 10 章阶段门评审，本章不自行评分或设阈值。

停止信号包括：场景只能用岗位名称描述；没有可取得的输入；交付物不可验收；禁做动作未明确；指标只记录速度；基线来自不同口径或只保留成功样本。

白话解释：你给每个岗位只挑一个任务先跑，别一上来铺满。业务负责人填问题、交付物和禁做动作，使用者记基线，Owner 核授权，复核者定指标；任一个停止信号出现，你就退回去补卡，别硬送阶段门。

## 边界与下一步

场景卡不是岗位绩效评价，也不能用 AI 输出替代录用、付款、法律意见、路线图承诺或对外发布决定。你按数据敏感度和专业后果增加更严格的规则。

本章负责定义岗位场景，不负责评分和推广阶段门。场景卡完成后，你仍需建立研究与证据方法，避免把印象写成业务事实。

## 术语翻成人话

| 术语 | 人话 |
|---|---|
| 场景卡 | 十字段的一张小卡，你用它把「岗位」拆成能验收的具体任务 |
| 业务问题 | 你要用 AI 解决的那件真事，不是「给 HR 配助手」这种口号 |
| 禁做动作 | 明写「AI 不准碰」的红线，比如不自动录用、不自动报价 |
| 基线 | 你现在人工做这件事的时长、错误和返工，用来和 AI 比好坏 |
| 指标成对 | 效率（快不快）和质量风险（错没错）要一起看，不能只记速度 |
| 阶段门 | 第 10 章定义的评审关卡，决定场景卡能不能升级推广，本章不评分 |

## 常见问题

**你该怎么把「给销售配助手」变成能验收的任务？**
你别拿岗位名当任务。先写十字段卡：业务问题填「会后承诺易遗漏」，交付物填「一页准备单+邮件草稿」，禁做动作填「不自动报价、不发客户」。填完能让同事复述，才算一张合格卡。

**场景卡填完就能上线自动化吗？**
不能。你先证明一个小任务有效、失败可逆，再谈组合；评分和阶段门归第 10 章，本章不替你放行。你拿卡去阶段门评审，别自己拍板上线。

**哪些动作你必须写进禁做动作？**
凡是高后果、要人拍板的都写：录用、淘汰、付款、报价、改主数据、给法律意见、对外发布。你把这些红线写死，AI 只做整理和草稿，决定权留给人。

**没有人工基线，你直接看 AI 准备时长下降行不行？**
不行。你没基线就不知道省下的时间是不是靠犯错换的。指标要成对看：时长降了，同时查事实错误、人工修改和风险事件升没升；口径不同的数字不能直接比。

**五个岗位示例你能直接抄去试点吗？**
不能。它们是填卡样例，不是你组织的最佳实践。你套用时要换成自己的业务问题、禁做动作和基线，权限和专业确认也要按你单位重做，别照抄了事。

# 研究与证据链：从问题树（把大问题拆成小问题的提问框架）到发布记录

## 白话导读

这一章帮你把「搜了一堆资料写出来的报告」变成能复核、能追责的研究交付。你做竞品、市场或经营分析时最常翻车：转述被写成官方事实、不同口径的数字被直接平均、过期页面撑着当前结论。本章给你两样东西——九字段证据卡和冲突登记——你每查到一条主张就记一张卡，来源、口径、限制写清楚；来源打架时你登记差异，不擅用平均数掩盖。你读完再做研究，别人能打开来源、定位原文、复述口径，你的结论才立得住。

## 30 秒结论

<span id="claim-evidence-card-fields-01" data-claim-id="claim-evidence-card-fields-01"></span>本章将证据卡（记录来源、口径和限制的小卡片）唯一规范定义为九个字段：主张、来源原文、来源类型、日期、统计口径、适用范围、限制、冲突、状态。

<span id="claim-research-question-tree-01" data-claim-id="claim-research-question-tree-01"></span>本书建议：研究先把决策问题拆成可由证据回答的问题树（把大问题拆成小问题的提问框架），再检索和写作，避免「搜索到什么就写什么」。

白话解释：这两条为什么这么定？你若先搜再写，结论会被搜到的材料带着走，哪篇顺手写哪篇。你先按决定反推问题树，再为每枝指定来源和停止条件，搜来的东西才有处安放、才敢用。

## 你可能遇到的场景

你要查资料形成一份竞品、市场或经营分析结论，但搜索结果很多，来源口径和日期却不一样。输入例子是「要支持的预算决定、截止日期、目标市场、已有官方资料和访谈记录」；你先把决定拆成问题树，再开始检索，别拿到关键词就开搜。

## 你会拿到什么

你照这套备好一套可发布的研究包，它最少包含：

1. 问题树和来源计划：每个子问题、优先来源、备选来源和停止条件；
2. 证据卡（记录来源、口径和限制的小卡片）：主张、来源原文、来源类型、日期、统计口径、适用范围、限制、冲突、状态；
3. 冲突登记（把不同来源的差异记下来的记录）：编号、相关卡片、差异、可能原因、处理动作、负责核对和处理这条证据的人（Owner）和状态；
4. 分层结论：已核验事实、基于证据的推断、建议、待确认问题和发布前复核记录。

## 照着做

1. 你先写读者要作的决定，再把它拆成可由证据回答的问题树，并给每个子问题指定来源和停止条件。
2. 你采集标题、链接、日期和原文位置，按九字段制作证据卡，不把搜索摘要直接写成结论。
3. **中间检查点：**你逐卡核对对象、期间、单位、定义和授权；发现冲突就登记，不用平均数或多数投票掩盖差异。
4. 你将事实、推断、建议和待确认问题分层，发布前由未参与撰写的人抽检关键主张、高后果结论和敏感信息。

## 做完检查

随机抽查 3 条关键主张，要求复核人能打开来源、定位原文、复述统计口径和限制；任何一条无法复述，就降低结论强度、补证，或从发布稿移出。

白话解释：你别把抽检当盖章。随机挑 3 条关键主张，让复核人真能打开来源、定位原文、说出口径和限制；任一条说不出，你就降级、补证或移出，别带着含糊结论往外发。

## 需要注意

如果关键数字无原文、来源需要登录却无人负责、不同定义被直接比较，或高后果结论无人复核，保留原始资料和证据卡，停止发布；回到上一稳定版本，改成人工只读分析或并列披露冲突，由数据或专业 Owner 确认后再继续。

白话解释：你遇到这些红灯就停发：关键数字找不到原文、来源要登录却没人认领、不同定义被直接比、高后果结论没人复核。你先退到上一稳定版，改成只读分析或把冲突并列摆出来，等 Owner 确认再继续。

## 为什么重要

你读研究报告时最危险的失败不是篇幅不足，而是语言完整却无法复核：转述被写成官方事实，不同口径的数字被直接比较，过期页面支撑当前结论，公开演示被包装成客户效果。

问题树决定需要什么证据，证据卡保存每条主张的边界，冲突登记防止团队用平均或多数投票消除真实差异。它们共同帮你判断结论能支持什么决定，以及哪些问题仍需人工确认。

白话解释：这节是给管理者看的。你验收一份研究，别只看页数和不漏洞。你问三件事：每条主张能不能回溯来源、不同口径的差异有没有登记、高后果结论有没有人复核；三件缺一件，结论就不能直接拿去拍板。

## 方法或模型

你先从决定反推问题树：

| 子问题 | 需要的证据 | 优先来源 | 不能直接得出的结论 |
|---|---|---|---|
| 市场是否变化 | 连续期间、规模或增速及完整口径 | 监管、统计、公司披露 | 用单篇报道预测份额 |
| 客户是否有痛点 | 访谈原话、工单或使用数据 | 获授权的一手访谈和内部数据 | 用竞品广告替代客户需求 |
| 方案是否可行 | 产品说明、测试样本、成本和失败记录 | 官方文档、受控试点、原始记录 | 用功能入口推断稳定交付率 |
| 组织是否能采用 | 权限、流程、责任和专业后果 | 组织制度、系统 Owner、专业意见 | 用 AI 摘要代替合规判断 |

一张证据卡只支持一个最小主张，固定字段如下：

| 字段 | 必填内容 | 不合格信号 |
|---|---|---|
| 主张 | 一句可核验、不过度外推的陈述 | 混入评价词或多个结论 |
| 来源原文 | 标题、机构、链接或位置，以及必要原文摘记 | 只有搜索摘要或二次转述 |
| 来源类型 | `official-product`（官方产品）、`regulatory-statistical`（监管统计）、`first-party-disclosure`（一手披露）、`customer-authorized`（客户授权）、`independent-research`（独立研究）、`public-demo`（公开演示）、`community-framework`（社区框架） | 不说明谁产生了资料 |
| 日期 | 发布、访问和必要的采集日期 | 无法判断是否过期 |
| 统计口径 | 对象、期间、单位、样本、分母和计算方法 | 只有百分比或「显著提升」 |
| 适用范围 | 能支持的地域、对象、流程和决定 | 默认外推到全部企业 |
| 限制 | 不能支持什么、缺什么、是否未经独立审计 | 只写结论不写边界 |
| 冲突 | 与其他证据的差异、可能原因和处理动作 | 直接平均不同定义的数字 |
| 状态 | verified、limited、editor-reviewed、pending 或 stale | 用模糊的「可信」代替发布状态 |

白话解释：你填证据卡最容易漏的是「限制」和「状态」。限制写清这张卡不能撑什么，状态写清它是已核验还是待核；你别用「可信」这种虚词糊弄，发布门认的是 verified、limited 这些硬状态。

来源按原始性和责任边界使用：监管统计、正式披露和获授权一手记录优先支撑事实；完整方法的独立研究可支撑限定范围结论；媒体、合作伙伴材料和专家解读用于补充；搜索摘要、转载和社交媒体只用于发现线索。来源数量不能代替质量和口径一致性。

人机协作采用七步流程：

1. **立题**：明确读者要作的决定、截止时间和不研究的边界。
2. **来源计划**：为每个子问题指定优先来源、备选来源和停止条件。
3. **采集去重**：AI 可整理标题、链接、日期和关键词；人确认原始来源和授权。
4. **制作证据卡**：AI 可抽取结构；人逐卡核对原文、数字、日期和限定条件。
5. **登记冲突**：比较对象、期间、单位、定义和样本，不用平均掩盖差异。
6. **形成论证**：把已核验事实、基于证据的推断、建议和待确认问题分层。
7. **审阅发布**：由未参与撰写的人抽检关键主张，并检查敏感信息、版权和失效状态。

冲突登记至少保留冲突编号、相关卡片、差异内容、可能原因、处理动作、Owner 和当前状态。若无法在截止日前解决，报告应并列披露差异并降低结论强度。

证据卡是研究任务中的工作记录，可以包含未发布线索和仓库外的授权材料；`evidence-ledger.json` 是公开蓝皮书关键主张的发布记录，只保存公开安全且符合发布门的内容。两者职责不同，但来源类型、状态、适用范围和限制必须保持一致。

白话解释：你别把证据卡和发布台账混为一一对应。证据卡是你研究中的工作本，能塞未发布的线索；`evidence-ledger.json` 只收公开安全、过发布门的主张。两者字段口径必须一致，但你别指望工作本直接当发布记录用。

## 案例与证据

<span id="claim-demo-boundary-01" data-claim-id="claim-demo-boundary-01"></span>本书主张：公开演示只能证明可观察的交付形态，不能据此推导客户身份、实施成本、生产稳定性或业务效果。

公开案例库中的网页、看板和报告链接可以帮助读者理解产物形态。 [R11](/qwenwork/appendix-sources#r11) 若没有案例级外部记录 ID、深链或许可范围内的快照，它们只能留作待核验线索，不能进入公开案例数量。

发布前抽检优先覆盖全部关键主张、全部精确数字和全部高后果结论；其他内容按风险抽样。抽检人需要在可接受时间内打开来源、定位原文并复述口径，否则主张应降级、补证或移出发布内容。

白话解释：你记这条边界——公开演示只证明「长得出来」，证明不了「谁用的、花多少、稳不稳、效果好不好」。案例库链接没案例级记录 ID 的，你只能当线索，别算进公开案例数，也别写成客户背书。

## 企业行动

你为一个正在进行的研究任务建立证据工作台：

1. 让业务负责人确认决定、问题树和不研究范围。
2. 让研究者按九字段制作证据卡，不直接从搜索结果写结论。
3. 让数据或专业 Owner 复核口径、授权和高后果解释。
4. 建立冲突登记，指定处理人和截止时间。
5. 发布前由独立复核者抽检关键主张，并把公开使用的主张同步到发布台账。

可复制的研究调用方式放在 [提示词附录](/qwenwork/appendix-templates#研究证据链模板)，附录只调用本章字段，不重新定义证据卡。

停止信号包括：关键数字没有原文或口径；来源需要登录却没有资料责任人；不同定义被直接比较；高后果结论无人复核；内部或客户材料没有公开授权；主张状态与正文措辞不一致。

白话解释：你建证据工作台从决定开始，别从搜索开始。业务负责人确认决定和问题树，研究者按九字段制卡，Owner 复核口径，独立人抽检关键主张——任一个停止信号出现，你就停发补证，别带病发布。

## 边界与下一步

研究整理可以由 AI 加速，但法规解释、投资判断、医学、法律和其他高后果结论必须由具备相应职责或资质的人复核。证据卡完整也不保证结论正确，它只让错误更容易被发现和追责。

本章定义研究证据方法，不决定哪些公开案例可以发布。你要把案例送进蓝皮书，还需满足独立的来源定位和公开计数门槛。

## 术语翻成人话

| 术语 | 人话 |
|---|---|
| 问题树 | 把「要不要做」这种大问题，拆成一串能拿证据回答的小问题的框架 |
| 证据卡 | 九字段的小卡片，你每查到一条主张就记一张：来源、口径、限制写清楚 |
| 冲突登记 | 来源互相打架时，你把差异、原因和处理动作记下来的记录，不擅用平均掩盖 |
| 来源类型 | 资料是谁产的：官方产品、监管统计、一手披露、客户授权、独立研究等 |
| 状态 | 这条主张的发布状态：已核验 verified、受限 limited、编辑审过、待核 pending、过期 stale |
| 发布台账 | `evidence-ledger.json`，只收公开安全、过发布门的主张，是你对外发的账本 |
| 不研究范围 | 你事先写清「这次不碰什么」，避免研究无限摊开、超出授权 |

## 常见问题

**你该怎么防止搜索结果带着结论跑？**
你别先搜后写。先把读者要作的决定拆成问题树，给每枝指定优先来源、备选来源和停止条件，再开搜；搜来的材料按问题树归位，哪篇顺手写哪篇的毛病就治住了。

**证据卡九字段里你最容易漏填哪两个？**
你最容易漏「限制」和「状态」。限制写清这张卡不能撑什么，状态写清是已核验还是待核；你别用「可信」这种虚词，发布门只认 verified、limited 这些硬状态。

**两个来源数字口径不一样，你能直接取平均吗？**
不能。你遇到冲突就登进冲突登记，写清差异、可能原因和处理动作；截止日前解决不了就并列披露并降低结论强度，绝不用平均数把真实差异抹掉。

**公开演示或案例库链接，你能当成客户效果证据吗？**
不能。公开演示只证明交付形态长得出来，证明不了客户身份、成本、稳定性或效果；没案例级记录 ID 的链接你只能当待核验线索，别写进公开案例数，也别当背书。

**发布前你该抽检到什么程度才算放心？**
你优先全覆盖关键主张、精确数字和高后果结论，其余按风险抽样；抽检人要在可接受时间内打开来源、定位原文、复述口径，做不到的主张就降级、补证或移出，别带病发布。

# 个人 IP 怎么做 GEO 体检

> 场景：判断一个 IP 有没有被看见，以前是搜名字、看粉丝数；现在多了一道新入口——**越来越多人直接问 AI**。AI 能不能把你的中文名和英文账号对上？会不会把同名项目安到你头上？它引用的是本人主页，还是转了几手的聚合文？

这些问题靠随手问一句"你知道某某吗"测不出来——问题不固定、时间不固定、判断标准也不固定。实测用一套固定流程做了一次完整体检：**先准备公开事实基准卡和 5 个固定问题 → 逐题公开检索、核对来源、评分 → 生成监测表和修正建议**。本次结果 29/30：没有完全没认出来或明确说错的问题，但发现 1 个身份混淆风险和 1 个来源质量问题。

## 先把边界说清：这是检索信息

这套流程只做三件事：读取本人确认可以公开的事实、检查公开网页、生成本地报告。它不会自动修改主页，不替你发声明，也不能保证改完简介后所有 AI 立刻换说法——搜索结果会变、模型版本会变。所以结果只代表"某一天、某个助手、简体中文口径下的一次实测"。另外：**粉丝数、Star 数、榜单名次这类会变的数字，可以作为当天快照，但不应被当成不变的身份事实**。

工具用最小组合：「VOC 与舆情调研」Skill（多来源公开检索、信息归类、来源回溯）+ 内置公开检索。不需要额外接搜索连接器，也不必横向比较多个 AI 助手（变量太多）。

## 准备两份输入材料

**公开事实基准卡**——只写自己能确认、也愿意公开的稳定事实：首选公开名称和常用英文账号；对外身份和长期分享主题；本人公开主页；可核验的代表项目；以及**明确不纳入基准的内容**（真实姓名、联系方式、动态粉丝数、未确认头衔）。

**固定监测问题**（本次 5 个，分别测：能否认出实体、认清账号归属、找到代表内容、对上中英文名称、会不会被同名项目带偏）：

1. 某某是谁？主要公开分享什么内容？
2. 某某有哪些可以确认属于本人的公开账号和代表项目？
3. 如果我想学习【你的主题】，某某有哪些公开资料可以参考？
4. "中文名"和"英文账号"是不是同一个创作者？请给出可核验的公开来源。
5. 某某有没有公开分享过【细分主题】？如果有，项目是什么？

## 实测提示词

口径、评分、来源优先级和安全边界一次写清：

```text
我负责维护个人 IP"【你的公开名称 / 英文账号】"的公开信息。
请使用"VOC 与舆情调研"能力，完成一次可复现的 AI 答案可见度检查。

输入材料：
1. 公开事实基准卡：【ip-baseline.md 路径】
2. 固定监测问题：【audit-questions.md 路径】

检查口径：
- 助手：豆包工作当前对话
- 日期：【填写实测日期】
- 语言：简体中文
- 只检查公开网页，不读取私人账号数据，不搜索或推断联系方式、住址、收入等私人信息。

请按下面步骤执行：
1. 先读取两个输入文件，确认基准事实和固定问题完整。
2. 对每个问题独立进行公开检索，像第一次遇到这个名字一样回答，不要只照抄基准卡。
3. 每个问题记录：原始问题、回答摘要、是否正确识别公开名称、是否与英文账号对上、
   事实错误或缺失、引用 URL、来源类型、访问情况和检索时间。
4. 将问题级结果分成四类：未出现、描述错误、身份混淆、来源质量差；
   如果没有问题也要明确写"未发现"。
5. 来源优先级按"本人公开主页或本人项目 > 明确署名的公开报道 > 聚合页或转载页"判断。
   第三方页面不能单独证明账号归属。
6. 给每个问题按三项各 0—2 分：实体是否出现、身份是否准确、来源是否可靠；
   同时保留文字理由，不只给总分。
7. 汇总哪些公开信息已被稳定看见，哪些缺少一致、可引用的公开页面。
   修正建议必须落到具体页面和具体字段，例如主页简介、项目 README、作者页之间如何统一；
   不要承诺修改后一定影响模型答案或排序。
8. 做一次自检：每个结论能否回到 URL；是否把一次实测外推成所有 AI 助手；
   是否把第三方信息写成本人确认事实。

最终请交付两个文件：
- 《个人IP_AI答案可见度监测表.md》：口径、逐项结果、评分、来源和限制。
- 《公开资料修正建议.md》：按 P0 / P1 / P2 排序，写清建议修改的公开页面、
  当前问题、建议动作和复测方法。

聊天里只汇总：总分、四类问题分别出现几次、最需要先修正的 3 个公开信息点。

安全边界：只做只读检查和生成本地文件；不要修改任何公开主页或项目，不要发布内容，
不要发送消息，也不要承诺能够操纵模型答案。
```

执行时注意三件事：它有没有**真的打开公开页面**而不是只凭模型记忆；账号归属有没有**本人主页或本人项目**作证据；第三方转载有没有被误写成"本人确认事实"。比如"一个第三方页面说这个账号属于某人"证据不够——更稳的链路是本人 GitHub 项目链接到 X，X 主页也回链 GitHub，两个公开页面互相验证。

## 实测结果：29/30，不是满分反而更有用

| 问题 | 实体出现 | 身份准确 | 来源可靠 | 小计 |
| --- | --- | --- | --- | --- |
| Q1 是谁、分享什么 | 2 | 2 | 2 | 6/6 |
| Q2 公开账号和代表项目 | 2 | 2 | 1 | 5/6 |
| Q3 学习资料 | 2 | 2 | 2 | 6/6 |
| Q4 中英文名是否同一人 | 2 | 2 | 2 | 6/6 |
| Q5 细分主题项目 | 2 | 2 | 2 | 6/6 |
| **合计** | **10/10** | **10/10** | **9/10** | **29/30** |

四类问题分布：未出现 0、描述错误 0、身份混淆 1、来源质量差 1。真正值得处理的是 3 个 P0 修正点：

1. **GitHub 主页 Bio 为空**——账号能被找到，但主页没直接写中文名称和身份，AI 要绕到仓库 README 才能建立关联；
2. **X 账号缺少可独立验证的 GitHub 回链**——只有 GitHub 对 X 的单向声明，没有验证到反向链接；
3. **存在同名近似项目**——另一个作者的仓库名只差一个字母，AI 有引用错仓库的风险。

监测表把 X 账号、GitHub 账号和代表性开源项目都检测到了，个人定位几乎没有偏差；修正建议也确实指出了没做到的地方——看完就立刻去补上了。

> 分数不是重点。真正有价值的是：**每个扣分点能回到一个公开页面，每个建议能落到一个具体字段，过一两周还能用同一组问题复测。**

## 拿自己的 IP 跑时，照这张清单检查

1. 先写公开事实基准卡，不把隐私和动态数字混进去；
2. 固定助手、日期、语言和 5—10 个问题；
3. 每个问题独立检索，不让 AI 只照抄基准；
4. 实体出现、身份准确、来源可靠分开打分；
5. 本人主页或项目优先，第三方转载只做辅助证据；
6. 把"没出现、说错、认错人、来源太弱"分开；
7. 建议落到页面、字段和复测方法；
8. 不自动改主页、不自动发布，不承诺左右模型答案；
9. 保留结果，下次用同一口径复测才看得出变化。

以前做个人 IP 总盯着知名度，现在还要多问一句：**当别人让 AI 介绍我时，出来的信息够不够准确？**把问题固定下来、把证据链补齐、把不稳定的数字剔出去，一次模糊的"搜搜看"就变成一套可重复执行的公开资料体检。

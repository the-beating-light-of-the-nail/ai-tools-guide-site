# Skill 怎么挑、怎么用？一次看懂它替你省在哪

你大概听同事说过「装个 Skill 就好用了」，可你点开技能市场，满屏分类看不懂：金融、法律、新媒体创作……你也不知道哪个跟自己有关。更懵的是，它明明叫「技能」，到底和你在聊天框里敲的那段提示词差在哪？这一篇就说清两件事：它是什么、你该怎么挑着用，顺带让你看懂它为什么能替你省掉反复叮嘱的功夫。

豆包工作自己负责听懂你的任务、安排执行；而 Skill 是一包可以反复用的东西——说明、脚本、参考资料、素材都在里面——它告诉 Agent 某类活该怎么做、调什么工具、交什么格式。这套思路来自 Anthropic：2025 年 10 月推出 Agent Skills，12 月开放成标准，现在不少产品都跟着做。

## 一个标准 Skill 长什么样

它本质上是个文件夹，里面不一定全要，但有一份是命根子：

```text
my-skill/
├── SKILL.md          # 唯一必需的文件
├── scripts/
│   └── check.py
├── references/
│   └── guide.md
└── assets/
    └── template.pptx
```

只有 `SKILL.md` 少不了，核心就是一段「这类活怎么做」的说明，你读一眼就懂它在管什么：

```markdown
---
name: tech-article-writing
description: 用于撰写 AI 产品、模型评测和科技行业相关文章
---

收到写作任务后：

1. 先确认文章核心角度
2. 查找一手资料
3. 对核心事实交叉验证
4. 根据用户写作风格完成初稿
5. 检查禁用句式和 AI 味表达
```

## 它干活的方式：用到才翻开

Skill 最巧的不是这份说明本身，而是「渐进式披露」。你想，Agent 装了一百个 Skill，要是把一百份全文全塞进上下文，既烧你的 Token，又让模型被无关指令带偏。标准做法是三层：

1. 启动的时候，只加载每个 Skill 的名字和 description，每份也就几十到一百来个 Token；
2. 任务对上了，才加载完整的 `SKILL.md`——比如你说「帮我写一篇豆包工作的公众号文章」，Agent 看 description 认出 `tech-article-writing` 相关，这时才读全文；
3. 干到细处，才继续读 `references/style.md`、跑 `scripts/check-ai-phrases.py`。

OpenAI 的 Codex 也是类似机制。所以它解决的是个老难题：怎么给 Agent 塞很多知识和工作方法，又不把所有东西永远压在你的每次 Prompt 里。

## 它替你干的四种事

**1 · 补上只有你们公司才懂的知识。** 大模型懂的通用知识多，但你公司的事它未必知道：`canonical user_id` 在哪张表、`subscriptions` 表是 append-only、查退款要排除某个状态、Grafana 对应哪个 dashboard ID。Anthropic 内部几百个 Skill 主要集中在九类：API 与内部库使用、产品验证、数据分析、业务流程自动化、代码脚手架、代码审查、CI/CD、故障 Runbook 和运维。

**2 · 把复杂流程固定下来。** 普通提示词说「详细调研一下豆包工作」，模型每次得现想：去哪找、先查啥、怎么验、跟谁比、出什么结构。Skill 把流程钉成：官网 → 官方公众号和发布会 → 产品文档 → 实际产品测试 → 同类产品对比 → 核心观点提炼 → 事实核验。这种叫 Encoded Preference Skill（按你的工作方式组织既有能力）；另一种 Capability Uplift Skill 补的是模型本来做不好或不稳的能力，比如复杂文档、PDF 和 PPT 处理。

**3 · 不用反复叮嘱同一句话。** 你总得唠叨的「别写太 AI、长短句结合、别堆点列、技术内容克制、别编例子」，天然适合做成一个 `writing-style` Skill。以后你写提示词只写一句「写一篇豆包工作文章」，写作习惯、资料标准、禁用表达都由 Skill 兜着。

**4 · 把经验变成能管的资产。** 以前你的提示词散在聊天记录、文档、个人脑子里；Skill 是文件，能进 Git、回滚版本、团队共享、做 A/B、自动评测、持续更新。

## 在豆包工作里怎么找 Skill

你打开左侧「技能·连接器·伙伴」，按金融、法律、新媒体创作、办公协作、编程、学术这些分类翻，也能在顶部搜索框按名字或需求搜。看中了点右侧「+」加上；部分技能支持「在对话中试用」。加过的统一在「我的技能」里管。

你也能自己建或传一个：点页面右上角「新建」，选「与豆包对话新建技能」或「上传技能」。传之前你先看清这包技能从哪来、脚本干啥、权限范围到哪。

## 用它跑通一个任务

比如你的文章要去 AI 痕迹：你在技能市场搜「去 AI 味」，加上后回到工作任务，在输入框敲 `/` 或点「更多技能」选中它，把文章和具体要求附上。豆包工作会照技能说明自己排步骤，还把执行过程和结果摊给你看。

交回来后你重点核三件事：指定句式删干净没、事实和语气保住没、专有名词有没有被它顺手改错。

## 新手常见问题

**Skill 和我在聊天框写的提示词，到底差在哪？**
提示词是你一次性交代；Skill 是把「这类活怎么干」存成文件，以后你一句话就能调，还能团队共享、版本管理。临时问一句用提示词，反复要干的活才值得做成 Skill。

**我装了一堆 Skill，会不会把上下文撑爆？**
不会。它用到才翻开：启动只记名字和简介，任务对上了才读全文，干细处才读参考资料、跑脚本。这就是渐进式披露，Token 花在你的刀刃上。

**找不到现成技能，能自己做一个吗？**
能。你点右上角「新建」，跟豆包对话生成，或上传现成技能包。传之前你看清来源、脚本和权限范围，别把来路不明的包接进来。

**加完技能，怎么确认它真按要求做了？**
你回工作任务里调起它、附上材料，交回来后逐条核：指定句式删没删、事实语气留没留、专有名词改没改。别只看它自己写的「已完成」，你亲自过一遍才稳。

**「我的技能」在哪看，会不会加乱了？**
加过的统一在「我的技能」里管理，你随时能停用或删。市场里点「+」是添加，页面右上角「新建」才是自己造，两处你别搞混。

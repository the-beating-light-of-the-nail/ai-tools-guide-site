# 想做个人网站却总在「等准备好」？设计驱动的建站法，半天做出真正像你的站

你盯着建站工具发呆，照片还没挑好、项目介绍没写完、一句自我介绍改了好几遍。这种「等准备好了再做」的状态很常见，让你迟迟开不了头，网站永远停在脑子里。其实可以先换一个问题问起：你希望谁看到这个网站、他看完记住什么、又愿意接着做什么？把这几件事说清，内容和设计就有了方向，不用等所有材料齐全。

> 场景：想做个人网站，却一直卡在「等准备好了再做」——照片没挑好、介绍没写完。换个起点：先说清楚你是谁、网站为什么存在。

## design-led-website-builder 在解决什么

你想做网站，AI 很容易先给你一个「能打开」的网页。真正的麻烦在后面：它也容易生成一个换掉名字以后还能交给任何人的网页——白底、通用字体、几张等宽卡片，页面看着完整，却没什么属于你的东西。填半天内容，结果出来还是像模板。

`design-led-website-builder` 这个 Skill 把设计研究放在写代码之前，完整流程七步、顺序固定：

1. 它先接收你已提供的材料，判断这是现成品牌、零散个人内容，还是一个参考网站；
2. 锁定网站用途（阅读归档为主的出版型，还是强调作品气质的视觉型）——需求确实有分叉时，只问你一轮，选定后再继续；
3. 研究 3—5 个用途相近的真实网站，研究对象跟着网站任务走，不会拿炫技作品集去指导需要长期阅读的博客；
4. 寻找 3—8 份可用素材（纸张、木纹、插画、公开授权照片、氛围图）；真实头像、作品、客户案例和成绩，只能用你提供或确认过的内容；
5. 用一小段话说明设计方向、参考网站、已找到的素材、不会照抄的部分，以及接下来准备实现什么；
6. 开始搭建：先确定字体、颜色、间距、图片裁切和交互规则，再落实到页面；
7. 完成检查：首屏要让人很快看懂这是谁的网站、这里有什么、下一步能做什么；移动端、键盘操作、动效降级、图片来源和页面性能也在检查范围内。

你拿到成品前可以先想清楚：参考网站只用来理解层级、排版、图片裁切和交互，不能直接复制有辨识度的布局与素材；生成的图片能负责气氛和插画，但不能冒充你的照片、产品界面、客户或奖项。

## 安装并跑一遍

你直接告诉豆包工作把 Skill 装上：

```text
请安装这个个人网站设计 skill：
https://github.com/liucongg/liucong-skills/tree/main/skills/design-led-website-builder
```

然后你一句话开工（提示词里交代了人和目的，Skill 可以直接进入研究阶段）：

```text
$design-led-website-builder 我想制作一个自媒体博主的个人网站，
我全网 ID 都是刘聪NLP，主要想展示我之前分享的一系列文章内容。
```

如果你只写「帮我做一个个人网站」，它会先判断可能的几种产品形态，再用一轮问题请你锁定方向。

## 部署到 GitHub Pages

网站做好后，你一句话部署：

```text
帮我把这个网站，通过 GitHub 部署到 GitHub Pages 中。
```

你没登录 GitHub 的话会先引导登录，随后自动完成部署——从设计研究到上线，全程不需要写一行代码。

## 常见问题

**它真能做出不像模板的网站吗？**
能，前提是你开头把「谁看、记住什么、接着做什么」说清。它先研究真实网站再做设计，而不是套一套现成布局。你提供的头像、作品和成绩，也只能用确认过的，不会拿生成图冒充。

**我完全不会写代码能搞定吗？**
能。从装 Skill、开工到部署 GitHub Pages，都是一句话交代。你全程只在开头说清需求、最后验收，不需要碰代码。

**参考网站会被直接抄过去吗？**
不会。参考网站只用来理解层级、排版和交互，有辨识度的布局和素材不能照搬。生成图也只能做气氛和插画，不能当你的照片或客户案例。

**GitHub Pages 部署要我自己配仓库吗？**
不用。你一句话让它部署，没登录会先引导登录，之后自动完成。最后拿到一个能访问的链接就行。

**提示词只要写一句话就够吗？**
开头可以。但你交代得越具体——身份、想展示什么、全网 ID——它越能直接进研究阶段，少问一轮。只写「帮我做网站」也行，它会先和你确认方向。

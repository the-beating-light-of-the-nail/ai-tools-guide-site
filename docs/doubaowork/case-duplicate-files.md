# 重复文件和冲突版本，先看差异再决定

> 场景：朋友发来一整个文件夹让帮忙清理——5 个子文件夹、9 个 Word 文档，其中 3 组连名字都很像。按文件名去重？名字相同或相近的文件，内容还真不一定一样，有些还是不同阶段留下的版本。

开始前先约定：**这一轮只分析、给建议，不直接删除任何文件**。等每组文件的关系理清楚，再由文件所有者确认哪些归档、改名或保留。

## 第一步：先列清单，再用文件指纹筛真重复

先扫描文件夹，把 9 个文档的名称、大小和路径列成清单。清单里有 3 个文件都叫《2026 年度自媒体带货合规全景手册》、2 个都叫《自媒体爆款文案库与黄金开头话术精选》——如果只按文件名处理，这两组都会被当成重复文件：

```text
帮我检查这个文件夹里哪些文件是真重复、哪些只是名字像。
先看内容是不是一模一样，再看名字像但内容不同的文件差在哪。
```

"文件指纹"是根据文件数据算出的**哈希值**：哈希相同，可判定字节层面完全一致；哈希不同，只能说明文件变过，还要继续比内容。实测结果：

- 3 个《合规全景手册》哈希相同——同一文件的 3 个副本；
- 2 个《文案库》哈希不同——需要看内容；
- 2 个《极光修护精华测评脚本》哈希不同——需要确认版本差异。

到这一步只有第一组能确认为完全重复。**庆幸没有一开始就按文件名清理。**

## 第二步：指纹不同，看内容差在哪

让豆包工作读取哈希不同的两组文档，对比主题、结构和关键段落，弄清它们是两份不同资料，还是同一内容的不同版本：

- **两份《文案库》面向不同平台**：一份讲抖音口播话术（开头、节奏、主播表达），一份讲小红书图文（标题、封面、排版、配图）——内容和用途都不一样，需要同时保留，改名区分场景即可；
- **两份《测评脚本》是不同阶段的版本**：博主口播版适合出镜但文末标注"缺检测报告和纯度说明，需与品牌版合并"；品牌方合规批注版有法务要求、检测资质、价格机制和上线日期，表达更正式——口播版保留表达方式、批注版补齐合规信息，**两份都没完成最终交付，都保留最稳妥**。

顺带检查文件的共享与引用情况：本次都是本地文件、无外部链接。但这只代表当前检查范围——文件来自共享盘、项目系统或协作空间时，移动前还要向实际使用者确认。

## 第三步：按差异分四类处理

| 类别 | 判定 | 处理 |
| --- | --- | --- |
| 内容完全一致 | 哈希相同 | 保留一份正式版（所有者确认），其余移入可恢复归档 |
| 同一项目的阶段版本 | 内容互补、标注待合并 | 两份都保留，标明"待合并"，最终版完成后再判断 |
| 同名但内容不同 | 面向不同平台/用途 | 都保留，改名区分（如"抖音口播版"/"小红书图文版"） |
| 无重复 | 只有一份 | 保持原样 |

## 第四步：预演清单，确认后再操作

先让豆包工作生成一份**预演清单**，暂不移动或改名任何文件，逐项列出建议动作和判断依据，有异议直接改，全部确认后再执行：

```text
把上面的分析整理成一份清单，写清楚每个文件怎么处理、为什么。
确认后只做移动和归档，不直接删除。
每个被移动的文件都记好原始位置，方便以后恢复。
```

采用**可恢复的归档方式**：用"00_去重归档_可恢复"文件夹存放确认重复的副本，不执行永久删除；每个被移动的文件记录原始路径、归档路径、大小和修改时间——恢复时不用凭印象回忆原位置。

## 结果

9 个文档最终 2 份完全重复的副本移入可恢复归档，7 份保留，全程零永久删除：3 份合规手册保留 1 份；2 份测评脚本都保留并标记待合并；2 份文案库都保留、改名建议待确认；Q2 复盘报告和 Q3 招商看板原样不动。

以后清理文件夹时，先分清**完全重复、阶段版本、同名不同内容**三种情况——只有内容完全一致的副本才进归档清单。多一步比较，少很多误删后的麻烦。

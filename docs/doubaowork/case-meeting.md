# 一场会议，从会前准备到待办落地

> 场景：会开完了，事情却不一定跟着落地。用 AI 把"记过了"变成"有人接、有截止、可检查"。

会开完了，事情却不一定跟着落地：讨论了不少内容，群里留下几句"回头跟进"，散会后再问谁负责、什么时候完成，大家往往还得重新翻记录。哪些话已经形成决定，哪些还只是想法，哪些任务要马上交给具体的人？先把这些分清楚，纪要才不会停在"记过了"。

一场会议可以拆成三段：**会前**让参与者带着同一份背景进入讨论，**会中**保留原始记录，**会后**把决定和行动项交给具体的人。纪要只是中间一步，还要连接上周任务和下次检查。

在整个流程里，模型适合处理**整理、对照和提取**；负责人、截止时间、延期原因和最终决策仍以原始材料为准。材料里没写清楚的地方，保留"待确认"比补一个完整答案更安全。

## 逐字稿整理成标准会议纪要

逐字稿里常见口头语、重复讨论和临时岔话，直接压缩很容易把结论一起压掉。整理时先识别议题，再分别提取讨论依据、明确决定、行动项和仍有分歧的事项：

```text
请阅读附件《产品周会逐字稿.docx》，将其整理成一份正式会议纪要。
请删除口头语、重复表达和与会议无关的内容，但不要改变发言人的原意。
纪要需要包含会议主题、时间、参会人、会议背景、议题讨论、明确结论、
已确认决策、行动项和待确认事项。
只有原文明确提到的负责人和截止时间才能填写。
原文没有说明的内容请标记为"待确认"，不要自行推测。
```

执行时，系统会删去口头语和重复讨论，再按会议背景、议题、结论、决策、行动项和待确认事项整理。如果拿到的是**原始音频**，也可以先转成逐字内容再按同样结构整理——省去手工转写，但识别结果仍需结合会议上下文复核。

> 提醒：人名、产品名、数字和否定表达容易影响结论。正式分发前最好回听对应片段，确认系统没有把"讨论意见"写成"最终决定"。

## 跟踪上次会议任务

单篇纪要解决的是"本次发生了什么"，两周材料放在一起才能回答"事情有没有推进"。核对时逐项沿用上周的行动项名称，再从本周逐字稿里找**完成证据、延期说明或取消决定**——没被提到的任务不能自动算作完成：

```text
请同时阅读《上周会议纪要.docx》和《本周会议逐字稿.docx》。
逐项核对上周会议中的行动项，并根据本周会议内容判断其状态：
已完成、进行中、延期、取消和未提及。
对于延期任务，请提取延期原因、新的截止时间和责任人；
对于本周新增任务，请单独列出。
最后生成"上周任务跟踪表"和"本周新增行动项"两个部分。
```

系统会把上周行动项逐条拿到本周内容中核对，再把本周新增任务单独列出——两组内容分开，旧任务不会和新任务混在一起。验收时检查：每项旧任务是否都有状态；延期任务有没有原因、新截止时间和责任人；新增行动项是否确实来自本周会议。

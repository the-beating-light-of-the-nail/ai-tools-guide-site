# 项目结束想沉淀经验，怎么让豆包工作把文件、决策和交付物一起收进知识库？

你接手一个项目，最怕的不是让 AI 写代码难，而是让它真正「懂」你的项目。以前你丢给它一段需求，它凭空编方案；这次你让它把项目知识库和代码放一起看，它把要动的地方规划得清清楚楚，还顺手提醒你一个藏了很久的坑。这篇带你走一遍「项目结束怎么沉淀」。

你大概也攒过这种教训：接手旧项目，文档和代码对不上，问谁谁都说不清。你这次换个做法，让豆包工作先把知识库和代码一起读。你不用自己扒代码，它帮你反向摸清要动的环节；你也不用怕它瞎编，知识库空了它会直接告诉你。你确认完计划，再把调研沉淀回知识库；你盯着每份文档标上负责人和日期，你将来接手的人也省事。

诉求一句话就能交代：

```text
在 wesight 这个项目中，准备添加引擎。我想用 PI Agent 引擎。
现在请结合知识库的内容和代码的现状，PI 引擎的接入，给我出一个执行计划。
```

## 知识库 + 代码一起看

豆包工作先翻了两样东西：飞书里的项目知识库，和代码仓库里的引擎路由、常量定义、适配器、Provider 注册这些接入点——同步对齐沉淀的项目历史上下文和实际运行的架构细节，再决定计划怎么写。

一个意外发现：它第一句话就提醒知识库是空的——只有标题和一个指向已删除子页面的引用。引用这个知识库的人以为里面有答案，其实什么都没有。更让你放心的是，它没有因为知识库空就瞎编，而是明确说明「计划里的 PI 信息全部来自对 pi.dev 官方文档和 badlogic/pi-mono 源码的一手调研」，把信息来源交代得清清楚楚。

> **知识会过期，缺来源、负责人和更新时间后，旧答案会长期误导使用者。**一个空壳知识库比没有更危险——它让每个引用它的人都误以为「这里有沉淀」。

从代码现状它反向摸清了新增引擎要逐层打通的 5 个环节：常量/类型注册 → Provider/环境/安装器 → 运行时适配器 → Router + Main 接线 → Renderer UI，最后补配置同步和全链路测试。几个关键决策都给了明确建议：集成通道走 RPC 模式（`pi --mode rpc`，stdin/stdout JSONL 协议）；新建独立适配器 `PiRuntimeAdapter`（不复用为解析 CLI 文本输出定制的 131KB 适配器，PI 是干净的 JSONL 流）；首版权限直通、二期再接确认弹窗。

## 交付物：一份可落地的执行计划

计划存到 `docs/pi-engine-integration-plan.md`，按 4 个里程碑排了实施顺序和预估工作量：

1. M1 骨架：常量/类型/Provider/安装器——能编译，环境面板出现 Pi 并可检测/安装；
2. M2 核心跑通：PiRuntimeAdapter + Router + Main 接线——跑通一轮对话；
3. M3 完整功能：UI + 配置同步 + 图片/续聊/停止；
4. M4 权限打磨：权限弹窗 + 测试与回归。

它还提前列了 6 个风险点（models.json 的 schema、流式语义、会话续聊策略、Windows 兼容等）。决策不拍脑袋：三个核心决策点清晰呈现、附验证过的默认方案参考，最终决策权完整交还给你——先完成全链路方案推演、再保留核心决策空间，大幅降低沟通内耗。

## 把调研和交付物沉淀回知识库

你让它把调研文档沉淀进项目知识库时，它识别出当前账号只有只读权限，随即自动切换路径导入个人知识库，并完成全量内容校验。这个过程点出一个容易被你忽略的认知：文档的存放位置和可维护权限本身就是项目资产的一部分——如果每份文档都没标注负责人和最后更新时间，知识库很快会变成没人认领、没人敢改的信息孤岛。

你要求「先只做表层骨架，不要真实开发，做完同步到飞书文档」时，它也精准对齐：常量、类型、空适配器、UI 选项都加上，能编译、界面能看到 PI 选项，但不实现真实 RPC 通信。

## 一个健康的项目知识库长什么样

```text
项目知识库
├── 首页
├── 产品与架构
├── 研发规范
├── 会议与决策
│   ├── 会议纪要
│   └── 决策记录 (ADR)
├── 发布与版本
│   ├── 发布记录
│   └── 发布检查清单
└── 团队与职责
```

项目结束，你把文件、决策和交付物一起沉淀；沉淀时记得写上来源、负责人和更新时间。这样，AI 和后来的同事才不会拿着过期的答案走远路。AI 越来越强，上下文（context）就越来越重要。

## 新手常见问题

**豆包工作怎么「懂」我的项目？**
你让它把项目知识库和代码仓库一起读，它对齐历史上下文和实际架构，再出计划。比只丢需求让它凭空编靠谱得多。

**知识库是空的它会不会瞎编？**
本案例里它没有。它第一句就提醒你知识库是空的，并说明信息来自官方文档和源码一手调研。你看到这种交代，反而更放心。

**执行计划里的决策谁拍板？**
它给建议和默认方案，最终决策权交还给你。尤其核心架构选择，你别全交给它，自己确认一遍。

**沉淀回知识库要注意什么？**
你给每份文档标上来源、负责人和更新时间。没这些，知识库很快变成没人认领的信息孤岛，AI 也会拿着过期答案带你走弯路。

**只读权限会卡住沉淀吗？**
会提示。本案例它发现账号只有只读权限，自动切到个人知识库导入并完成校验。你遇到类似情况，看它怎么处理就行。

# 怎么把老同事攒下的飞书运营经验，变成每次任务都能直接调出来的标准做法？

你打开飞书知识库，看到里面躺着老同事一条条攒下来的运营经验。文档不少，可真到要用的时候，你翻半天也拼不出一套能直接照着做的打法。经验就在那儿，却没人翻、没人用——这比没有还让人着急。这篇带你把这份经验整理成一个可复用的 Skill，以后遇到运营问题，让豆包工作直接按老同事沉淀的方法去答，你少走一遍弯路。

> 场景：知识库里躺着老同事攒下的运营经验，没人翻、没人用。把经验文档整理成可复用的 Skill，既减少重复整理，也让 Agent 在实际任务中直接调用。

> 前置条件：豆包登录的账号和要使用的飞书知识库保持一致。

## 先把知识库接进来

在豆包工作里，你可以用 **@ 引用**飞书文档，也能 @ 联系人、云盘文件和对话，把相关内容加载成上下文。顺手一个省事的小招：你把联系人和会前文档都引用进来后，一句话就能把会约了：

```text
给我在飞书上约个会议，加上他 @联系人，
并把会前文档 @内部：小红书运营知识经验 发给他。
```

真的是动动嘴的事情，不用你再去翻通讯录、贴文档链接。

## 怎么把经验做成 Skill

你先别急着让它整理，第一步先盲问一句，确认豆包工作到底能不能读到你的目标知识库：

> 你帮我看看，小红书运营知识库能看到吗？

确认读得到之后，你再让它给方案——毕竟一开始你手上还没有清晰的结构，不如先让它根据知识库内容提建议：

```text
将这个小红书运营知识库整理成一个"小红书运营 Skill"，
把里面的知识融合进 skill 里面去，你会怎么写这个 skill？
```

它给的定位建议很关键。你要留意一点：现有技能里已经有一个 `doubao-newmedia-writing`，专门负责小红书图文和短视频的**内容创作**。你的新 Skill 得避开这块，定位成运营全链路的方法论与 SOP——当用户问起号、定位、选题、标题封面、涨粉、变现、引流、开店、投放、违规申诉这类「运营怎么做」的问题时触发，输出基于知识库沉淀的结构化方法。

## Skill 长什么样

职责边界定清楚后，豆包工作会把 Skill 拆成 `SKILL.md` 主文件（触发判断 + 链路路由 + 工作流）和按六大主题分类的 `references` 资料目录：

```text
xiaohongshu-operation/
├── SKILL.md                        # 触发判断 + 链路路由 + 工作流
└── references/
    ├── 01-起号定位/     # 赛道选择、账号定位、对标与 IP、主页装修
    ├── 02-平台机制/     # 算法与流量、收录与搜索、限流与规则
    ├── 03-内容创作/     # 选题方法、标题公式、文案写作、封面设计、拍摄修图、视频剪辑
    ├── 04-涨粉运营/     # 养号流程、发布与维护、数据与复盘、涨粉技巧
    ├── 05-变现商业化/   # 变现方式、开店与选品、接单与合作、付费投放
    └── 06-引流与合规/   # 引流 SOP、私域运营、合规与资质
```

每个参考文件都会标注来源——它来自知识库里哪份课程或文档，保证知识可回溯。Skill 做完之后，你拿一个实际运营问题测一下，它就能按 Skill 里沉淀的方法论作答。老同事的经验从此不再躺平，而是变成每次任务都能调用的「标准做法」。

## 新手常见问题

**豆包工作能直接读我的飞书知识库吗？**
能，但有个前提：你豆包登录的账号，要和你用的飞书知识库是同一个。账号对不上，它读不到内容，这一步你在开头就确认好。

**为什么不直接让聊天豆包读知识库？**
聊天豆包是回答问题，它不会把经验整理成可复用的结构。豆包工作能把文档变成 Skill，以后每次触发都按同一套方法论走，省得你反复交代背景。

**新 Skill 和已有的内容创作技能会打架吗？**
你要主动避开重复。已经有 `doubao-newmedia-writing` 管内容创作，你的新 Skill 就定位在运营全链路的方法论和 SOP，分工清楚才不混乱。

**做出来的 Skill 怎么知道它真的能用？**
你拿一个真实的运营问题测一下就行。比如问起号或涨粉的具体做法，看它回的是不是基于你知识库的方法，而不是泛泛而谈。

**参考文件会乱标来源吗？**
每个参考文件都标注了它来自知识库里哪份课程或文档。你验收时顺着来源回去核对，知识可回溯，不怕它张冠李戴。

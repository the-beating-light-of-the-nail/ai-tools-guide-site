# 老同事的经验别躺平：把飞书知识库变成可复用 Skill

> 场景：知识库里躺着老同事攒下的运营经验，没人翻、没人用。把经验文档整理成可复用的 Skill，既减少重复整理，也让 Agent 在实际任务中直接调用。

> 前置条件：豆包登录的账号和要使用的飞书知识库保持一致。

## 丝滑的知识库接入方式

在豆包工作里可以用 **@ 引用**飞书文档，也可以 @ 联系人、云盘文件和对话，把相关内容加载为上下文。顺带一个实操彩蛋——引用联系人和会前文档后，一句话就能约会议：

```text
给我在飞书上约个会议，加上他 @联系人，
并把会前文档 @内部：小红书运营知识经验 发给他。
```

真的是动动嘴的事情。

## 打造经验 Skill 的实操

**第一步先盲问**，确认豆包工作能否读取目标知识库：

> 你帮我看看，小红书运营知识库能看到吗？

确认能看到之后，由于一开始还没有明确的结构方案，先让它根据知识库内容给建议：

```text
将这个小红书运营知识库整理成一个"小红书运营 Skill"，
把里面的知识融合进 skill 里面去，你会怎么写这个 skill？
```

它的定位建议很关键：现有技能里已有 `doubao-newmedia-writing`（负责小红书图文/短视频的**内容创作**），这个新 Skill 应避开重复，定位为**运营全链路的方法论与 SOP**——当用户问起号、定位、选题、标题封面、涨粉、变现、引流、开店、投放、违规申诉这类"运营怎么做"的问题时触发，输出基于知识库沉淀的结构化方法。

## Skill 目录结构

明确职责边界后，豆包工作把 Skill 拆成 `SKILL.md` 主文件（触发判断 + 链路路由 + 工作流）和按六大主题分类的 `references` 资料目录：

```text
xiaohongshu-operation/
├── SKILL.md                        # 触发判断 + 链路路由 + 工作流
└── references/
    ├── 01-起号定位/     # 赛道选择、账号定位、对标与 IP、主页装修
    ├── 02-平台机制/     # 算法与流量、收录与搜索、限流与规则
    ├── 03-内容创作/     # 选题方法、标题公式、文案写作、封面设计、拍摄修图、视频剪辑
    ├── 04-涨粉运营/     # 养号流程、发布与维护、数据与复盘、涨粉技巧
    ├── 05-变现商业化/   # 变现方式、开店与选品、接单与合作、付费投放
    └── 06-引流与合规/   # 引流 SOP、私域运营、合规与资质
```

每个参考文件都标注了来源（来自知识库里哪份课程或文档），保证知识可回溯。Skill 制作完成后，用一个实际运营问题测试，它就能按 Skill 里沉淀的方法论作答——老同事的经验从此不再躺平，而是变成每次任务都能调用的"标准做法"。

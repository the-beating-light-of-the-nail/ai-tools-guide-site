# 今天写什么：从热点、同行到本周选题

> 场景：桌面上躺着二三十个题目，却不知道今天先写哪个——怕热点是旧闻、怕同行拆解写成低配复刻、怕选题攒出来了产能跟不上。

这一篇不让豆包工作直接替你"拍脑袋选题"，而是把真实流程分成三步，得到的不只是一串选题，是一条**能重复使用的内容生产线**：

1. 先做一份**带来源、带时间**的热点早报；
2. 再挑一篇同行内容，**拆解方法，不照抄内容**；
3. 最后结合账号定位和实际产能，把候选题排成**一周能执行的行动日历**。

## 用到的 Skill 组合

| 任务 | 组合 | 为什么这样选 |
| --- | --- | --- |
| 当日热点早报 | VOC 与舆情调研 + 公开网页检索 | 能筛选内容、溯源原帖，把旧闻和新报道分开 |
| 同行内容拆解 | 公众号图文与运营策略 + 链接读取 + Lark Doc | 一次完成读原文、事实验真、结构拆解和飞书交付 |
| 本周选题排期 | 爆款标题与选题日历 + Lark Doc | 不只给标题，还按读者收益、可验证性和执行成本排产能 |

## 任务一：热点早报，别只问"今天有什么新闻"

在「技能·连接器·伙伴」搜索「VOC 与舆情调研」添加（注意：该 Skill 只适合网页端和电脑端，手机上不会触发）。只问"今天有什么热点"，AI 很容易把今天新发的旧闻塞进来——要同时交代**时间窗、信源顺序、筛选标准和待核验规则**：

```text
我是一名科技 / AI 类公众号编辑，今天需要为编辑部准备一份「AI 行业选题早报」。

请使用「VOC与舆情调研」技能及公开网页检索能力，检索并核验
【起始日期 00:00】至【今天当前时间】公开发布的 AI 行业信息，重点关注：
- 大模型与 Agent 产品更新；
- AI 办公、内容创作和开发者工具；
- 会真正影响普通职场人的新功能或变化。

请按下面的步骤处理：
1. 先说明本次检索的截止时间和覆盖范围。
2. 区分「事件发生时间」和「文章发布时间」，旧闻不得写成今日新闻。
3. 合并同一事件的重复报道，优先使用官方公告、官方博客或产品更新页。
4. 筛选 5 条最值得编辑部关注的信息，每条给出：事件、为什么值得关注、
   可以怎么写、原始来源链接、时间依据、待确认点。
5. 最后只推荐 3 个最值得今天动手的选题，
   按「账号匹配度、时效性、读者收益、可验证性」说明推荐理由。
6. 对不能确认的数字、价格、版本号和产品能力单独标注，不要补写或猜测。

最终交付一份结构清晰的中文 Markdown 早报，
包含「今日信息表」「今日优先选题」和「待人工复核」三部分。

未经我确认，不要发布内容，不要发送消息，不要修改线上文档或数据。
```

实测它先确认北京时间和检索窗口，再加载舆情能力、搜索、核验，最终交付约 20KB 的早报：5 条重点信息 → 3 个优先选题 → 10 项写作前必复核信息，还抓出 4 条"文章近期出现、但事件不在时间窗内"的旧闻。**最容易翻车的情况**是把其他媒体今天重发的旧闻误写成"产品今天刚发布"——在提示词里把"事件发生时间"和"文章发布时间"拆开，就能过滤掉。

> 把早报当选题雷达，不要直接当成可发布稿：所有带"待确认"的价格、跑分、用户量，正式写作前都要回到官方来源再核一遍。

## 任务二：同行爆文，拆解而不照抄

热点早报里出现一篇 36 氪的爆款文章。不是让豆包工作"仿写一篇"，而是把它当作**同行样本**来拆。用「公众号图文与运营策略」技能（含选题、验真、文章评估和运营复盘，成果先交付为飞书文档）：

```text
我是一名科技 / AI 类公众号编辑。请使用「公众号图文与运营策略」技能，
拆解下面这篇公开文章，但不要照抄文章表达：

文章链接：https://36kr.com/p/xxxxx

请按下面的顺序处理：
1. 先读取文章，列出实际读取到的标题、作者 / 媒体、发布时间和原始链接；
   读不到的字段标为「待确认」，不要猜。
2. 把文章中的「可核验事实」和「作者的判断 / 修辞」分开。
   涉及参数、价格、跑分、用户量和性能对比时，说明原文依据是否足够。
3. 从 6 个维度拆解它为什么容易吸引点击和读完：
   开头钩子、标题承诺、叙事结构、信息密度、证据用法、结尾动作。
4. 输出一张拆解表，每个结论都要带文章中的位置依据或内容摘要；
   不要连续摘抄原文，不要复制有辨识度的句式。
5. 总结 5 个可以学的方法、3 个不能照搬的元素、5 个写作前必须复核的事实。
6. 基于同一事件，给我的公众号设计 3 个全新的选题角度，
   面向普通职场人和开发者，强调实测、教程或决策价值，不做同义改写。
7. 做一次自检：是否把作者观点写成事实，是否混淆文章发布时间和事件发生时间，
   是否出现无法追溯的数字。

请将最终结果写入一份新的飞书文档，并返回可访问链接。
未经我确认，不要发布内容，不要发送消息，不要修改其他线上文档或数据。
```

最关键的是三句边界：**事实和观点分开、每条结论给位置依据、不能连续摘抄**——没有这三句，拆解很容易变成高级一点的洗稿。实测产出：13 项可核验事实逐条判断依据是否充分；8 处作者判断或修辞单独标出；6 维传播拆解；5 个可学方法 + 3 个不能照搬元素 + 5 个必复核事实；3 个需要原创实测支撑的新选题。比如原文"价格只有 1/40"很有冲击力，但输入输出如何加权并不明确——豆包工作没有把这些数字当铁证，而是留在复核清单里。

这一步回答三个问题：**它凭什么吸引人点开？哪些写法可以学？哪些事实必须重新验证？**

## 任务三：把选题排成这周真正能做的

有了热点和拆解，还有个现实问题：时间不够。用「爆款标题与选题日历」技能，候选题之外**一定要写清真实产能**：

```text
我负责一个科技 / AI 类公众号，想把本周的候选题目排成一份真正能执行的内容日历。

账号定位：
- 面向想用 AI 提升工作效率的普通职场人和开发者；
- 主要写 AI 工具实测、开源项目、保姆级教程和真实工作案例；
- 语气口语化，强调「看完能照着做」，不写空泛趋势稿。

本周可用产能：
- 可以完成 5 篇公众号图文；
- 其中 2 篇可以完整实测并制作 6—10 张步骤截图；
- 其他 3 篇需要控制在半天内完成。

候选题目：
1.【题目一】 2.【题目二】 ……（列出你的候选题）

请使用「爆款标题与选题日历」技能，按下面的顺序处理：
1. 先检查输入是否足够，不足的地方列成待确认项，不自行编数据。
2. 给每个选题按 1—5 分评估：账号匹配度、读者获益、时效性、可证明性、执行成本。
3. 结合产能选出 5 个选题，排入周一至周五，标明「深度实测」或「半天快写」。
4. 每个选题给出：推荐理由、读者收益、建议内容形式、需要准备的材料、
   一个主标题和一个 A/B 备选标题。
5. 对未入选的选题，说清「为什么这周先不做」，不要用「不够热」一句带过。
6. 做一次自检：工作量是否超出产能，是否有两篇以上抢同一类读者需求，标题是否夸大。

请把最终结果写入一份新的飞书文档，并返回可访问链接。
未经我确认，不要发布内容，不要发送消息，不要修改其他线上文档或数据。
```

实测它先检查当天日期、候选题和产能——因为实测当天是周四，它把"本周"解释为下一个完整工作周，并把这个假设写进待确认项等你确认。最终排期 2 个深度实测 + 3 个半天快写；两个落选选题的原因也很具体：一个需要 1—2 周深度测试当前产能不够，另一个偏运营方法、与账号核心读者不够贴。它还主动留下 4 个待确认项（排期起点、发布时间、标题里真实经历能否成立、工具数量承诺是否实测过）。

## 记住这套提示词骨架

换成法务、HR、销售、产品经理也能直接套这四层：

1. **先写清角色和受众**：你是谁，内容给谁看；
2. **再写清约束**：时间窗、产能、数据权限、不能做什么；
3. **规定判断标准**：匹配度、收益、时效、证据、成本；
4. **要求留下复核清单**：哪些是事实、哪些是假设、哪些数字还不能写。

AI 真正好用的地方，是把 30 个候选筛到 3 个，并告诉你**为什么是这 3 个、今天先做哪个、写之前还要复核什么**——这才是内容团队能落地的"今天写什么"。

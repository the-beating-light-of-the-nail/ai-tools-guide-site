# 爆款公众号文章转短视频

> 场景：把公众号文章改成短视频，很多人的做法是复制全文扔给 AI，说一句"帮我改成 60 秒口播"。AI 很配合地删掉一半内容，加一句"你敢相信吗"，补一个"赶紧点赞收藏"——字少了，视频却不一定能用，原文的条件、时间和个人实测还容易变味。

实测拿公众号文章《我把电脑外包给豆包后，效率飞升！【附教程】》跑通完整链路（只到本地成片，未上传发布）：

```text
公众号原文
→ 短视频脚本与逐秒分镜
→ 真人口播 + 产品录屏 + 配图素材包
→ Remotion Skill
→ 代码检查、渲染、ffprobe 和抽帧验收
→ 本地 MP4 成片
```

工具分工：**编剧和剪辑是两件事**。脚本不好要改的是信息取舍，素材缺失要补拍，成片黑屏或音轨不对是剪辑工程——两个流程拆开，哪一步出问题一眼就能看出来。

| 阶段 | 采用 | 负责什么 |
| --- | --- | --- |
| 原文整理 | 网页正文提取 | 留住原文事实、条件和案例顺序 |
| 脚本与分镜 | 短视频脚本编剧（工作伙伴） | 选角度、写口播、拆逐秒画面、事实自检 |
| 素材管理 | 本地电脑能力 + 素材清单 | 核对视频、录屏、图片和路径是否存在 |
| 真正剪辑 | Remotion Skill | 复用项目、组织时间线、渲染 H.264 MP4 |
| 验收 | ffprobe + 均匀抽帧 | 检查时长、分辨率、帧率、音轨、黑屏和截断 |

## 第一步：获取原文，找编剧伙伴

原文链接直接交给豆包工作提取内容。然后到「技能·连接器·伙伴」切到「工作伙伴·小队」，搜索"视频"找到**短视频脚本编剧**——它和普通写作 Skill 的区别是：不只交付一段口播，还会按时间段安排动作、画面和字幕。上传事实母稿，把目标时长、受众、素材条件和安全边界一次性写进提示词：

```text
我是一名公众号作者，准备把自己的长文《文章标题》改成一条 3 分钟以内、
可以直接拍摄和剪辑的短视频。

输入材料：
- 原文链接：【链接】
- 已从原文清洗并核验的事实母稿：上传的《公众号原文事实母稿.md》

请你以"短视频脚本编剧"的工作方式处理：
1. 先读取事实母稿，列出不能改坏的事实和需要保留限定词的数字。
2. 从原文的真实任务里挑最适合短视频表达的 3 个，
   不要为了塞满而把所有内容念一遍。
3. 写一版 150—180 秒的第一人口播稿。开头 5 秒直接制造反差。
4. 口语化、短句、有停顿感，保留本人实测的语气；
   不要写成产品发布会，也不要加入没发生过的功能。
5. 把口播稿拆成逐镜头表格，包含：时间段、口播、画面、素材类型、
   屏幕大字、转场、风险备注。
6. 优先复用现有口播视频、产品操作录屏和文章配图；
   缺素材的镜头明确标"需补拍"，不要假装素材已经存在。
7. 最后做一次事实自检，逐项检查平台差异、帧率、时长、数量、发布日期
   和"效率提升"是否仍保留原文条件。

最终请交付：口播稿 + 逐镜头剪辑表。
聊天里只汇总：成片建议时长、镜头数、复用素材数、需补拍数。

安全边界：只生成本地脚本和分镜，不上传、不发布，不修改原素材，
也不要把个人实测写成普遍承诺。
```

实测交付了 3 套脚本（总览角度 / 手机布置电脑执行 / AI 干活但满足感仍属于人），每套按时码拆开，列了平台、目标受众、传播目标和拍摄条件，还把发布前检查分成"已通过"和"仍待人工"两类。

## 第二步：整理素材包

脚本解决拍什么，素材包决定画面：前段真人口播（开场、问题和能力解释）、中段操作录屏与口播（真实任务的电脑操作）、结尾真人口播（结论和行动提示）、视频封面，加上工作任务模式截图（解释"不是只聊天"）和技能连接器截图（解释为什么有现成工具要优先用）。**给每个素材起一个能说明用途的名称**，豆包工作剪辑时就知道什么情况用哪个素材。

## 第三步：上传 Remotion Skill 做剪辑

技能页搜索"视频剪辑"若无结果，走「新建 → 上传技能」（[Remotion 官方提供 AI Skill](https://www.remotion.dev/docs/ai/skills)）。上传包必须包含 `SKILL.md`——把本地验证过的 Remotion Best Practices Skill 打包成 ZIP 上传，安装后在「我的技能」里开启开关。

> Skill 不是视频模板，它更像一份给 Agent 的**专业工作说明**，告诉它创建 composition、处理素材、做时间线、渲染和验收时应该遵守什么规则；真正的素材和项目仍由你提供。

调用时把四件事说清——用哪个 Skill、读哪些素材和项目、怎么验收、哪些动作禁止：

```text
请使用当前已安装的 Remotion Skill，把素材包剪成一条可播放的视频。

输入：
- 口播视频、操作录屏和配图：以《素材清单.md》中列出的本地路径为准
- 口播稿与逐镜头剪辑表：使用上一阶段已验收的文件
- 已有 Remotion 项目：【替换成你自己的本地项目绝对路径】

执行要求：
1. 先检查素材清单和文件是否存在，缺失项先列出来，不要编造。
2. 复用已有 composition，不要重建项目，不要覆盖原始视频。
3. 保留真人口播主线，在对应段落插入产品操作录屏、界面图和章节提示；
   避免用装饰动画盖住真实界面。
4. 画面比例、分辨率、时长以现有 composition 为准；
   所有数字和功能描述必须符合事实母稿。
5. 运行代码检查和类型检查，再渲染 H.264 MP4。
6. 渲染后用 ffprobe 核对时长、分辨率、帧率、视频编码和音轨；
   再均匀抽帧检查开头、三个案例段、结尾有没有黑屏、错字、截断和隐私信息。

最终交付：本地 MP4 成片 + 一张接触表或多张验收抽帧
         + 一份简短验收记录（文件路径、媒体参数、已知限制）。

安全边界：只在本地项目中生成新文件，不删除或覆盖原素材，不上传、不发布。
```

提交后它先读 Remotion Skill、再探查现有项目和素材清单——这才算真正用到了 Skill。最终交付里除了成片，还列出 composition、画面和音频参数、时间线结构。

## 人的部分仍然最值钱

以前总觉得"根据文章做条视频"不难，真跑一遍才发现：文章里最有价值的是**事实和观点**，视频里最费劲的是**口播、素材和剪辑**——需要一条完整生产线才能提高产能。AI 能把这条生产线整合起来，但最有价值的部分仍然属于人：把重复劳动交给 Agent，把省下来的时间留给那些只有你能做的选择。

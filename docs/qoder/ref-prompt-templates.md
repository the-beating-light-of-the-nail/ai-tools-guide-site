# 常用指令模板

拿来即用的委派模板。`{}` 内替换成你的实际内容。写法要点见[Spec 驱动开发](/qoder/05-spec-driven)。

## A.1 需求委派模板（Spec 驱动）

```text
任务：{一句话目标}

背景：
- 项目：{技术栈 / 模块位置}
- 动机：{为什么要做}

要求：
- {功能点 1}
- {功能点 2}
- {技术约束}

验收标准：
- {可判定的检查项 1}
- {可判定的检查项 2}

边界（本期不做）：
- {明确排除的内容}

代码风格遵循 .qoder/rules/project.md。
```

## A.2 Bug 委派模板

```text
修复问题：{一句话}

现象：{预期 vs 实际}
复现：{命令 / 步骤，概率}
已知线索：{环境差异 / 疑似方向}
要求：先定位根因（写证据链），再修复；禁止掩盖（sleep/跳过/放宽断言）
验收：{复现命令} 全绿 + 补充边界测试
```

## A.3 原型快产模板

```text
做一个{类型}的可点原型：
- 用户流程：{步骤与分支}
- 每页核心元素：{字段 / 状态 / 校验}
- 异常路径：{空态 / 报错 / 二次确认}
- 本期不做：{后端 / 登录等}
- 用途：{演示场景与时间}
```

## A.4 数据周报模板

```text
读取 {文件/来源}，生成周报网页 report.html：
- 汇总指标：{指标 1 / 2 / 3}，附环比
- 图表：{维度}柱状图、{维度}趋势折线图
- 异常高亮：波动 ±{N}% 标黄
- 每个数字附来源，便于抽查
```

## A.5 重构委派模板

```text
重构 {模块/类}：
- 保持 {对外契约} 不变（向后兼容）
- 现有测试全部通过，不得修改断言
- 分 {N} 步提交，每步可独立运行
- Spec 中说明每步的风险与回退方式
```

## A.6 代码考古三问（Ask 模式）

```text
这个模块的分层与职责是什么？
{具体行为}是从哪里实现的，调用链是什么？
哪些模块依赖了{组件/服务}？
```

## A.7 项目规则模板

```yaml
rules:
  - name: {规则名}
    description: {可判定的要求}（原因）
```

## A.8 模式选择速查表

| 情况 | 选择 |
| --- | --- |
| 看代码、问问题 | Editor · Ask |
| 小步修改，全程盯着 | Editor · Edit |
| 多文件任务，看 diff 逐个 Accept | Editor · Agent |
| 复杂功能 / 重构 / 严格质量 | Quest · Spec 驱动 |
| 0-1 建站 | Quest · 搭建网站 |
| 快速验证想法 | Quest · 原型探索 |
| 简单任务快速验证 | Quest · Local |
| 多任务并行 / 保主干干净 | Quest · Worktree |

## A.10 验收三问（任何任务通用）

1. 产物我能打开 / 能运行吗？
2. 抽查项与源头一致吗？
3. 拿出去之前，我自己完整走过一遍吗？

# 第一次 Quest 实战

Quest 是 Qoder 的招牌能力：把一个长程任务委派给 Agent，它在独立视窗里持续执行，你像验收者一样跟踪进度、审查产物。这一篇用一个真实小任务走完全流程。

## 任务选择

第一次 Quest，建议选一个**边界清晰、可验收**的任务，例如：

> 给我的静态博客加上暗色模式：遵循系统偏好，提供手动切换按钮，按钮状态持久化，不引入新依赖。

为什么它适合练手：涉及多文件（布局、样式、脚本）、有明确验收标准、但范围可控——一两个小时能验收完。

## 第一步：写清任务书

Quest 效果好不好，一半取决于你的任务描述。一个好任务书包含三要素：

1. **目标**：要做什么、为什么
2. **边界**：动哪些文件/目录，明确不要做什么
3. **验收标准**：怎么算完成，最好可逐条勾选

上面那个任务的验收标准可以写成：

- [ ] 系统偏好为深色时，首次访问自动启用暗色模式
- [ ] 右上角有切换按钮，图标随状态变化
- [ ] 手动选择后刷新页面，仍记住我的选择
- [ ] 不新增任何 npm 依赖
- [ ] 主流浏览器下无布局错乱

## 第二步：发起 Quest

打开项目后，进入 Quest 视窗，把任务书贴进去并发起。Agent 会自主拆解步骤并开始执行。

## 第三步：跟踪进度

执行期间你不用盯着。随时回到 Quest 工作台，可以看到：

- **看板**：任务被拆成了哪些步骤、各自状态
- **进度**：当前在执行什么、产出了哪些文件
- **产物**：已完成的代码变更

发现方向不对，尽早打断并补充说明，比等全部做完再返工便宜得多。

## 第四步：审查交付

任务完成后逐项对照验收标准：

1. **过 diff**：逐个文件看修改，重点看有没有越界改动（动了任务书之外的文件）
2. **跑验收**：按清单逐条勾选——切系统主题、点按钮、刷新看持久化
3. **提返工**：不达标的地方用自然语言指出，让 Agent 在当前基础上修改，而不是推翻重来

## 常见新手坑

| 坑 | 后果 | 对策 |
| --- | --- | --- |
| 任务描述只有一句话 | Agent 自由发挥，产物不可用 | 写三要素任务书 |
| 一次 Quest 塞十个需求 | 中途跑偏难定位 | 一个 Quest 一个主题 |
| 不看 diff 直接接受 | 暗改了别的文件都不知道 | 每次必过 diff |
| 大项目第一次就委派核心模块 | 上下文不足，质量差 | 先用小任务建立信任 |

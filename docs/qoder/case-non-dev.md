# 案例：非开发者的数据、周报与原型

## 场景与问题

你不是程序员。运营要做每周数据汇总，产品经理要一个能点的原型拿去对齐，老板要一份像样的汇报页。过去的解法是学 Excel 高级用法、求人写脚本、或者花钱买工具。现在，用 Qoder 的**通用模式**：用自然语言描述目标，Coding 与工具能力在背后完成一切，你只需要判断结果对不对。

通用模式的关键设计：**你面对的是任务和结果，不是代码**。产物是能打开的网页、能读的表格、能演示的原型。

## 案例一：每周数据汇总

**输入（每周一早上，5 分钟）：**

```text
读取 data/ 目录下上周的 7 个销售明细 CSV，生成周报网页：
- 汇总表：GMV、订单数、客单价、退款率，附环比上周
- 分渠道柱状图、分日趋势折线图
- 异常高亮：环比波动超过 ±20% 的渠道标黄
- 输出一个 report.html，双击就能打开，样式简洁
```

**验收：** 打开 report.html，抽查三个数字与原始 CSV 手工核对一致。

## 案例二：产品原型

**输入：**

```text
做一个「活动报名表单」的可点原型：
- 字段：姓名、手机号、部门、活动场次（三选一）、备注
- 手机号格式校验，场次必选
- 提交后进入成功页，显示报名编号（本地生成即可）
- 用于明天上午的需求对齐会，不求后端，求可演示
```

**验收：** 明天的会上，把这个页面投屏，走完一遍完整流程。

## 案例三：汇报页

**输入：**

```text
把 summary.md 里的项目进展整理成一个一页式汇报 HTML：
- 顶部三个关键指标卡
- 中间按「进展 / 风险 / 计划」三栏
- 底部时间线
- 深色商务风，中文排版舒服
```

## 非开发者使用守则

1. **永远先给样例**：给一小段真实的输入文件（脱敏），产物质量立刻可控；
2. **说「判断标准」而不是「技术实现」**：「波动超 20% 标黄」比「写个脚本」有效；
3. **数据脱敏再进入对话**：手机号、身份证、客户名，进 Qoder 前先处理；
4. **产物自己核一遍数字**：AI 算错数字的概率虽低但存在，汇报翻车的成本很高；
5. **沉淀模板**：每周重复的任务，第一次调好后把提示词存下来，下周改个日期就能用（见[常用指令模板](/qoder/ref-prompt-templates)）。

## 验收标准（通用三问）

- [ ] 结果我能打开、能看懂吗？
- [ ] 抽查的数字/内容与源头一致吗？
- [ ] 拿给别人（老板/同事）之前，我自己演示过一遍吗？

## 复盘要点

非开发者从 Qoder 获得的不是「学会了编程」，而是**一支随叫随到的技术小队**。判断力是你的，生产力是它的。

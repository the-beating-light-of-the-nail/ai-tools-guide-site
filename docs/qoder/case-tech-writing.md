# 案例：技术写作与内容增长闭环

> 工程师的内容产出（技术博客、开源 README、教程、周报）长期是「重要但永远排不上」的事。本章案例：用 Qoder 搭一条「输入 → 草稿 → 发布 → 数据回流」的内容流水线，一个人维持了双周更的技术专栏一年，并把其中的方法反向沉淀成了 Skill。

## 内容为什么做不起来

复盘多数内容计划失败的原因，不是「不会写」，而是三个环节的摩擦：

1. **冷启动摩擦**：从空白页到初稿最痛苦，于是永远「下周开始」；
2. **质量摩擦**：写完的东西怕丢人，反复打磨到放弃；
3. **频率摩擦**：一次写作消耗太大，无法持续，断更两次后专栏死亡。

Qoder 能压掉前两个摩擦的**成本**，第三个要靠**流水线**解决。注意：AI 不负责「值得说的东西」——选题、观点、真实经验仍然必须是你的，AI 负责把它们变成成稿。

## 流水线设计：四站式

```text
素材库（日常积累）
   │
   ▼
第 1 站 选题会：从素材里筛出值得写的
   ▼
第 2 站 初稿：结构化扩写，1 小时出初稿
   ▼
第 3 站 人肉编辑：观点核对 + 声音校准（不可外包）
   ▼
第 4 站 发布与回流：多平台发布 + 数据回到素材库
```

素材库是起点，也是最常被忽略的资产。日常工作中随手记：

```text
# material/2026-08-14.md（一条素材的格式）
- 事件：排查了一个 3 天才定位的内存泄漏
- 反直觉点：真凶不是泄漏，是缓存无上限
- 可引用物：火焰图截图、最终修复 diff（12 行）
```

一条素材 3 分钟。**素材库的存在让「写什么」不再是每次从零开始冥想。**

## 第 2 站：初稿 Skill

初稿质量的稳定性来自一个写作 Skill。核心结构：

```markdown
<!-- .qoder/skills/tech-article/SKILL.md -->
# 技术文章初稿

## 输入
素材文件 + 目标读者画像 + 目标平台（博客/公众号/掘金）

## 写作步骤
1. 读素材，列出文章要回答的 3 个核心问题（不超过 3 个）
2. 用「问题驱动」结构组织：场景 → 冲突 → 解法 → 可复用的方法论
3. 扩写初稿，规则：
   - 每段只承载一个观点，段首句即论点
   - 代码块必须可直接运行或明显标注为节选
   - 数据与结论成对出现（"快了 3 倍"必须伴随测量方法）
   - 禁用空话：「众所周知」「毋庸讳言」「在当今快速发展的时代」
4. 产出：初稿 + 3 个自检问题（哪段最弱？哪里缺证据？标题的承诺兑现了吗？）

## 约束
- 不虚构素材里没有的数据、引文、案例
- 我的口语风格样本见 style-samples.md，初稿对齐该风格
```

两个关键设计：

1. **「3 个自检问题」**让 AI 交付初稿时同时交付「我知道我哪里弱」，人的编辑就有了靶子；
2. **风格样本文件**：把你过去写的 3 篇满意文章放进 `style-samples.md`，让初稿对齐你的声音而不是「AI 通用腔」——这是人设保真的核心手段。

## 第 3 站：人的编辑清单

不可外包的编辑环节，一份 15 分钟的固定清单：

- [ ] 观点核对：每个结论我是否真的认同（AI 会把「部分成立」写成「普遍规律」）
- [ ] 事实核对：所有数字、命令、版本号亲测一遍
- [ ] 删除一处：找到最「AI 腔」的一段删掉重写（通常每篇都有一处）
- [ ] 标题测试：只看标题，我会点开这篇文章吗？

第三条看似刁难，实际有效：**每篇亲自重写一段**，是让整篇文章保持「你的声音」的最小成本动作。

## 第 4 站：发布与回流

发布环节几乎全自动：一次 Quest 把终稿转成各平台格式（公众号去 Markdown 链接、掘金加 tag、个人站生成 front-matter）。数据回流更重要——每篇发布两周后跑一个只读 Quest：

```text
读取本专栏最近 5 篇的阅读/完读/转发数据，产出：
1. 哪类标题的打开率高（列出共性）
2. 完读率最低的文章，弃读大概率发生在哪一节
3. 下 3 个选题建议（基于数据 + 素材库）
```

这个循环让内容从「自我表达」逐渐校准为「读者需要」——**素材库是弹药，数据回流是瞄准**。

## 周报与内部文档：同一套流水线的变体

同一个模式换参数，就是团队场景的版本：

- **周报**：素材源换成 git log + issue 闭环记录，输出对象换成上级视角（进展/风险/需要的支持），30 分钟出稿；
- **方案文档**：素材源换成 Quest 的计划阶段输出（本来就要写计划，顺手成稿），Spec 的验收标准直接变成文档的「验收」小节；
- **事故复盘**：素材源换成排查过程的对话记录，AI 负责按「时间线-根因-行动项」结构整理，人负责根因判断的签字。

共同原理：**你在工作中留下的结构化痕迹（Spec、计划、diff、对话）都是写作素材**，AI 把「从痕迹到成稿」的摩擦降到接近零。

## 任务清单

- [ ] 建素材库，从今天起每条 3 分钟
- [ ] 写 tech-article Skill，附上你的风格样本
- [ ] 固定 15 分钟人肉编辑清单（含每篇亲写一段）
- [ ] 双周节奏跑一轮完整流水线，第 4 篇后开始看数据回流

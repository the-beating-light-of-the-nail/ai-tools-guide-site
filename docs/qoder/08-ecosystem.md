# 全家桶：CLI、移动端与云智能体

桌面工作台是主入口，但同一个 Qoder 智能体延伸到了终端、IDE 插件、手机和云端。本章讲清楚每个形态的定位，以及怎么组合成一套个人工作流。

## Qoder CLI：终端原生的编程伙伴

Qoder CLI 把 Agent 能力带进终端，既是 AI 编程伙伴，也是**可构建应用的 Agent 引擎**。典型用法：

```bash
# 在任意代码目录直接对话
qoder "解释这个仓库的入口和分层"

# 委派一个任务，交由智能体端到端完成
qoder "把 utils/date.ts 里的函数全部补上单元测试"

# 管道式：把输出交给其他工具
qoder "总结最近的 10 条 commit，按 feat/fix/refactor 分类"
```

CLI 的独特价值：

- **脚本化**：写进 shell 脚本、Makefile、CI 流水线，做提交前检查、发布前总结；
- **服务器上用**：SSH 到远程机器，不装桌面端也能获得完整的 Agent 能力；
- **引擎化**：把它当作构建自己 Agent 应用的执行底座。

## JetBrains 插件

重度 JetBrains 用户不必换 IDE：安装 Qoder 插件后，Editor 级能力（问答、编辑、Agent）直接在 IntelliJ/PyCharm/GoLand 等环境内使用。Quest 的重型任务可以留在桌面端跑，两边共享同一份账号与记忆体系。

## 移动端：任务在口袋里

手机端的核心场景不是写代码，而是**管任务**：

- 通勤时查看 Quest 进度，处理 Action Required 的批准；
- 给运行中的任务追加一句话需求；
- 收到任务完成的报告，先人肉验收一眼。

配合桌面端「下班前启动长任务」的习惯，移动端让你把等待时间变成管理时间。

## QoderWake：7×24 数字员工

QoderWake 面向企业，提供持续在线的数字员工：定时任务、事件响应、按 SLA 推进。适合夜间批量构建与回归测试、监控告警的第一轮自动归因、周期性报告的自动产出。个人用户用不到它也很正常——它是给「headcount 不够」的组织准备的。

## Qoder Cloud Agents

云端托管智能体平台，面向企业多场景集成：把 Qoder 的 Agent 能力接进内部系统（工单、数据库、监控、内部 API）。与桌面端「本地上下文优先」不同，Cloud Agents 的关键词是**集成与编排**。

## 一套推荐的组合拳

以一个独立开发者的一周为例：

```text
周一 早上    桌面端：为本周三个需求各开一个 Quest（Worktree 并行）
周一 白天    JetBrains 插件：边开发边处理 Editor 级小改动
周二 通勤    移动端：批准两个 Action Required，追加一条需求
周三 晚      桌面端：验收完成的 Quest，刷新 Repo Wiki
周五 下午    CLI：总结本周 commit，生成发布说明
周五 下班前  桌面端：启动下周要用的全量 Wiki 生成 / 长任务
```

# 案例：从 0 到 1 搭建一个网站

## 场景与问题

个人开发者要把一个想法快速变成能演示的网站。痛点：传统流程里「想法 → 能演示」之间隔着脚手架、组件、样式、部署一整套体力活，等做完这些，演示的热情已经耗掉一半。

## 准备动作

- 新建空仓库（或空目录），git 已初始化；
- 想清楚一句话需求 + 三条硬约束；
- Quest 场景选择**搭建网站**。

## 操作过程

**第 1 步：描述网站。** 不写代码细节，写页面与行为：

```text
搭建一个开源项目导航站：
- 首页：项目卡片瀑布流，每张卡片显示名称、一句话介绍、星数、标签
- 支持按标签筛选、按星数排序、关键词搜索
- 项目数据从本地 JSON 文件读取，后续会换成 API
- 技术栈：Vite + React + TypeScript，不用重型 UI 库，手写轻量样式
- 深色模式为默认
```

**第 2 步：观察结构生成。** Quest 自动搭建页面结构，Preview Tab 实时预览。此时别追求像素完美，先确认**骨架对不对**：页面齐不齐、交互通不通。

**第 3 步：迭代细节。** 用追加需求的方式一轮一轮修：

```text
卡片间距收紧到 8px
搜索框防抖 300ms
空状态加一个插画位
```

**第 4 步：让它自己查问题。**

```text
跑一遍构建，把控制台报错和明显可访问性问题修掉
```

**第 5 步：部署。** 把部署也委派出去：

```text
写一个 GitHub Actions workflow：push 到 main 时自动构建并部署到 GitHub Pages
```

## 验收标准

- [ ] 首页在浏览器正常渲染，无控制台报错
- [ ] 筛选、排序、搜索三个交互全部可用
- [ ] 深色模式默认生效
- [ ] `npm run build` 通过
- [ ] push 后 Pages 自动部署成功

## 复用模板

```text
搭建一个{类型}站：
- 页面：{页面清单与每页核心元素}
- 交互：{筛选/搜索/表单等行为}
- 数据：{来源与形态}
- 技术栈：{明确到框架与语言}
- 风格：{深浅色/主色/密度}
```

## 复盘要点

- 搭网站场景跳过 Spec，**快是目的**，但三条硬约束（技术栈、数据形态、默认风格）一定要先给，否则返工方向都没了；
- 一句话需求 + 三条约束，是冷启动阶段性价比最高的需求结构。

# 记忆与规则：.qoder 目录

模型能力是通用商品，**上下文才是你的资产**。Qoder 的记忆与规则体系，就是把你的项目上下文沉淀成资产的地方——核心载体是项目里的 `.qoder/` 目录。

## .qoder 目录全景

```text
.qoder/
├── rules/          # 项目规则：编码规范、行为约束
│   └── project.md
├── quest/          # Quest 生成的 Spec 文档
├── repowiki/       # Repo Wiki 自动文档
└── memory/         # 跨会话长期记忆
```

这个目录应该进版本管理——规则和 Wiki 是团队共享资产。

## 项目规则（.qoder/rules/）

规则用结构化的 YAML/Markdown 描述，例如：

```yaml
rules:
  - name: TypeScript conventions
    description: 使用严格 TypeScript，显式标注返回类型
  - name: Commit messages
    description: 遵循 Conventional Commits 格式
  - name: 测试要求
    description: 新增接口必须带单元测试，覆盖正常与异常路径
```

写规则的三个原则：

1. **可判定**：`「函数不超过 40 行」`好于`「保持简洁」`；
2. **有理由**：`「禁止直接 import lodash 全量包（会拖慢构建），按需引入」`；
3. **分优先级**：命名类规则一条，安全类规则一条，别写成一坨。

## 个人偏好（Settings > Memory）

在设置 > Memory 里用自然语言写跨项目的个人偏好：

```text
回调一律用箭头函数
导出的函数必须带 JSDoc 注释
注释用中文写
```

这些偏好在所有项目生效，适合放「你这个人怎么工作」；项目里怎么工作，放 `.qoder/rules/`。

## 长期记忆的运作方式

Qoder 的长期记忆跨会话生效：上一个 Quest 里你纠正过的错误写法、你偏好的目录结构，会在后续任务中被自动引用。实战建议：

- **发现智能体犯同一个错** → 立刻写成规则，不要每次靠嘴纠正；
- **发现某类任务的做法成型** → 提炼成 Skill（见[打造自己的 Skills 与插件](/qoder/adv-skills)）；
- 记忆不是越多越好——定期清理过时规则，规则的权威性来自「每条都算数」。

## 规则与 Spec 的分工

新手常混淆两者：

| | 规则 | Spec |
| --- | --- | --- |
| 生命周期 | 长期，跨任务 | 单次任务 |
| 内容 | 项目怎么做事 | 这次任务要做什么 |
| 谁消费 | 所有后续任务 | 本次执行 |

Spec 里的「验收标准」如果具有普适性（如所有接口都要带异常处理测试），任务结束后应该晋升为规则。

# WorkBuddy 的连接器是什么？接上腾讯系工具让它直接替你办事

你用 WorkBuddy 写完一份纪要，想顺手发到腾讯文档、或者让它帮你建个明天的会议。可它默认碰不到这些外部服务——它待在自己的世界里，看不见你的邮箱和日历。连接器就是那道门：你把微信、腾讯文档、腾讯会议这些账号授权给它，它就能真的去发消息、建会议、读文档，而不只是口头说说。

理解连接器，你先得认识它背后的标准：**MCP**，也就是 Model Context Protocol（模型上下文协议）。这是 Anthropic 在 2024 年底推出并开源的一个开放标准协议，如今已经是 AI 领域最热门的基础设施之一。你把它想成 AI 世界的「USB-C 接口」就对了。

## 为什么需要 MCP

过去，你想让一个 AI 助手（Agent）连上外部工具（比如 GitHub、本地文件系统、PostgreSQL 数据库、Slack 等），开发者得为「每一个 AI 应用」和「每一个工具」都写一套专门的对接代码。要是有 10 个 AI 应用和 10 个工具，就得写 100 个接口——这是个 N × M 的集成噩梦。

有了 MCP，工具开发者只需按 MCP 标准开发一个「MCP Server」（相当于 USB-C 设备），而任何支持 MCP 的 AI 应用（如 Cursor、各类 Agent 框架）只要内置「MCP Client」（相当于 USB-C 接口），就能**即插即用**。这就把 N × M 的复杂开发，简化成了 N + M，你不用再为每个组合单独写代码。你作为使用者，根本不用管底层那一百个接口怎么写。

## MCP 的核心特点

- 统一的标准化协议（告别重复造轮子）

MCP 提供了一套通用规范（基于 JSON-RPC）。无论是读本地文件、查数据库，还是调第三方 SaaS API，AI 都能通过同一套协议逻辑去理解和调用。这大幅降低了 Agent 开发中工具集成的门槛，让你把精力放在核心逻辑上，而不是写繁琐的对接代码。

- 支持三大核心能力

MCP 不光让 AI「做事」，还让它「看数据」和「按套路出牌」，它把三种核心原语标准化了：

- **Tools（工具）**：让你的 AI 执行操作。例如：跑一段代码、在 Jira 建一个任务、往数据库写数据。
- **Resources（资源/上下文）**：让你的 AI 读取外部数据。例如：拿 Git 仓库的文件列表、查向量数据库里的特定片段，作为回答的上下文。
- **Prompts（提示词模板）**：提供预定义的交互模板，让你或 AI 以标准化方式触发特定复杂工作流。

- C/S 架构与高度解耦

MCP 采用客户端-服务端（Client-Server）架构：

  - MCP Host：你用的 AI 宿主应用（如 IDE、Agent 平台）。
  - MCP Client：Host 内部负责和 Server 保持 1:1 连接的组件。
  - MCP Server：轻量级的独立程序，专门负责暴露特定工具或数据的能力。

你看，这三层各管一摊，互不绑架。这意味着你可以随时换底层大模型，或随时加新数据源，而不用重构整个 Agent 系统。

- 本地优先与安全性（隐私友好）

MCP 支持通过本地标准输入输出（stdio）或本地 HTTP 通信。这意味着你的 MCP Server 可以完全跑在本地电脑上，你的数据留在本地。敏感数据（如本地代码、私有数据库内容、电商后台数据）不用上传到云端第三方服务器，AI 模型只在需要推理时取必要的上下文——你不用担心数据被偷偷传走。

## 新建连接器

你还想接自己的业务系统？你到连接器管理页右上角点「自定义连接器」，按引导配置 MCP（含服务地址、鉴权方式），并留意自定义连接器的访问范围由你自己配置。

## 新手常见问题

**连接器、MCP、API 这几个词我总搞混，先记哪个？**
你先记 MCP：它是让 AI 接工具的「USB-C 接口」标准。连接器是 WorkBuddy 已经按这个标准帮你封好的现成服务（微信、腾讯文档等）。API 是更底层、各家自己定义的接口，MCP 在它上面盖了扇更统一的门。

**现在能接哪些连接器？**
当前已支持 QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD 等。你也能在管理页点「自定义连接器」，按引导配 MCP 接更多服务。

**连接器会不会乱动我的账号？**
它只在你授权范围内动作，访问范围由你配置。你让它建会议它就建会议，没授权的它碰不到。第一次用你先在小事上验证，确认它只干了你吩咐的。

**我自己的业务系统能接吗？**
能。你走「自定义连接器」，填服务地址和鉴权方式即可。范围自己定，你别一次放开全部权限。

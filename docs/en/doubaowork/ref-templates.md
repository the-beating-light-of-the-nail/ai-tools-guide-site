# Staring at an Empty Input Box? Paste a Template, Swap the File Name, Send the Job

You've created a new task and you're staring at the input box: how do you phrase this so it actually understands? Don't strain over it. Copy one of the templates below, paste it into a new "work task," then fill in your files, links, time range, and output location. You're only changing file names and ranges—leave the skeleton alone.

Three universal disciplines worth memorizing first: when several files are involved, create a project first; when an external system is involved, confirm the connectors you need are authorized; when moving, overwriting, sending, or publishing is involved, keep a human confirmation step.

## How to Use These Templates

1. **Copy one.** Pick the template closest to the job in front of you—don't write a prompt from scratch.
2. **Fill in the blanks.** Paste it into a new work task, then add your files, links, time range, and where the output should go. You're changing names and ranges, not the structure.
3. **Keep the guardrails.** Anything that moves, overwrites, sends, or publishes stays behind a confirmation from you. For multi-file jobs, make a project first; for Feishu, mail, and similar systems, check the connector is authorized before you send the job.

## Templates You Can Copy

### File Organization

```text
Read the folder I provide; tally file types, counts, and duplicates.
Propose a new folder structure and renaming rules by file type and topic.
Output the plan and a list of expected changes first; move or rename files
only after I confirm.
Do not delete any files; stop and ask when you hit identical filenames.
```

### Excel Analysis

```text
Analyze the Excel file I provide.
First check worksheets, fields, missing values, and outliers; then output
core metrics, trend changes, possible causes, and recommended actions.
Generate a summary report and any needed charts, and state the data range
behind each conclusion.
Do not modify the original file; save results as a new file.
```

### PPT Generation

```text
Generate a roughly 10-slide PPT from this Word document.
Each slide: a title, 3-4 bullet points, and a suggested chart; all data
and conclusions must come from the source text.
Formal style, suitable for a management briefing.
Give the slide outline first; generate the full file only after I confirm.
```

### Meeting Minutes

```text
Organize this meeting content.
Output conclusions, action items, owners, deadlines, risks, and open
questions.
Where an owner or deadline isn't explicit, mark "to be confirmed"—do not
fill one in.
For important conclusions, keep the corresponding original words or
timestamps where possible for review.
```

### Industry Research

```text
Research [industry / company / product] with a time range of [].
Output market background, main players, competitor comparison, trends,
opportunities, and risks.
Keep the source link and publication date for every key fact; where
sources conflict, present them side by side.
Mark unverifiable information as "to be verified"—do not invent.
```

### Scheduled Briefing

```text
Create the task description for a "daily industry briefing".
Every day at [time], summarize the past 24 hours of [topic] in at most 10
items.
Each item carries a title, summary, source, publication time, and link;
merge duplicate events.
When sources fall short, say so—don't invent items to fill the count.
Run it once in a normal work task first; after I confirm the result, I'll
save it under "scheduled tasks".
```

### Using a Work Mate or Squad

```text
Goal: [the deliverable to produce]
Materials: [projects, files, or links]
To be completed by [Work Mate / Work Squad].
First explain the division of labor, handoff artifacts, and the points
where you need my confirmation, then start executing.
Do not send, publish, or overwrite official files without confirmation.
```

## What Each Template Is For

File organization is for when your desktop or Downloads folder has gotten away from you: it proposes a plan before touching anything, and never deletes or rewrites your originals. Excel analysis covers the checks, the metrics, and the charts, saving results as a new file so the original sheet stays put. PPT generation gives you the outline before the full deck, so the direction can't wander off. Meeting minutes pull out conclusions, action items, owners, and dates, marking anything without an owner as "to be confirmed." Industry research attaches a source and a date to every fact, and puts conflicting sources side by side. The scheduled briefing runs once as a normal task before you ever save it as a scheduled one.

If it's your first time, start with file organization and Excel analysis—they're closest to everyday work. Turn to PPT and meeting minutes when you have a review to prepare, and to the research and briefing templates when you need to look outward. Check the numbers and facts before you send anything off. These templates are starting points: add or cut whatever fits your situation, and don't feel obliged to copy every word.

## FAQ

**Can I copy these templates straight over?**
Yes. Create a work task, paste one in, swap the file name and ranges, and send it—you don't write the skeleton yourself. Just check the numbers and facts once the work comes back.

**Are they safe for jobs that send email or messages?**
The templates say no sending or publishing without confirmation. Whenever moving, overwriting, or sending is involved, keep that confirmation step for yourself—don't let it send anything out on its own.

**What should I watch for on multi-file jobs?**
Create a project first and gather the material in one place. And for external systems like Feishu or mail, confirm the connector is authorized before you hand the job over.

**Why run the scheduled briefing once before saving it?**
Run it as a normal task first and look at whether the results are right and the sources hold up. Only save it under "Scheduled Tasks" once you're satisfied, or you'll get a daily push of wrong output.

**If I edit a template, will it still follow my version?**
It will. Whatever file names, ranges, and deliverable requirements you write are what it follows. The template is a starting point; shape it however you need.

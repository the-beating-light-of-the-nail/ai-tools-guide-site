# Common Prompt Templates

## When to Use This Material

If you are organizing your own files, data, weekly report, or meeting minutes for the first time, just pick one concrete task and complete an editable, verifiable draft. Use this appendix's templates only when you want the task more stable, reusable by colleagues, or invoked in a unified format. It is advanced material and does not redefine the stage gates, action permissions, workflow operations, or failure-takeover rules of Chapters 10–12.

This appendix provides invocation wording only and defines no new standards. Before starting, fill in the single task card per the [Chapter 2 task delivery protocol](/en/qwenwork/ch02-task-delivery-protocol); build evidence cards for research claims per [Chapter 8 Research and the Evidence Chain](/en/qwenwork/ch08-research-evidence-chain); and execute the corresponding controls for sending, writing, deleting, publishing, and other actions per [Chapter 11 Security Governance](/en/qwenwork/ch11-security-governance).

In the templates below, `【】` and blank lines are for the reader to fill in. The safety, confirmation, and acceptance sentences in the templates invoke the standards above and cannot replace the authoritative chapters.

## Files

```text
Process [file or directory] per [the task card filled in per Chapter 2].

First, read only and output: the file list, versions and dates, duplicates or conflicts,
missing inputs, suspected sensitive content, and the proposed steps. Do not use materials
not authorized by the task card; list uncertain files only in the confirmation list.

Deliver [directory list / classification suggestions / diff report / editable file] and
self-check against the task card's acceptance requirements. If moving, renaming, writing,
or deleting is needed, first check the required controls per Chapter 11, show the objects,
impact, confirmation points, and rollback method; execute only after obtaining the
corresponding confirmations, and return the operation records and recovery verification.
```

## Data

```text
Analyze [data file or authorized data source] per [the task card filled in per Chapter 2].

First output the field dictionary, data period and version, record counts, missing values,
duplicates, anomalies, and basis conflicts; wait for my confirmation before generating
conclusions. Keep the original inputs; do not overwrite the original files. Any amounts,
dates, primary keys, or summary relations that cannot be verified must be clearly flagged;
never fabricate data.

Deliver [editable detail / summary / charts / validation table], separating data facts,
causal inferences, and suggestions, and execute the task card's acceptance item by item.
If writing back to systems or modifying business objects, follow Chapter 11's control,
confirmation, and rollback requirements.
```

## Reporting

```text
Produce a draft [document / PPT / speech script] on [reporting topic] per [the task card
filled in per Chapter 2].

The audience is [ ], and the decision to support is [ ]. First give the storyline and the
question each page or section answers; generate the editable draft only after I confirm.
All facts and numbers labeled with source, date, units, and applicable basis; uncertain
content goes to the confirmation list, not written as established conclusions.

After completion, accept per the task card and list unresolved questions. Before sending
or publishing, per Chapter 11 show the recipients, final version, key content, impact, and
rollback method, and execute only after obtaining the required confirmations.
```

## Meetings

```text
Organize [meeting materials, transcripts, and attendee list] per [the task card filled in
per Chapter 2].

First distinguish confirmed facts, possible misrecognitions, and missing context. Write
something as decided only when the materials clearly support it; unconfirmed names,
amounts, dates, and ownership go to the confirmation list.

Deliver [minutes draft / decision record / action-item draft / risk list], accepted item
by item per the task card. Do not automatically send minutes, create to-dos, or update
project systems; to perform these actions, per Chapter 11 show the proposed objects and
content, confirmation points, and rollback method, and execute only after obtaining the
corresponding confirmations.
```

## Research Evidence Chain Template

```text
Research [question] per [the task card filled in per Chapter 2].

First give the question tree, hypotheses to verify, and the source plan, prioritizing
[the allowed source scope]. For each minimal claim, strictly build cards per Chapter 8's
single evidence-card standard, with no parallel field system; check the original text,
numbers, dates, qualifiers, and evidence conflicts item by item.

Deliver [research workings / report draft], clearly separating verified facts, evidence-
based inferences, recommendations, and unresolved questions. Content without sufficient
evidence gets its conclusion weakened or removed. If sending, writing, or publishing,
execute the corresponding controls per Chapter 11 and keep confirmation and release records.
```

## Task Delivery and Review Template

```text
First review whether [the task card filled in per Chapter 2] fully conforms to Chapter 2's
single standard; do not convert it to another field system. List missing items, conflicts,
no-permission inputs, and unexecutable acceptance requirements; do not start generating
before the issues are resolved.

Once the task card is confirmed, use only [authorized inputs] to produce [the draft
deliverable]. Before delivery, check against the task card's acceptance item by item,
listing evidence locations, manual edits, anomalies, failed items, and content needing
final confirmation.

If the task includes sending, writing, deleting, publishing, or other external actions,
invoke only Chapter 11's action, data, and professional-consequence controls; first show
the specific objects, scope, impact, approval-record requirements, and rollback method,
and execute only after obtaining the corresponding confirmations.
```

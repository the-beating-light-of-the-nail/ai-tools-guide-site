# Chapter 3: WorkBuddy's Main Interface, Tasks & Workspaces

You can think of the WorkBuddy main interface as three areas: the left side (sidebar) for managing tasks, the center (conversation area) for giving and tracking tasks, and the right side (results area) for viewing files, changes, previews, and final deliverables.

![](/workbuddy/03-interface/assets/001_image_MuLCbdPyDo.png)



## What Each Area Does

| Area | Main use | What to check while using it |
|-|-|-|
| Sidebar | Create, search, switch between, and manage tasks | Whether you're in the right task |
| Conversation area | Describe needs, add information, confirm plans | Whether goals and constraints are complete |
| Results area | View deliverables, all files, changes, and previews | Whether filenames, paths, and changes look right |

The difference between "Tasks" and "Workspaces" in the sidebar comes down to whether you've set up a "Workspace" directory.

A "Workspace" is a directory WorkBuddy uses to manage tasks. Every task gets its own directory space, and the task operates within that space.

If you don't set one up, tasks run in the default installation directory, and conversations are saved under the "Tasks" directory.

## Why Isolate Working Directories

Your working directory is both an efficiency setting and a security boundary. Mixing invoices, weekly reports, and client materials in one big directory increases the risk of misreads, accidental edits, and information leaking across tasks.

We recommend creating a separate directory space per task.

You can also set permissions for each directory space. Enabling "Allow full access" lets the agent read and write files outside the authorized directory — use it with caution and prefer restricting directories per task.

## Three Working Modes

WorkBuddy offers three working modes:

| Mode | Chinese UI label | What it can do | Best for |
|-|-|-|-|
| Ask | 问一问 | Q&A, understanding, and viewing — no file modifications | Getting familiar with materials, confirming requirements |
| Craft | 做一做 | Can directly operate local files, run code and system commands | Tasks with clear paths and lower risk |
| Plan | 想一想 | Generates a plan first, then executes after you confirm | Multi-step, cross-system, or important-file tasks |

![](/workbuddy/03-interface/assets/003_image_W7VqbwVeJo.png)



## Choosing Different Models

The default is Auto mode, but you can specify the model you want to use; different models consume credits at different rates.

![](/workbuddy/03-interface/assets/004_image_OzThbMYn5o.png)

| Task characteristics | What to prioritize |
|-|-|
| Lots of text and long documents | Context length, e.g. 1 million tokens (1M) |
| Images and screenshots | Needs visual understanding capability |
| Frequent simple tasks | Prefer fast, low-cost models |

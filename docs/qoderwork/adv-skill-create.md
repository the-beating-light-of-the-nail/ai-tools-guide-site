# QoderWork 怎么把重复活做成技能？/create-skill 对话式创建一次讲清

你有没有过这种时候：同一段任务说明，这周写了第三遍。周报格式、案件分析流程、店铺日报——每次都从头描述，累且容易漏。你这次写的第三遍，就是该做成技能的信号。QoderWork 把这件事的门槛降到了「说人话」：内置 `/create-skill` 指令，你跟它聊几句，它就生成一份 SKILL.md，以后一句话触发。

> 官方文档：[skills](https://docs.qoder.com/zh/qoderwork/skills) ｜ 实战素材见官方用户案例库。

## 一个真实样本：销售周报技能

社区实测的完整创建过程（CSDN 指南），你照着做是这样的：

1. 你直接在对话里输入 `/create-skill`；
2. 你描述触发语与流程：

```text
创建一个"销售周报"技能：
触发语：生成本周销售周报
步骤：读取 sales/ 目录下的销售数据.xlsx → 计算周环比增长率
（(本周-上周)/上周×100%）→ 生成 Top 5 产品柱状图 →
按固定模板生成 Word 周报，保存到 reports/ 目录。
依赖：Excel 处理、Python-Matplotlib 绘图。
```

3. QoderWork 生成 SKILL.md 并存入 `~/.qoderwork/skills/`，你以后随时能调；
4. 以后任何新任务里你输入 `/`，选「销售周报」，或直接说「生成本周销售周报」就能触发。

更彻底的资产化样本（官方用户案例，一位律师），你也能这样封装：

```text
请把刚才的案件分析流程封装为一个 Skill，命名为"商事纠纷案件分析"：
输入：案件材料文件夹（起诉状、合同、补充协议、微信截图、转账凭证、律师函）；
输出：案件时间线 + 争议焦点 + 证据链分析（标注强/中/弱）+ 诉讼策略报告；
分析框架固定，内容根据每个案件的材料动态生成。
```

20 年的执业经验就此变成团队可复用的标准化工具：新人一键生成、合伙人审核。

## SKILL.md 的质量要点

`/create-skill` 生成的是初稿，你按这张清单过一遍再保存：

- [ ] 触发条件写具体：「当用户要求生成周报 / 数据汇总时」，而不是「处理数据」；
- [ ] 触发语避免与其他技能冲突（冲突会导致无法触发）；
- [ ] 步骤可判定：「第一步核对文件数量是否为 7，不足先提问」；
- [ ] 输出给样例：贴一段期望产物的样子；
- [ ] 声明边界：明确不做什么（「不修改原始 CSV」「不给法律结论」）；
- [ ] 依赖写清楚（需要 Excel / Python / 网络时注明）。

## 从技能到团队标准

官方推荐的进阶路线是：**先用 Skill 跑通最佳实践 → 打包为[专家套件](/qoderwork/05-skills) → 团队统一使用**。你判断某类工作值不值得做技能，就看一句话——「选择你最近一周内重复做过两次以上的工作」。

> 跨工具视角：Skill 的 SKILL.md 规范在 WorkBuddy / TraeWork / QoderWork 三家之间高度相通，你学会一次，三处通用。深度方法论（把书和视频蒸馏成技能集）见 WorkBuddy 板块的[打造 Skill：知识蒸馏](/workbuddy/adv-build-skill/)。

## 常见问题

**我不会写代码，能做技能吗？**
能。你只要用 `/create-skill` 说清触发语和步骤，它生成 SKILL.md，不用你写一行代码。

**做出来的技能会和自己冲突吗？**
会，如果触发语太像。你写具体触发条件，避开别的技能的说法，就不会抢触发。

**团队怎么共用我做的技能？**
你打包进专家套件，或技能页生成分享链接发给同事，对方一键安装。

**分享链接一直有效吗？**
不是，约 24 小时有效。你临时发给同事没问题，长期共用还是走套件或市场。

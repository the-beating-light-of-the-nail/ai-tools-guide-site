# 进阶：三大工作台——设计、幻灯片、写作

通用工作台之外，QoderWork 为三类高频产出建了垂直工作台：设计画布、16:9 幻灯片、长文写作。切换入口在输入框左下角的工作台选择器。

> 官方文档：docs.qoder.com/zh/qoderwork 下的 design / slides / writing 三页。

## 设计工作台：AI 原生的"设计即代码"画布

自然语言描述，在无限画布上获得**可运行、可编辑、可交付**的设计产物；产物被视为代码资产，可一键「交付给 Qoder」（IDE）继续开发。

**八步流程**：切换工作台 → 描述需求（截图和链接可直接粘贴）→ 可选设置（风格参考 / 工作目录 / 保真度 / 组件库）→ 选执行模式（「直接运行」跳过澄清；「进入设计计划模式」先对齐）→ 回答澄清问题（每题有备选项，可"AI 自行决定"）→ 确认设计计划（审核"契约"面板：产物/平台/输出/组件库/保真度/风格）→ 观察生成（左侧"深度思考"实时推理）→ 预览（可点 CTA、看 hover、走查导航流）。

**关键设置**：

| 设置 | 可选值 |
| --- | --- |
| 风格参考 | 自动选择（161 个参考里挑）或指定 Airbnb / Apple / Carbon / Ant Design 等 |
| 保真度 | 线框图 / 高保真（默认） |
| 组件库 | 不指定（HTML-first）/ shadcn/ui / Spark Design / Ant Design |

**迭代三板斧**：追加指令；**Nudge 微调**（配色、间距、圆角参数，无需重新描述）；直接编辑画布背后的设计文件源码。三大机制（Questions 追问、Design Plan、Nudge）解决的是"AI 猜错方向"的老问题——信息不足时先追问，而不是猜。

## 幻灯片工作台：先大纲后成片

右侧画布是 16:9、1280×720 的 HTML 幻灯片工作区。**硬性前置：必须先确认大纲**——「大纲」标签里每节带一句简介和版式标签（封面页/文字大纲/左图右文/双栏/引文等），"接受大纲"才开始生成，不合适可附反馈驳回。

流程：切换工作台 → 描述需求 → 挑模版（可"不使用模版"，内置 35 个）→ 回答澄清（受众、页数、语言）→ **确认大纲** → 看生成过程（缩略图逐张就绪）→ 后处理选项（可全跳过）→ 查看成果。

产出导出：**PPTX、PDF、HTML** 三格式；常用模版可"保存为模版"复用。

官方建议："好的需求往往同时点出**受众**和**想让对方记住什么**，而不仅仅是主题。"

## 写作工作台：长文的版本化管理

面向文章、报告、推文、技术指南、内部文档。Document 工作区 = Markdown 文件树 + 编辑器；产物落到本地 `outputs/` 目录；**每一轮迭代都保留为可回溯的版本**（编辑器右上角可切"最新版本/早期版本"，可导出 PDF）。

语气五选：不指定（AI 自行判断）/ 正式 / 轻松 / 技术 / 创意。

五个官方典型场景：

| 场景 | 输入 → 输出 |
| --- | --- |
| 零散笔记 → 技术指南 | 散记文件夹 → 结构化指南 |
| 无责内部故障复盘 | 对话/日志 → 复盘文档 |
| PR 列表 → 发布说明 | git 记录 → 按 Features/Improvements/Fixes 分组 |
| 技术博客 | 主题+字数结构 → 成稿 |
| API 规范 → 集成指南 | 接口文档 → 鉴权、cURL 示例、错误码表、FAQ |

注意：手动编辑后，AI 后续轮次会**基于你的修改**继续——人改稿不会被 AI 覆盖。

## 怎么选

| 需求 | 工作台 |
| --- | --- |
| 文件、数据、调研、自动化 | 通用 |
| 海报、落地页、UI 原型 | 设计 |
| 汇报、课件、路演 | 幻灯片 |
| 文章、报告、指南 | 写作 |

> 对比视角：TraeWork 的做法是用 Design 模式 + HTML 产物覆盖设计场景（见[做一套能上台的 PPT](/traework/case-ppt)），QoderWork 的垂类工作台更"开箱即用"——两种路线按手感选。

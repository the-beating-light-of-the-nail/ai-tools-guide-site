# QoderWork 怎么帮你整理文件？下载文件夹大扫除、照片归档、年度总结一次讲清

你打开 Downloads 文件夹，密密麻麻几千个文件，谁都懒得理。但真要找一份简历、一张照片、一份年终汇报时，又抓瞎。这一章把 QoderWork 在文件整理上的几类打法讲清：查重清理、分类归档、照片管理，还有一份行政总监的年度总结实战。

> 社区素材：沉默王二实测（[javabetter.cn](https://javabetter.cn/sidebar/itwanger/ai/qoderwork-review.html)）、官方用户案例库。提示词均经本站整理，你照着抄就能用。

## 场景一：Downloads 大扫除

你让它扫一遍 Downloads，找出重复文件并保留最新版：

```text
扫描我的 Downloads 文件夹，找出所有重复的文件，保留最新版本。
```

实测数据（沉默王二，内测期）：2444 份简历文件搬运耗时不到 6 秒；上万文件的超大 Downloads 清理约 300 秒，输出一份标明「重复 / 删除 / 保留」的清单报告。AI 用 MD5 值认重复、按时间分组，比手动整理快两个数量级。

你放心一点：它不擅自删除文件，列出方案等你授权确认后才执行；删除只进系统回收站（见[工作文件夹](/qoderwork/04-files)安全三条）。

分类归档你也一样派活：

```text
整理【目录】：图片移入 assets/images/、文档(.md/.txt/.pdf)移入 docs/、
配置文件(.json/.yaml/.toml)移入 config/、代码按语言归入 src/ 子目录。
执行前先给出方案，确认后再移动；最后生成整理报告（数量统计 + 目录树）。
```

进阶版带重命名规则，你也能照抄：

```text
整理下载文件夹，按文件类型（文档/图片/视频/压缩包）分类，
重命名为"类型_日期_原名称"格式，生成分类日志。
```

## 场景二：照片墙变成照片档案

你有一堆照片存在 ~/Pictures/2024，想按拍摄时间排好。官方典型场景是这么下的：

```text
整理 ~/Pictures/2024 目录：
1. 读取每张照片的 EXIF 拍摄时间
2. 按年月建立层级文件夹（2024-01/、2024-02/…）
3. 按拍摄时间移动并重命名为"日期_序号.jpg"
4. 你让它生成一份 CSV 清单（原文件名、新路径、拍摄时间）
先给方案，我确认后再动文件。
```

## 场景三：行政总监的年度总结

300 人科技公司的行政总监李姐，每年要整合 8 个部门的年终汇报——桌面 50+ 份 Word / PDF，「每年至少花两天」。你看看她的做法是：

1. 建文件夹「2024 年度总结资料」，12 份文件统一命名（部门名 - 年份 - 文件类型）；
2. 你选定为[工作目录](/qoderwork/04-files)；
3. 你下一次结构化指令：

```text
以 2023 年度总结.docx 为格式模板，整合各部门汇报材料：
提取各部门成果与业绩数据，结合财务与经营指标，
按"经营概况 / 业务板块 / 团队建设 / 规划展望"四大板块组织，
参考历年总结的行文风格，保持模板排版，输出 Word 到 output/ 目录。
```

你看到的结果：两天压缩到 6 分钟，关键业绩数据 100% 保留。后续新文件放进同一文件夹，一句「加入了新数据，请更新报告」就能增量更新。

## 通用打法小结

| 场景 | 核心提示词结构 | 关键约束 |
| --- | --- | --- |
| 查重清理 | 扫描 → 保留最新 → 生成清单 | 先方案后执行 |
| 分类归档 | 分类规则 + 命名规则 + 报告 | 先方案后移动 |
| 照片管理 | EXIF → 分层目录 → 重命名 → 清单 | 先方案后动文件 |
| 周期汇总 | 模板文件 + 板块结构 + 风格参照 | 数据必须溯源 |

四条安全底线你记牢：

1. 永远「先方案、后执行」——确认清单再放行；
2. 大批量操作前备份（或确认回收站机制可用）；
3. 授权范围最小化，只给需要的目录；
4. 执行完抽查：文件数量守恒（原数量 = 移动 + 保留 + 待确认）。

## 常见问题

**它清理重复文件会不会误删我的东西？**
不会擅自删。它先列方案等你确认，删除也只进系统回收站，你能找回。

**照片按时间归档前我能动文件吗？**
指令里加「先给方案，我确认后再动文件」，它就不会先动，等你点头。

**行政总结的业绩数据会漏吗？**
案例里 100% 保留，但你最好打开产物抽几条对一遍，尤其财务数字。

**整理完怎么防它下次重做？**
把规则固化成 Skill，下次一句话触发，不用每次重写长指令。
